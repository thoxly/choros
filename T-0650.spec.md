# T-0650 — Авто-слаги: серверный генератор + SlugField (слаг-ад)

**Столп:** 2 (интерфейс из блоков на данных) + 5 (настройка через ИИ) · **Волна:** W4-UX (stage4)
**Источник:** `docs/design/ux-study-2026-07-05.md` §7 (карта 11 мест, ~15-30 рукописных машинных имён на кейс)

## Диагноз

Сборка одного решения требует придумать латинский машинный слаг руками в ~11 местах
(приложение / набор полей / ключ каждого поля / подразделение / должность / сотрудник /
роль / найм агента / SoD-форма / модельер (3 подместа) / учётка-логин). Грамматика уже
едина (`SLUG_RE = /^[a-z0-9][a-z0-9-]{0,63}$/`, продублирована в 6+ файлах backend+frontend),
и генератор транслита УЖЕ существует дважды (`src/core/slugify-process-key.ts` для ключей
процессов, `src/core/register.ts::slugifyOrgName` для само-регистрации тенанта) плюс третий
раз на фронте (`web/src/forms/relation-cascade.js::slugFromName`) — просто не унифицирован и
не применён к остальным местам.

## Решение (по инструкции фаундера — ядро + главные места обязательно)

1. **Единый серверный генератор** `src/core/slug-generator.ts` — канонизирует транслит-карту
   и грамматику `SLUG_RE` (единственный источник для всех create-эндпоинтов и для
   `slugify-process-key.ts`, который теперь тонкая обёртка над этим модулем — без breaking
   change для существующих импортов).
2. **Слаг опционален на create-эндпоинтах ядра:**
   - `POST /api/applications` (приложение)
   - `POST /api/registry-defs` (набор полей)
   - `POST /api/departments` (подразделение)
   - `POST /api/positions` (должность)
   - `POST /api/employees` (сотрудник)
   - `POST /api/roles` (роль)

   Если `slug` отсутствует/пустой → сервер генерирует из `display_name`/`title`/`name`
   транслитом + при коллизии атомарный суффикс `-2/-3/…` (retry-on-insert-conflict —
   НЕ read-then-write race). Если `slug` прислан явно → валидируется как раньше (обратная
   совместимость со старыми вызовами и тестами).
3. **UI `SlugField`** (`web/src/components/slug-field.jsx`) — человек вводит только
   «Название»; под полем живая подпись «будет создан как `zakupki-2` · изменить»
   (debounce-превью транслита на клиенте — не round-trip; редактируемо ДО отправки формы,
   после создания слаг неизменяем как и раньше). Применяется в местах 1, 2, 4, 5, 6, 7
   (приложение / набор полей / подразделение / должность / сотрудник / роль).
4. **Ассистент (столп 5):** `create_application` tool-обработчик в
   `src/core/assistant-configurator.ts` — при отсутствующем/невалидном `appSlug` вызывает
   ТОТ ЖЕ `generateSlugFromName`, а не блокирует операцию требованием, чтобы LLM сам
   придумал слаг.

## Не в обязательном скоупе (FINDINGS/follow-up)

- Ключ каждого поля схемы (место #3) — плотная grid-строка `FieldRow`
  (`screen-app-schema.jsx`), требует отдельного визуального прохода (авто из «Название
  поля» + анти-коллизия внутри массива полей клиентской формы, без круговой зависимости
  от сервера на каждый ключевой удар). Заведено отдельным follow-up.
- «Набор полей» полностью спрятать (авто-`main` при первом «Настроить поля») — навигационное
  изменение экрана `AppSchemaScreen` (список наборов → сразу редактор), больше чем point-fix;
  SlugField снимает боль ручного слага, но сам registry_def-концепт остаётся видимым.
- Найм агента (#8) — `slug` даёт `deriveKcClientId` → Keycloak `clientId`; Keycloak-клиент
  создаётся ДО DB-транзакции (`src/http/agents.ts` Step 4), так что retry-on-conflict должен
  ретраить И создание KC-клиента, не только INSERT — отдельный аккуратный проход.
- SoD/intents-форма (#9, `ra-intents.jsx`) — внутренний debug-инструмент админ-тулинга
  (`/api/rights/intents/hire`), не основной путь сборки кейса.
- Модельер: 3 подместа (#10, `bpmn-properties-panel.jsx`) — требует доступ к схеме
  привязанного приложения для мультиселекта ключей полей; отдельная задача (упомянута в
  исследовании §7.4 как волна B).
- Пикеры «Название (slug)» вместо голого слага (org-crud.js:202-205) — если бюджет
  позволит, применяется после ядра (низкий риск, чистая косметика).

## Анти-кейс

Транслит-таблица генерик (кириллица→латиница по алфавиту, не кейс-словарь). Тесты
генератора используют синтетические имена ("Тестовое приложение", "Отдел продаж"), не
конкретный бизнес-кейс фаундера.

## Тесты (по срезам)

1. `slug-generator.test.ts`: транслит («Закупки оборудования» → `zakupki-oborudovaniya`),
   пустое/только-спецсимволы имя → фоллбэк, обрезка длины, коллизия → `-2`/`-3` через
   инъецированный `existsFn`, SLUG_RE-совместимость каждого сгенерированного слага.
2. Create-эндпоинты (applications/registry-defs/departments/positions/employees/roles):
   без `slug` в теле → 201 с авто-слагом, отражающим `display_name`; с `slug` → валидируется
   как раньше (в т.ч. невалидный → 400); коллизия (2 одинаковых названия подряд) → второй
   получает суффикс `-2`, не 409 (регресс на atomic retry).
3. `SlugField.test.jsx`: рендерит подпись-превью из "Название"; ручное редактирование
   слага отключает авто-синхронизацию (не перезаписывается при дальнейшем вводе названия).
4. Assistant `create_application`: без `appSlug` в args → генерируется, не блокируется.
