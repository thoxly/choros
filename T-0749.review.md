## 2. Гейт не ослаблен

`strip_deactivation_noise() { sed -E 's/deactivations?//gI; s/reactivations?//gI'; }`
— снимает только два буквальных compound-слова. Ни `entitlement`, ни
`verifyKey`, ни `isEntitled`, ни `not_after` не являются подстроками
`deactivation`/`reactivation`, и наоборот — значит strip не может «съесть»
кусок соседнего реального токена.

Прогнал `--self-test` живьём:

```
[T-0749] deactivation/reactivation false-positive self-test PASS (negative+positive+mixed)
[T-0198] entitlement-gates-vendor-only self-test PASS (exit 0)
```

Дополнительно проверил вручную (не только пробами скрипта):
- `checkVendorEntitlementActivation(key)` — после strip **всё ещё матчится**
  (позитив, гейт ловит).
- `"deactivation triggers isEntitled recheck"` — после strip **всё ещё
  матчится** (isEntitled уцелел, строка не «съедена» целиком).
- Прогнал grep по всему `src/http/*.ts` на предмет compound-слов вида
  `deactivationActivation`/`reactivationEntitlement` (риск «откусить» кусок
  соседнего реального токена) — **0 совпадений**, риск не материализован.

Единственный оставшийся (некритичный) риск: гипотетическая будущая строка,
где ЕДИНСТВЕННЫЙ VOCAB_RE-хит — это «activation» внутри слова «reactivation»
(например: настоящее «reactivation» вендорской лицензии вне vendor-edge, без
других токенов на той же строке) — была бы теперь замаскирована. Отмечено
как non-blocking nit (R-1 в review.json): это унаследованный класс риска
любой substring-эвристики (был и до T-0749 у самого `VOCAB_RE`), сейчас
ничего не маскирует (см. §3), и не заслуживает founder-эскалации сам по себе.

## 4. Полный fitness

Прогнал `npm run fitness` живьём (345-шаговая цепочка, `&&`-связка — любой
реальный неноль немедленно оборвал бы цепочку):

```

```

Entitlement-чек и его `--self-test` внутри цепочки — оба PASS. В логе
встречается ~21 строка `FAIL [...]` — все они проверены построчно: это
hostile-probe демонстрации ВНУТРИ чужих `--self-test`-блоков (substitution-
coverage-invariant, read-pdp-anti-case, read-pdp-frozen-core, rights-*
и др.), каждая немедленно сопровождается `PASS self-test: ... detects ...`
/ `SELF-TEST PASS`. Реальных незапланированных красных нет — что и
подтверждает итоговый `exit 0` всей `&&`-цепочки.

`npm ci` на свежем worktree — подтверждено, не связано с T-0749: диф не
трогает `package.json`/lockfile/исходники, требующие новых зависимостей;
это provisioning-артефакт свежего worktree (тот же класс, что упомянут в
памяти ранее: «npm install после merge»).
