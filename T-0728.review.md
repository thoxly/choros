## 2. Канбан рендерит person-поле чипом, не «—»

`resolveCardFieldCell` (kanban-board.js) — чистая функция, дословно повторяет старую логику `rawVal`/`rendered` (относительно `formatCellValue`/`computeComputedFieldValue`), добавляя ветку: `rendered === personSentinel` → `{isPerson:true, personId: String(rawVal)}`. Для НЕ-person путей (string/computed/missing-meta/relation/file) поведение идентично старому (`typeof rendered === 'string' ? rendered : '—'`) — подтверждено юнит-тестом «relation/file sentinels still degrade to "—", not a crash».

`KanbanCard` (kanban-board.jsx) диспатчит: `cell.isPerson ? <PersonCell personId={cell.personId} employees={employeesById} /> : <span>{cell.displayVal}</span>` — единственная точка рендера ячейки, нет параллельного пути.

Деактивация: `PersonCell` (теперь общий для таблицы и канбана) передаёт `deactivated={Boolean(hit && hit.deactivated)}` в `ActorChip` → тот же `chs-exec--deactivated`-визуал и тот же tooltip-суффикс, что таблица уже показывает. Поскольку это буквально тот же компонент (не второй hand-rolled wrapper), деактивация не может рассинхрониться между display-mode — она одна на оба.

Честная деградация:
- Пустое/отсутствующее person-значение → `formatCellValue` возвращает `'—'` (строка) → `resolveCardFieldCell` даёт `{isPerson:false, displayVal:'—'}` — юнит-тест это доказывает и для `{}` (отсутствует), и для `{executor:''}` (пусто).
- Непустое значение, отсутствующее в `employeesById` (не загружено/удалённый сотрудник) → `PersonCell` не паникует: `hit` = `undefined` → `name={personId}` в `ActorChip`. `personId` гарантированно непустая строка (иначе `formatCellValue` вернула бы `'—'`, не сентинел) — не может дать `"undefined"` как текст.

## 4. employeesById проп

`const EMPTY_EMPLOYEES_MAP = new Map();` — объявлен на уровне модуля (не внутри компонента), используется как дефолт `employeesById = EMPTY_EMPLOYEES_MAP` в сигнатуре `KanbanBoard`. Стабильная ссылка между рендерами — не создаёт новый объект каждый вызов, не ломает мемоизацию нижестоящих `useCallback`/`useMemo`. `screen-app-records.jsx` теперь ВСЕГДА передаёт свой уже существующий `employeesById`-стейт (`employeesById={employeesById}` внутри `isKanban`-ветки, screen-app-records.jsx:1459) — тот же стейт, что таблица батч-грузит через `fetchEmployees()`→`buildEmployeesById()`, гейтованный на `hasPersonColumn` (эта логика НЕ тронута диффом — уже была верна для обоих display-mode, spec §2 честно это документирует, не переизобретает). Нет второго fetch/эндпоинта — подтверждено grep'ом диффа: ни одного нового вызова `fetch`/API в этом коммите.

Проброс: `KanbanBoard → KanbanColumnView → KanbanCard`, единственная точка использования `<KanbanCard>` (внутри `KanbanColumnView`) и единственная точка `<KanbanColumnView>` (внутри `KanbanBoard`'s column map) — проп доходит до каждой карточки каждой колонки, нет отдельного «unassigned»-бакета с собственным путём рендера, который бы проп пропустил.
