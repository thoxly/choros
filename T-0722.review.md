# T-0722 — судейский вердикт (адверс-судья, P2 security/PDP)

**Вердикт: approved.** Блокеров нет. Две non-blocking заметки (обе — задокументированные
deferrals/pre-existing, НЕ дефекты этой задачи).

Задача: `GET /api/processes` (LIST) раскрывал имя/шаг/recordId ВСЕХ инстансов тенанта любому
члену тенанта (enumeration-сайдченнел вокруг READ-PDP T-0570). Фикс — батчевый
`filterProjectionsByReadVisibility` (process-projection.ts), сужающий уже tenant-scoped
`InstanceProjection[]` по той же `isRecordReadable`, что DETAIL-гейт T-0721. Диф:
**104 добавления, 0 удалений** в process-projection.ts (readEvents/listInstanceProjections
НЕ тронуты) + 34 строки врезки в processes.ts + тесты/FF/ADR.

## Адверсариальная проверка (6 векторов)

### 1. IN-MEMORY фильтр vs ПАГИНАЦИЯ / cap — ГЛАВНЫЙ риск → НЕ блокер
`listInstanceProjections` фетчит `ORDER BY occurred_at ASC LIMIT 200` (cap 200, oldest-first),
ЗАТЕМ фильтр. Проверено `git diff --numstat` = 104/0: cap и readEvents **не изменены этой
задачей** — pre-existing.

Ключевой вывод: **фильтр НЕ удаляет ни одного инстанса, который актор ВПРАВЕ видеть и который
попал в окно** — он вычитает только НЕ-видимые строки. Инстансы актора за пределами oldest-200
окна были невидимы и ДО T-0722 (окно = oldest-200 ВСЕХ инстансов тенанта, не зависит от
владения). Сценарий "актор видит ПУСТО, хотя его инстансы существуют за cap" реален, НО:
(а) те инстансы были невидимы и до фикса (pre-existing ASC-200 cap), фильтр их видимость не
ухудшил; (б) до фикса на их месте показывались 200 ЧУЖИХ строк (сама утечка) — теперь честно
пусто; (в) второго числа для десинка нет — эндпойнт несёт ТОЛЬКО `instances[]`, ни total, ни
cursor, ни count (проверено grep'ом ответа); `instances.length` считается ПОСЛЕ фильтра.
Осознанное отклонение от буквы «SQL WHERE» задокументировано ADR §2.3 (containment-математика
`isNarrowerOrEqual`/`isEffective` не SQL-выразима без дублирования authority-математики → NF-5);
records.ts LIST T-0570 — единственный прецедент в кодовой базе — делает РОВНО пост-фильтр.
→ **Non-blocking**, честно задокументировано (критерий задачи выполнен). См. N1.

### 2. Обход через overlay — ЗАКРЫТО
Порядок в processes.ts: `filterProjectionsByReadVisibility(...)` → `overlayDetailLiveSteps(
startDeps.flowable, visibleProjections)`. Фильтр СТРОГО ДО overlay. `instances` строится ТОЛЬКО
из отфильтрованного+overlaid набора — метаданные скрытого инстанса не текут ни через overlay
(он получает только visibleProjections), ни через live-engine (round-trip не тратится на
отброшенный инстанс). FF-INST-VIS-3c механически стережёт source-order gate-before-overlay
(self-test PASS). → чисто.

### 3. Батч-резолв кросс-тенант — ЗАКРЫТО (двойной замок)
`loadRecordRowAncestryBatch`: `WHERE r.tenant_id = $1 AND r.id = ANY($2::uuid[])` внутри
`withTenant` (SET LOCAL choros.tenant_id). Плюс `listInstanceProjections` — ПЕРВЫЙ tenant-барьер:
инстансы тенанта B физически не входят в список тенанта A, фильтр их не видит. Live-PG:
кросс-тенант тест (широкий reader A не видит инстанс B в LIST) + mixed-visibility
(record-scoped грант видит ТОЛЬКО свою запись, count честен) — оба PASS против реального RLS
(choros_app NOBYPASSRLS, cloned test DB).

### 4. recordId null → остаётся видим — ЛЕГИТИМНО
`record_id` пишется на старте в tenant-tx стартующего (on_create-триггер). null = процесс
НЕ был порождён записью (explicit-launch `/api/processes/start`) — привязки-источника нет, гейтить
не по чему. Не «чужая запись с потерянным линком»: инстанс уже tenant-scoped фолдом, а
отсутствие record_id означает, что связи никогда не было. Симметрично DETAIL (T-0721),
задокументировано как phase-1/2 scope. → Non-blocking, deferred (phase-3, см. N2).

## Non-blocking findings

- **N1 (pre-existing, не введено задачей):** `readEvents` фетчит `ORDER BY occurred_at ASC
  LIMIT 200` — oldest-first cap. Тенант с >200 инстансов теряет видимость БОЛЕЕ НОВЫХ процессов
  в LIST для ВСЕХ (не только эффект фильтра). T-0722 это не ухудшает (диф 104/0), но фикс делает
  cap заметнее (пустой список вместо 200 чужих строк). Стоит завести follow-up: newest-first +
  явная пагинация/«показать все». Задокументировано ADR §2.3(b).
- **N2 (задокументированный deferral):** record-less инстансы (explicit-launch) не сужаются —
  phase-1/2 scope, симметрично DETAIL. Phase-3 (process-definition-scoped read-грант) закроет;
  вне объёма T-0714 опции (c) фаз 1-2.
