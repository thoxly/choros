## 1. Переинтерпретация скоупа — ЧЕСТНАЯ (оба обоснования отказа проверены ЖИВЬЁМ = TRUE)

Исходная формулировка просила «человеко-имя из BPMN name». Строитель признал это недостижимым безопасно и отдал `keyDemoted`-чип. Проверил ОБА пункта отказа в коде, не по ADR:

**(а) Локальный BPMN-файл мёртв в проде — ПОДТВЕРЖДЕНО.**
`Dockerfile`, стадия `runtime` (`FROM node:22-slim AS runtime`, строки 48-64) копирует РОВНО:
`dist/`, `package*.json`, `web/dist/`, `migrations/`, `ops/docker-entrypoint.sh`.
`config/` НЕ копируется ни в одну стадию (web-builder/app-builder тоже нет). → чтение `config/flowable/processes/*.bpmn20.xml` на живом контейнере вернуло бы `null` всегда; работает только в dev-чекауте. Аргумент «нечестный сигнал» — верен.

**(б) Flowable process_key не tenant-partitioned — ПОДТВЕРЖДЕНО.**
`src/core/flowable-client.ts`:
- `deployBpmn` (739): POST `/repository/deployments`, тело = multipart-форма с XML-блобом. Нативного Flowable `tenantId` НЕТ.
- `startInstance` (785): POST `/runtime/process-instances`, тело = `{ processDefinitionKey, variables? }`. Нативного `tenantId` НЕТ.
→ `process_key` глобален в Flowable; резолв человеко-имени по голому ключу рискует показать тенанту A имя одноимённого процесса тенанта B. Это РОВНО класс утечки T-0616 §F-1. Аргумент SECURITY — верен.

**Итог:** оба обоснования истинны. Человеко-имя НЕ достижимо безопасно в размере P3. `keyDemoted`-чип = лучшее доступное. Строитель НЕ срезал угол — он честно сузил задачу до реального дефекта (один из двух потребителей `deriveInstanceTitle` отбрасывал половину контракта) и задокументировал отклонённые альтернативы + follow-up O-1, а не подменил тихо.

## 2. keyDemoted решает исходную жалобу; человеческий-слой-или-жаргон

- **Различимость:** для РАЗНЫХ движковых процессов на записи (разные ключи, напр. `telLinear` vs другой engine-only) — да, чипы различны → строки различимы. Это и есть буквальная жалоба «несколько таких процессов … выглядели одинаково».
- **Два запуска ОДНОГО ключа** остаются с идентичным чипом — но это честно: инстансы одного определения различаются через StepRef/StatusChip/ссылку на `/processes/:id` (работает). См. nit R-1.
- **Жаргон vs человек:** `keyDemoted` = сырой ключ `telLinear` — это camelCase-жаргон/слаг, но НЕ opaque actor-UUID (несёт частичный смысл). Рендерится ДЕМОТИРОВАННО (muted, `--chs-text-xs`), НИКОГДА не primary — primary остаётся честный generic «Процесс». Строго говоря — machine-leak, но МЕНЬШЕЕ зло против двух неразличимых «Процесс», и это уже благословлённая конвенция: `screen-process-instance.jsx` рендерит его так же, и гейт `anti-uuid-actor-render.sh` его НЕ флагует (0 bare renders — он ловит bare actor/UUID-primary, а не demoted-secondary Mono). Настоящий человек-слой («Канонический линейный ТЭЛ») остаётся follow-up O-1 — nit R-2.
