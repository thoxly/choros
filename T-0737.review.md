# T-0737 — судейский вердикт (адверс-судья, security P1)

**Вердикт: `approved`.** Три находки — все `nit` (non-blocking).

Задача: закрыть READ-PDP на аудит-поверхности — `GET /api/audit`,
`/api/audit/export`, `/api/audit/:instanceId` — единым гейтом `requireAuditRead()`
(genesis-owner ONLY, политика T-0500). Строитель: коммит `ed78708f`, PR #62.

---

## 1. Все три роута загейчены ПЕРЕД отдачей данных — да

Прочитан каждый роут (`src/http/audit.ts:671-778`), ровно 3 `router.register`:

- **GET /api/audit** (`:680`) → `handleGetAuditLog` → `requireAuditRead(pool, req)`
  на `:615` **до** `readAuditLog`/`withTenantTx`. Данные не текут до гейта.
- **GET /api/audit/export** (`:708`) → `pool===undefined`→503 (`:709`), затем
  `await requireAuditRead` (`:716`) **до** любого `getTelDemoInstance`/`findAuditData`/
  `getDefaultAuditInstance`/стрима. Тело формируется только после гейта (`:725+`).
- **GET /api/audit/:instanceId** (`:755`) → `pool===undefined`→503 (`:756`), затем
  `await requireAuditRead` (`:763`) **до** `getTelDemoInstance`/`findAuditData`.

**/:instanceId demo-trace закрыт полностью.** Раньше — `withAuth(async (_req...` с
неиспользуемым `_req` и НУЛЁМ per-route гейта: любой запрос (в dev-режиме — вообще
без аутентификации) получал demo-трейс. Теперь `req` используется, `requireAuditRead`
вызывается первым. Грепом подтверждено: функции demo-трейса
(`getTelDemoInstance`/`findAuditData`/`getDefaultAuditInstance`) **не имеют** других
потребителей вне `audit.ts` — альтернативной незагейченной точки входа нет. Ни один
handler не глотает исключение гейта в try/catch — throw уходит в error-envelope роутера.

## 2. Политика genesis-owner-only — верна

`holdsAuditRead(admin) = admin.isGenesisOwner` (`:521-523`) — и только. `loadAdminContext`
грузит `mgmt_object:*`-гранты в `adminGrantsList` (`org.ts:847-894`), но `holdsAuditRead`
их **не** консультирует. Stub-тест кейс 4c (`:305`) доказывает: non-owner с делегируемым
`mgmt_object:*` грантом → 403. Совпадает с требованием ревью T-0500 (скоуп-грант на один
объект не должен открывать весь журнал). Одна политика на три роута — согласен: export/
:instanceId отдают demo/fixture-данные, но forward-obligation файла явно требовал закрыть
все три вместе, а консервативный owner-only безопаснее развилки авторитетов. См. R-1
(nit): auditor-персона заблокирована до отдельного founder-решения — задокументировано.

## 3. Деактивированный genesis-owner отсекается — да, доказано живьём

`loadAdminContext` в подзапросе резолва сотрудника несёт `${ACTOR_ACTIVE_SQL}` =
`"deactivated_at IS NULL"` (`actor-authority-gate.ts:73`, `org.ts:816`). Деактивированный
owner → подзапрос employee пуст → `employee_id = (NULL)` → owner-role не матчится →
`isGenesisOwner=false` → 403.

**Прогнал live-PG сам** (PG :55432, реальный Pool + реальный `http.Server`, `http.request`,
не мок): `audit-route-deactivation-gate.db.test.ts` — **9/9 PASS**.
- AC-1..3: деактивированный owner → **403** на всех трёх роутах.
- AC-4..6: активный non-owner → **403** на всех трёх.
- AC-7 (позитивный контроль): активный owner → **200** на всех трёх.

Тест реально бьёт HTTP (сидит tenant/owner/deact-owner/member в живой PG, дёргает
маршруты через сеть). R-2 (nit): вектор прогнан в dev-режиме (x-dev-user), не через
keycloak-JWT residual window — но предикат в mode-agnostic `loadAdminContext`, а сам он
отдельно доказан на resolver-уровне (T-0658).

## 4. 503 fail-closed при no-pool — правильно

`pool===undefined` → 503 `AUDIT_UNAVAILABLE` **до** `requireAuditRead` (которому нужен
DB-read). Fail-closed, не fail-open. Плюс `resolveActorTenant` при DB-ошибке →
403 `ACTOR_TENANT_UNRESOLVED` (не тихий роут в Dev Silo). Лучше 503/403, чем открыть аудит.

## 5. findings 12→9 через WHITELIST §D — честно, не маскировка

Прогнал скан сам: `77 GET routes audited — 13 marker-covered, 55 whitelisted, 9 findings`.
Грепом подтвердил: **ни один audit-роут не в списке findings** (остались grant-trail,
inbox, operational-analytics, record-links, process-analytics, rights-change-requests,
rights-sod — не эта задача). Whitelist §D цитирует `requireAuditRead (audit.ts:554-569)`;
функция **реально** гейтит (спот-чек кодом + stub 13/13 + live 9/9). Скан не видит гейт
только потому, что он вынесен в module-scope helper (block-scope text-scan, §2.4
limitation #1 — тот же класс, что `notification-prefs.ts`). Self-test скана — **PASS**.
R-3 (nit): `/api/audit` попал в whitelist хотя гейт был с T-0500 — false-negative скана,
не дыра.
