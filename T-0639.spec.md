# Spec · T-0639 — «Подмена»: честная обязательность и честный фидбек (Tier-1 vs Tier-2)

**Phase:** SPEC+DESIGN+BUILD (совмещённая, coder-агент)
**Status:** ready
**Base spec:** `docs/specs/T-0588-substitution-escalation.spec.md` (FR-6, §5 AC-8/AC-9) —
эта задача не пересматривает модель Tier-1/Tier-2, только честность UI.

## 1. Разведка (сделана)

- Компонент: `SubstituteForm` в `web/src/screens/rights/ra-intents.jsx:233-283`.
- Кнопка «Объявить подмену» — `disabled={result === 'loading' || !absentId || !substituteId || !roleId || !until || !orgNodeId}`.
  Поле «Орг-узел (отдел)» (`orgNodeId`) — один из пяти required-полей, но
  ЕДИНСТВЕННОЕ без визуальной пометки обязательности (label = "Орг-узел (отдел)",
  без "*"/"обязательно"), и нет текста, объясняющего, чего не хватает, когда
  кнопка неактивна.
- Сервер: `registerSubstitute` в `src/http/rights-intents.ts:710-929`. Определяет
  tier внутри транзакции (`tier2 = forceTier2 || poolRows.length === 0`, строка ~781)
  и **уже возвращает различимый признак** в JSON-ответе (строка 923):
  `{ rule_id, tier: result.tier, ttl_grant_id, valid_until }` — `tier` это `1 | 2`
  (см. `return { ruleId, tier: tier2 ? 2 : 1, ttlGrantId }`, строка 917).
  **Контракт уже несёт нужный признак — бек трогать не нужно** (FR-6 T-0588
  предполагала такую возможность: "используя уже существующее поле… аналогичный
  маркер"; здесь это `tier` в ответе `/api/rights/intents/substitute`).
- Текущий фронт при успехе показывает ОДНО сообщение независимо от tier:
  `Подмена объявлена${r.data.ttl_grant_id ? ' (с временным грантом)' : ''}` —
  формально различает по `ttl_grant_id`, но текст «Подмена объявлена» звучит
  одинаково безусловно-активно в обоих случаях, тогда как при Tier-1 (пул уже
  покрыт другим держателем) заместителю ПРЯМО СЕЙЧАС ничего не меняется —
  правило вступит в силу только если единственный держатель уйдёт (Tier-1
  правило создано, но задачи прямо сейчас не маршрутизируются на substitute,
  т.к. `resolveExecutorFallbackBatch` в первую очередь берёт живых pool-holders;
  substitution suppress-absent срабатывает только когда исходный держатель
  отсутствует/деактивирован). Пользователь читает "Подмена объявлена" как
  «заместитель теперь получает задачи» — вводит в заблуждение.
- Жаргон "Tier-1"/"Tier-2" — внутренний термин спеки/кода, не должен идти в
  видимый текст UI (условие задачи + G5 денилист-дух). Используем русские
  формулировки; `tier` как число остаётся в `data-tier` атрибуте карточки
  результата и в теле JSON (уже так).

## 2. Изменения (аддитивные, только web/src)

### 2.1 Явная обязательность полей SubstituteForm

- Добавить единый суффикс `" *"` к label каждого из 5 required-полей
  (Отсутствует / Замещает / Роль / Орг-узел (отдел) / До) — визуальный маркер,
  консистентный с существующей конвенцией формы `form-defs.js` (`fjs-asterix`).
- Добавить строку-легенду под заголовком секции: «* — обязательно для заполнения».
- Когда кнопка disabled из-за незаполненных полей (не из-за `loading`), показать
  видимое пояснение под кнопкой: список конкретно недостающих полей
  ("Заполните: Орг-узел (отдел)" и т.п.), а не молчаливый disabled.
  Реализация — маленький helper `missingSubstituteFields(...)`, чистая функция
  (тестируема без DOM), плюс `<span>`-пояснение в чере, `aria-live="polite"`
  чтобы SR-пользователь тоже слышал причину.

### 2.2 Честный фидбек после объявления (различимый Tier-1 / Tier-2)

- После успешного `POST /api/rights/intents/substitute`, ответ уже содержит
  `tier` (1|2, см. §1). Ветвим сообщение:
  - `tier === 1` (роль покрыта другим держателем; грант НЕ выпущен):
    «Правило подмены создано. Роль сейчас покрыта другим держателем — подмена
    вступит в силу автоматически, если этот держатель станет недоступен
    (уйдёт/будет деактивирован). Прямо сейчас у заместителя ничего не меняется.»
  - `tier === 2` (единственный держатель; грант выпущен):
    «Подмена объявлена и активна: заместитель получил временный грант и
    увидит задачи этой роли в своём инбоксе.»
  - Fallback (если `tier` вдруг не пришёл со старого/иного бекенда — оборонительно,
    не ломаем контракт): текущее поведение по `ttl_grant_id` как раньше.
- `data-tier={result.data.tier}` на баннере результата — для тестов/дебага,
  жаргон "Tier-N" в САМ текст не идёт (человеческие формулировки выше).

## 3. Не делаем (out of scope)

- Не меняем `registerSubstitute` контракт — `tier` уже есть, поле аддитивно
  используется, не переименовывается.
- Не строим новый экран/CRUD над `substitution_rule` (ND-4 T-0588, future).
- Не трогаем `SelfAbsenceForm` текстологически сверх того, что уже описывает
  Tier-1/Tier-2 своими словами в статичной подсказке (эта форма уже честная —
  см. `ra-intents.jsx:347-350` — но она не возвращает `tier` из ответа и не
  показывает пост-сабмит ветку; вне охвата этой задачи, т.к. явно указана
  только `SubstituteForm`).

## 5. Acceptance

- AC-1: кнопка «Объявить подмену» disabled + explicit объяснение недостающих
  полей, включая «Орг-узел (отдел)», помеченный как обязательный (`*`) в label.
- AC-2: после Tier-1 объявления баннер честно говорит "ничего не меняется
  прямо сейчас"; после Tier-2 — говорит "заместитель получил доступ".
- AC-3: слово "Tier" отсутствует в видимом тексте (JSX text nodes), допустимо
  только в `data-tier`/коде/тестах.
- AC-4: `tsc --noEmit`, `npm run build`, `vitest run` (web, полный), G5,
  anti-case-lock, substitution-isolation — зелёные.
