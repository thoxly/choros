## 2. Deep-link C→B (AC-C3) — РАБОТАЕТ

- Карточка: `count>0` → `<Button>` → `navigate(processGridDeepLink(procKey))` = `/processes?definition=<encoded procKey>`.
- Грид: `useSearchParams()` → `useState(() => searchParams.get('definition') || '')` → первичный
  `useEffect([definition,…])` → `fetchPage(0)` → `buildProcessesQuery({definition})` эмитит `?definition=`.
- Совпадение ключа: и deep-link, и опции грид-фильтра (`definitionFilterOptions`) читают `process_key` из
  ОДНОГО контракта `GET /api/process-catalog` → seeded `definition` матчит опцию `<select>`. Переход из
  каталога = свежий mount грида, поэтому инициализатор реально отрабатывает.
- Счётчик — кнопка ТОЛЬКО при >0; при 0 честный статик-текст «0 инстансов» (не мёртвая кнопка, G7).

## 3. Анти-UUID — ЧИСТО (gate 0)

## Non-blocking (LIVE_PROOF-риски для стенда)

- **R-1 (ось 3):** seed `definition` только в инициализаторе useState (на mount). Для указанного анти-кейса
  (переход из /process-catalog = свежий mount) работает; in-grid `?definition=` или back/forward внутри
  грида рассинхронят фильтр с URL. Follow-up: `useEffect([searchParams])`.
- **R-2 (ось 3, косметика):** при приходе по deep-link `<select value={definition}>` до загрузки async-опций
  кратко пуст (фильтр УЖЕ применён — состояние засижено, fetch отфильтрован); самолечится по приходу имён.
- **R-3 (ось 1):** LIVE_PROOF отложен — стенд offline. Живьём НЕ доказано, что грид-фильтр `?definition=`
  считает те же инстансы, что рекламирует `instance_count` карточки. Прогнать D-064-проход перед промоутом
  dev→main (план в pr-handoff).
