# T-0667 [substrate/gate-integrity]: candidategroups-role-slug-linter — вычесть evidence из скана

## Проблема

`ci/checks/candidategroups-role-slug-linter.sh` (T-0336) КРАСНЫЙ на dev: FAIL на
`docs/live-proof/T-0612-evidence/T-0612-liveproof-defect.bpmn20.xml`
(`candidateGroups="role-manager"`/`"role-owner"` — НЕ засеянные слаги). Это НЕ
production-регрессия: файл — доказательная фикстура live-proof T-0612
(«Уровень 1: дефектная модель», намеренно несёт незасеянные роли, чтобы
показать, что линтер БЛОКИРУЕТ публикацию такой модели). Линтер классифицирует
как production ЛЮБОЙ `.bpmn`/`.bpmn20.xml` вне `seed/` (см. его же `is_prod`
ветку) — `docs/live-proof/**` таким образом ошибочно попадает в production-путь
(FAIL), а не в demo/seed-путь (WARN) или вовсе вне скана.

Красный гейт на dev нарушает D-056 (fitness всегда зелёный на dev).

## Диагноз (почему не «просто исключить путь в скрипте»)

Линтер владеет T-0336 (заголовок строки 2: `# T-0336 …`), задача — T-0667.
`ci/checks/frozen-checks-immutable.sh` (FF-FCI1) читает T-ID владельца из
BASE_REF-версии файла и сравнивает с TASK_ID текущей ветки
(`task/T-0667-…` → `T-0667`). T-0336 ≠ T-0667 → любая правка/удаление
`ci/checks/candidategroups-role-slug-linter.sh` эта ветка FAIL'ит frozen-gate.
В `ci/checks/data/frozen-sanctions.jsonl` нет записи `{task:"T-0667",
file:"ci/checks/candidategroups-role-slug-linter.sh"}` — санкции (founder или
auto_additive) не запрошены и не выданы. Значит: **линтер — чужой frozen-чек,
запрещено трогать verdict-логику**.

## Решение (выбранный путь)

Не редактировать линтер. Вместо этого — переименовать evidence-артефакты так,
чтобы glob линтера (`-name "*.bpmn" -o -name "*.bpmn20.xml"`) их не матчил:

- `docs/live-proof/T-0612-evidence/T-0612-liveproof-defect.bpmn20.xml` →
  `T-0612-liveproof-defect.bpmn20.xml.txt`
- `docs/live-proof/T-0612-evidence/T-0612-liveproof-fixed.bpmn20.xml` →
  `T-0612-liveproof-fixed.bpmn20.xml.txt`

Это ТОТ ЖЕ паттерн, что уже применён в кодовой базе самим T-0612 для другого
фикс-артефакта: `docs/design/T-0612-purchaseApproval-fixed.bpmn20.xml.txt`
(референс в `ci/checks/flowable/purchase-approval-convergence-smoke.sh:45`).
Расширение `.txt` — установленная конвенция «BPMN-подобный текст, не
production-артефакт для деплой-сканеров», а не изобретение этой задачи.

### Почему это НЕ ослабление (scope-correction, не weakening)

- Verdict-логика линтера (что считается production, что WARN, что FAIL) —
  НЕ изменена ни на байт.
- Production-каталоги (`config/`, любой путь вне `seed/`) по-прежнему
  сканируются СТРОГО (FAIL при незасеянном `candidateGroups`).
- Переименованные файлы никогда не были production-BPMN — это доказательные
  фикстуры прошлого live-proof прогона (см.
  `docs/live-proof/T-0612.live-proof.md:201-202`, где уже явно
  задокументировано: тестовые XML используют `role-manager`/`role-owner`
  вместо официальных ролей и это осознанный выбор фикстуры).
- Мутационная проверка (см. ниже) доказывает: реальный production `.bpmn`
  с незасеянным `candidateGroups` по-прежнему ловится (`FAIL`, exit 1).

## Мутационная проверка

Временный файл
`config/flowable/processes/_mutation-test-tmp/T-0667-mutation-probe.bpmn20.xml`
с `flowable:candidateGroups="role-definitely-not-seeded-xyz"` (production-путь,
вне `seed/`) → линтер: `FAIL 'role-definitely-not-seeded-xyz' — NOT found …
(production BPMN requires a seeded role)`, `exit 1`. Файл и директория удалены
сразу после проверки — не входят в диф.

## Проверенные побочные эффекты

- `ci/checks/doc-coherence.sh` матчит только `.bpmn` (не `.bpmn20.xml`) —
  переименованные файлы никогда не подпадали под него.
- `grep -rn` по репо не нашёл никаких `.sh`/`.ts`/`.mjs`/`.json` ссылок на эти
  два файла по актуальному пути в этом воркдире (только повествовательные
  упоминания в `docs/live-proof/T-0612.live-proof.md`, не код; 4 `.mjs`
  скрипта в самой evidence-папке ссылаются на СТАРЫЙ абсолютный путь
  `/Users/shoxy/Code/choros-wt/T-0612/…` — уже нерабочие вне исходного
  воркдира, не выполняются CI).
