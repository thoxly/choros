# T-0652 — «Администрирование честное» (W4-UX §6)

Родитель: T-0647 (E-UX-HUMAN). Спека: `docs/design/ux-study-2026-07-05.md` §6.
Волна: 4. Совмещённые SPEC+DESIGN+BUILD.

## Проблема (из §6, перепроверено по коду)

1. **Фейковые кнопки.** «Экспорт прав» (`shell.jsx` ~650) и «+ Исполнитель» (`shell.jsx` ~628) в
   топбаре — `aria-disabled` + `preventDefault` с пояснением ТОЛЬКО в `chs-sr-only` (для скринридера).
   Зрячий видит обычную рабочую кнопку, которая молча ничего не делает. Правила против этого нет.
2. **Мёртвая «Экспорт» в журнале прав.** `ra-grant-trail.jsx:327` — `<Button>Экспорт</Button>` без
   `onClick`, не помечена disabled, просто мертва. (Краш /rights/trail React #31 уже закрыт T-0648.)
3. **Формы управления правами похоронены под фолдом.** «Назначить роль сотруднику» / «Дать роли право»
   работают (`screen-rights.jsx:519-548`), но живут в самом низу карточки роли — discoverability ноль.
   Для читателей (`canManage=false`) нет явного бейджа «только просмотр» в шапке.
4. **KC-UUID вместо логина в /users.** Учётки до миграции 126 имеют `login=NULL`; для KC-backed
   `slug`=KC-UUID → `login ?? slug` (`user-mgmt.ts:502-509`) светит сырой UUID
   (`2e082a32-25ff-…`) как «логин».

## Решение (acceptance-критерии, машинно-проверяемые)

### Часть 1 — правило «нет фейковых кнопок»
- AC1.1 «Экспорт прав» (topbar, screen∈{rights,reference}) и «+ Исполнитель» (topbar, screen=org)
  рендерятся с **видимым** disabled-стилем И **видимой** причиной (не только `chs-sr-only`).
  Признак в коде: у обеих заглушек рядом есть видимый (не `chs-sr-only`) элемент-подсказка.
- AC1.2 Новый UX-гейт `ci/checks/ux/ux-g7-no-fake-buttons.sh`:
  - диффом против `dev` флагует НОВЫЕ добавленные строки в `web/src/screens/**` и
    `web/src/app-shell/**`, где на кнопке стоит `aria-disabled` (или `onClick={(e)=>e.preventDefault()}`
    как единственный обработчик) БЕЗ видимой причины поблизости.
  - имеет `--self-test`, exit 0/1/2 как у `ux-g6`.
  - режим INFORMATIONAL по умолчанию, `--required` для fail.
- AC1.3 `ux-g7 --self-test` PASS.

### Часть 2 — CSV-экспорт журнала прав
- AC2.1 Кнопка «Экспорт» в журнале имеет `onClick`, генерирует CSV из уже загруженных строк
  журнала (клиентская генерация — данные уже пришли из `GET /api/grant-trail` через
  `fetchGrantTrail`, который несёт `authHeaders()`; **голого fetch нет**).
- AC2.2 CSV корректно экранирует кавычки/запятые/переводы строк (RFC4180: `"` → `""`, поле в кавычках).
- AC2.3 Кнопка disabled, когда строк нет (нечего экспортировать), с видимой причиной (не фейк).
- AC2.4 Юнит-тест (web, node-tier): `rowsToCsv(displayRows)` даёт заголовок + строки, экранирование
  проверено на поле с запятой и кавычкой.

### Часть 3 — формы управления в шапку карточки роли
- AC3.1 В шапке карточки роли (`chs-roledetail__head` actions) при `canManage` есть кнопки-действия
  «Назначить роль» и «Дать право», открывающие формы в дровере/модалке (используется kit `Modal`,
  роль=drawer — нет отдельного Drawer-компонента в kit).
- AC3.2 Для читателя (`canManage=false`) в шапке виден бейдж «только просмотр» (видимый текст).
- AC3.3 Формы `AssignRoleForm`/`GrantRightForm` монтируются ТОЛЬКО при `canManage` (сохранён инвариант
  безопасности — не disabled, а отсутствие в DOM для не-владельца).
- AC3.4 web-тест: при `can_manage:true` в шапке есть триггеры «Назначить роль»/«Дать право»; при
  `can_manage:false` — бейдж «только просмотр» и НЕТ форм в DOM.

### Часть 4 — backfill login (убрать KC-UUID из /users)
- AC4.1 `GET /api/users/accounts` НИКОГДА не возвращает KC-UUID в поле `login`. Когда `login IS NULL`
  и `slug` UUID-формы → `login=null` + `login_missing:true` (честный сигнал «логин не задан»), НЕ сырой
  UUID. Для legacy-seed (slug — человекочитаемый, напр. `e-kravtsova`, не UUID) → `login=slug` как раньше.
- AC4.2 Фронт `/users` (`screen-users.jsx`): при `login_missing` показывает честную метку
  «логин не задан» вместо `MonoId` с UUID.
- AC4.3 Серверный тест: строка с `login=NULL`, `slug`=UUID → `login:null, login_missing:true`; строка с
  `login=NULL`, `slug`=`e-kravtsova` → `login:'e-kravtsova', login_missing:false`; строка с явным
  `login='ivan.petrov'` → `login:'ivan.petrov', login_missing:false`.
- AC4.4 Без новой миграции и без живого KC на CI (решение: display-layer честность на чтении —
  UUID-логин НЕ течёт в человеческий слой; настоящий backfill из KC — follow-up при живом KC).
