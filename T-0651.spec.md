# T-0651 — Сайдбар как рабочее место

**Phase:** DESIGN → IMPL · **Wave:** W4-UX (столп 4 — агенты-с-правами, но здесь: рабочее
место человека, предпосылка для видимости всего остального) · **Task:** T-0651
**Source:** `docs/design/ux-study-2026-07-05.md` §1 (фаундер, 2026-07-05)
**Epic:** T-0647 [E-UX-HUMAN]
**ADR:** `docs/design/ADR-T0651-sidebar-workspace.md`

## 1. Проблема (из исследования, §1)

Сайдбар — свалка из **~43 пунктов одной нескроллируемой-по-группам колонкой**: Обзор →
РАБОТА → 21 приложение «Без раздела» → КОНСТРУКТОР (5) → НАБЛЮДАЕМОСТЬ (7) →
АДМИНИСТРИРОВАНИЕ (8). Три системных дыры:

1. **Нет структуры под частоту использования.** Всё видно всегда, свёрнуть нельзя —
   разделы «Конструктор/Наблюдаемость/Администрирование» нужны редко, но занимают
   столько же места, сколько ежедневная «Работа».
2. **Разделы уже сущность (T-0551/T-0552), но управление ими спрятано.** Создать раздел
   можно только на `/sections` (зона Конструктор); перенести приложение — только через
   `/apps` → строка → поповер → модалка. Из сайдбара — НИЧЕГО: ни создать, ни перенести,
   ни переименовать. Отсюда «0 разделов при 21 приложении» в тенанте.
3. **Нет per-user состояния вообще.** Ни свёрнутых групп, ни личной глубины — «настроить
   под себя» сегодня негде хранить (диагноз §0 исследования: «нет слоя персонального
   рабочего места»).

## 2. Решение (три хода, ADR §1 исследования)

**A. Структурная диета.** Постоянный рабочий слой: Обзор, Мои задачи (+счётчик),
Процессы, разделы с приложениями. Конструктор/Наблюдаемость/Администрирование —
collapsible-группы, **свёрнутые по умолчанию**. Состояние — **per-user**
(user-prefs store, ADR §2).

**B. Управление на месте боли.** «+ Раздел» прямо в сайдбаре у заголовка списка
приложений; контекст-меню приложения (Переименовать / В раздел → / Настроить поля) —
реюз существующих модалок `screen-apps.jsx` (`RenameAppModal`, `SetSectionModal`,
`buildAppMenuItems`); инлайн-переименование раздела прямо в сайдбаре.

**C. Drag-and-drop поверх кнопок ▲/▼, не вместо.** Ручной HTML5 DnD (паттерн из
`kanban-board.jsx`, T-0582 — никакой библиотеки), персист в `sort_order`/`section_id`.
Кнопки ▲/▼ остаются как первоклассная клавиатурная альтернатива (тот же принцип, что
`screen-sections.jsx` и `list-view-panel.jsx` уже используют).

## 3. Явно НЕ делаем (границы)

- **Вложенные разделы** — ADR T-0551 §6 сознательно отверг; остаётся отвергнутым здесь.
- **Мегаменю / floating-сайдбар** — движимость закрывается collapse-режимом + persist,
  не изменяемой шириной/доком.
- **Кейс-контент** — весь UI генерик; ни одного продуктового кейса не заведено этой
  задачей (anti-case-lock.sh должен остаться в пределах текущего baseline).

## 4. Реюз примитивов (ничего не изобретаем заново без необходимости)

| Что нужно | Уже есть | Новое (эта задача) |
|---|---|---|
| Раздел = сущность, CRUD | `choros.section` (migration 113), `src/http/sections.ts` — GET/POST/PATCH(`name`,`sort_order`)/DELETE | — (используется как есть) |
| Приложение → раздел | `PATCH /api/applications/:id { section_id }` | — (используется как есть) |
| Приложение → позиция ВНУТРИ раздела | **не было** (`application` не имел `sort_order`) | `sort_order` колонка (migration 129) + PATCH-поддержка |
| Переименовать приложение | `RenameAppModal` + `renameApplication()` (`apps-manage-api.js`) | — (импортируется в сайдбар как есть) |
| Перенести приложение в раздел | `SetSectionModal` (`screen-apps.jsx`) | — (импортируется в сайдбар как есть) |
| Ручной DnD (без библиотеки) | `kanban-board.jsx` (T-0582) — HTML5 draggable/dragover/drop, optimistic+rollback | адаптирован под сайдбар (apps ↔ apps, sections ↔ sections) |
| ▲/▼ reorder-паттерн | `screen-sections.jsx` (`SectionRow`, index-swap PATCH) | адаптирован в сайдбар |
| Счётчик «Мои задачи» | `GET /api/inbox` → `counts.mine` (уже в ответе, T-0401) | читается в шелле, рендерится как бейдж |
| Per-user настройка (сворачивание группы) | **не было** («нет user-prefs store вообще» — диагноз §1) | `choros.user_pref` (migration 129) + `src/http/user-prefs.ts` (GET/PUT/DELETE) — ОБЩИЙ примитив, переиспользуемый §4 исследования (личные виды/плотность) |

## 6. Приёмка (LIVE_PROOF)

1. Свернуть группу «Конструктор» → перезайти (или обновить страницу) → группа остаётся
   свёрнутой (per-user persist через `/api/user-prefs`).
2. «+ Раздел» в сайдбаре → создать раздел → раздел появляется в списке немедленно.
3. Перетащить приложение в другой раздел (DnD) → `section_id` меняется, персистится,
   видно после перезагрузки. Кнопки ▲/▼ по-прежнему работают (клавиатурный путь).
4. Счётчик у «Мои задачи» совпадает с `counts.mine` из `/api/inbox`.
