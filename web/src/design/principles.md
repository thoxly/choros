# Choros — принципы облика (local design principles)

Тонкий локальный свод поверх внешнего источника UX-паттернов
([uxpatterns-MCP](https://mcp.uxpatterns.dev) — оракул «как себя ведёт паттерн»). Здесь —
только то, что специфично для Choros и накапливается со временем (вкус продукта). Внешний
контент **не вендорим** (лицензия non-commercial): правила ниже — авторские.

Источник визуального языка — брендбук «тёплая нейтраль + кобальт». Реализация — токены
`design/tokens.css` (и самодостаточная копия `forms/form-theme.css`). Потребляй ТОЛЬКО
токены `--chs-*`; не хардкодь цвет/размер/тень в обход слоя.

---

## 1. Темы: светлая — основная

- **Светлая тема — основная** (default). Тёмная — равноправная, но вторичная.
- Флип закреплён в токенах: `:root` = светлая семантика, `[data-theme="dark"]` = тёмная.
  Любой узел, до которого тема не пробросилась (модалка, оверлей, iframe формы), падает в
  **читаемую светлую основу**, а не в нечитаемое тёмное.
- Любой новый поддокумент/iframe **наследует** активную тему приложения
  (`document.documentElement.dataset.theme`), не дефолтит в тёмное.
- **Обе темы — WCAG AA**: текст ≥ 4.5:1, крупный/UI-элементы ≥ 3:1. Это пол, не цель.
  `--chs-color-text-faint` (≈3:1) — только плейсхолдер/декор, НИКОГДА не body-текст.

## 2. Иконки: линия, без эмодзи

- Иконки — **линейные, в стиле Lucide** (stroke 1.5–2, скруглённые концы), монохром
  `currentColor`, размер из плотности (14–18px в строках/кнопках).
- **Эмодзи в продуктовом UI запрещены.** Эмодзи в коде допустимы только как временная
  заглушка; в поставляемом интерфейсе их быть не должно (включая ✓/✗ в роли иконок —
  используем маску `--chs-check` или иконку).
- Глифы исполнителей (●Человек ◆Агент ■Сервис) — это **информационная семантика**, не
  декор: цвет + форма несут смысл, дублируй текстом для доступности.

## 3. Голос: без дев-жаргона

Пользователь видит продукт, не нашу разработку. В видимом тексте **не должно быть**:

- ID тикетов и кодов задач (`T-0244`, `TSK-…` как служебный код), кодовых имён процессов
  (`telLinear`, `dogfood`, `genesis-seed`, `анти-oracle`);
- флагов БД и внутренних терминов (`is_system=true`, `seed`, `provisioned`);
- голого UUID во вводе (роль/сущность выбирается из пикера, не печатается);
- технических дат-заглушек (`1970-01-01` — признак непроставленного `created_at`).

Системные/служебные строки и пользовательские тексты — **разные слои**. В UI — человеко-
понятные названия. Моноширинные ID (`PRC-2041`, `INS-8837-A`) — допустимы как доменные
идентификаторы, если они часть продуктовой модели, а не след разработки.

## 4. Поверхности: modal vs popover vs drawer

Поведенческие детали (фокус-ловушка, Esc, scroll-lock, a11y) сверяй в uxpatterns-MCP
(`get_pattern`). Локальный выбор «какую поверхность»:

- **Modal / Dialog** — задача требует фокуса и осознанного подтверждения/ввода, перекрывает
  работу: создание сущности, опасное действие (удаление), обязательная форма. Затемнённый
  оверлей, фокус-ловушка, закрытие по Esc и крестику. Не вкладывать модал в модал.
- **Popover** — лёгкий контекст рядом с триггером, не блокирует фон: выбор из короткого
  списка, мелкая правка инлайн, подсказка-действие. Закрывается по клику вне и Esc.
  Не для длинных форм.
- **Drawer (боковая панель)** — деталь/редактирование объекта в контексте списка, когда
  пользователь хочет видеть строку рядом: карточка задачи/записи, настройка справа. Не
  крадёт навигацию целиком; уместен на широких B2B-экранах.
- **Toast** — недолгое уведомление об исходе (успех/ошибка действия), само исчезает; не для
  того, что требует решения.

Правило аффорданса: **enabled-элемент обязан что-то делать** (навигация / сеть / видимое
изменение). Если не готово — `disabled`/`aria-disabled` или метка «скоро», но не молчаливый
no-op (худшая обратная связь — её отсутствие).

## 5. Плотность: плотный B2B

- Инженерная плотность: база текста 13px, строка таблицы 34px, контрол 30px. Не «воздушный»
  consumer-стиль — это рабочий инструмент с большим числом сущностей на экран.
- Используй ширину экрана: формы не жмём в левые ~420px, когда справа пусто; широкие экраны
  — две колонки / деталь рядом со списком.
- Радиусы малые (chip 2 / control 4 / panel 6), тени сдержанные — опора на границы, не на
  тяжёлый drop-shadow.
- Моноширинный (`--chs-font-mono`, `tnum`) — для всего «машинного»: ID, таймстампы, деньги,
  числовые колонки таблиц.

## 6. Состояния — всегда явные

Любой список/деталь рендерит **компонент** состояния, не пустоту:

- **Empty** — внятный текст + явный следующий шаг (CTA), а не голый «нет данных».
- **Loading** — скелет/индикатор, не прыжок раскладки.
- **Error** — текст ошибки + «Повторить», без белого экрана (хороший образец — обработка
  500 в «Уведомлениях»: текст + ретрай).
