# Судейский вердикт T-0732 — человеко-имя движковых процессов из BPMN `<process name>`

**Вердикт: approved.**

Задача решена по существу: движковые (`source=engine`, без строки в
`choros.process_definition`) процессы получают настоящее человеко-имя из
`<process name>` через tenant-scoped оверлей-таблицу `choros.engine_process_name`,
резолвимую средним ярусом (`modeler > engine-оверлей > голый ключ`). Все семь осей
проверены адверсариально, гейты воспроизведены живьём в этом worktree, совпадают с
заявленными. Кросс-тенант закрыт RLS на NOBYPASSRLS-роли. Ни одного блокера.

---

## 1. Архитектурный выбор (a′ vs a) — ОБОСНОВАН, не over-engineering

Проверил все 4 заявленных ripple-потребителя по коду — инвариант «движковый =
ОТСУТСТВИЕ строки в `process_definition`» РЕАЛЕН и несущий:

1. **`process-start.ts:352`** — `definitionIsDraft = hasDefinitionRow && !definitionPublished`.
   `resolveProcessSandboxStateDb` (`:255`) считает `has_row = count(*)>0`. Строка (a)
   со `status='draft'` → `definitionIsDraft=true` → `wouldRunSandbox=true` → рядовой
   юзер ловит **409 SANDBOX_NOT_RUNNABLE** на старте telLinear. Коммент `:344-346`
   прямо гарантирует «directly-deployed без строки НЕ блокируются» — (a) ломает эту гарантию.
2. **`inbox.ts:draftOnlyProcessKeys` (`:757`)** — `HAVING bool_or(status='published')=false`.
   Строка (a) со `status≠'published'` → ключ draft-only → **задачи telLinear скрыты из инбокса**.
3. **`process-catalog-view.ts:buildCatalogDefinitions` ветвь 1 (`:136`)** + **`listProcessDefRows`
   (`process-catalog.ts:226`, `SELECT DISTINCT ON (process_key) … БЕЗ фильтра по status`)** —
   ЛЮБАЯ строка defRow → `source='modeler'`. Строка (a) **переклассифицирует telLinear
   в редактируемую модельер-дефиницию** (потребует фейковый `bpmn_xml`, `version`).
4. CHECK `status IN ('draft','published')` не оставляет безопасного статуса: `draft`→(1)+(2),
   `published`→(3). Вывод: (a) НЕ проще/безопаснее — трогает 4 потребителя в authz/видимости.

Оверлей (a′) трогает РОВНО 1 read-резолвер (`resolveDefinitionNames`) + каталог, НОЛЬ
authz/видимости. Выбор корректен и честно задокументирован в ADR §2 с код-обоснованием
(latitude «выбери в DESIGN» задачей дан). **Не over-engineering.**

## 2. Кросс-тенант (T-0616 §F-1 класс) — ЗАКРЫТ

- `choros_app`: `rolbypassrls=f`, `rolsuper=f` (проверено `pg_roles` живьём). RLS реально
  принуждается против рантайм-роли. `choros_migrator` (bypassrls=t) — только мигратор, не рантайм.
- FF-2 db-тест прогнан САМ и **проходит даже против замусоренной shared-БД** (`DB_ISOLATION=off`),
  где лежат 8+ остаточных `telLinear`-строк РАЗНЫХ тенантов («Имя тенанта A/B», «Секрет
  тенанта B», demo-seed) — RLS-маскировка доказана в реальном collision-состоянии. Тенант A
  резолвит ТОЛЬКО своё имя (helper И `listInstanceProjections.definitionName`).
- `cross_tenant.test.ts` с изоляцией: **202/202 PASS**; `engine_process_name` в
  `known_tenant_tables` + seeder + `SEEDED_TABLES` → generic RLS-инвариант авто-покрыл таблицу.
- Мутация «снять `WHERE tenant_id`» остаётся ЗЕЛЁНОЙ — это **КОРРЕКТНО** (зеркало T-0616
  §F-1 own-comment): реальный guard = RLS FORCE на NOBYPASSRLS-клиенте, явный WHERE =
  defense-in-depth. НЕ дыра: `choros_app` физически не может обойти RLS. Формулировка FF-2
  честно исправлена строителем (изоляция RLS-enforced, а не WHERE-mutation→red).

## 4. Фолбэк keyDemoted — ЦЕЛ

FF-3 db-тест доказывает: движковый инстанс БЕЗ оверлея → `definitionName = голый ключ`
(не пусто). Web `deriveInstanceTitle` (НЕ тронут, `process-instance.logic.js:143-149`)
демотирует `name===key` до «Процесс» + keyDemoted-чип; ключ НИКОГДА не primary. С оверлеем
→ `name!==key` → primary = человеко-имя. Инвариант «никогда голый ключ» свят.

## 5. Парс BPMN — fail-closed, DATA, без утечки

`parseBpmnProcessMeta` через общий `tokenize` (реюз `bpmn-deploy-normalizer.ts`, не regex).
→ `null` на malformed/пустом/без-name/undefined (9 unit-тестов: порядок атрибутов,
namespaced-prefix, entity-decode, empty/whitespace, no-process, first-named-wins, `parse-error`).
Имя = DATA: пишется параметризованным `$3` (SQL-инъекция невозможна), рендерится
React-escape (XSS невозможен). Инъекция в `name` — не вектор.

## 6. Резолв средним ярусом — приоритет верен, один резолвер

`resolveDefinitionNames` (`process-projection.ts:1163`): `unresolved = uniqueKeys.filter(!names.has)`
→ modeler-строка ПЕРЕКРЫВАЕТ оверлей (precedence db-тест PASS). ЕДИНСТВЕННЫЙ общий резолвер
покрывает список/деталь/инбокс; `selectEngineProcessNames` — ОДИН read-оверлей, реюзан
обоими дисплей-путями (проекция + каталог) → каталог ↔ деталь не расходятся. Дубль-резолвера НЕТ.
Врезка ВНУТРИ `try/catch` honest-degrade (DB-ошибка оверлея → фолбэк ниже, read-плоскость не падает).

  проверяет). Формулировка слегка переусилена; не дефект.
