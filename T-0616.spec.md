# T-0616 — два нит-фикса из ревью T-0614: честный proc_key fallback + tenant-scope пин

**Task:** T-0616 [standard_code, столп 1 (движок), анти-кейс чистка]
**Родитель:** ревью `docs/review/T-0614.review.json` (findings F-1, F-2 — оба `severity: nit`, не блокировали мерж T-0614, зафиксированы как явный follow-up)
**База:** dev @ `bda4a0c` (ветка `task/T-0616-proc-key-fallback`)

## 1. Контекст

T-0614 заменил три кейс-литерала в `projectionToInstance` (name/progress/execs) на
honest-резолвленные поля `InstanceProjection`. Независимый ревьюер (не автор) прогнал
три мутационные пробы на дельте и нашёл два `nit`-финдинга, не блокирующих мерж, но
зафиксированных как долг:

- **F-2** (доктрина fallback-ключа): когда `payload` НЕ содержит `proc_key` (legacy/
  битая строка), `procKey` дефолтился к КОНКРЕТНОМУ ключу `"telLinear"`
  (`export const DEFAULT_PROC_KEY = "telLinear"`, `src/http/process-projection.ts:335`) →
  `definitionName` резолвился в КОНКРЕТНОЕ имя `"Канонический линейный ТЭЛ"` (через
  `fallbackDefinitionName`, `src/core/process-catalog-view.ts:89`, которая
  спецкейсила именно строку `"telLinear"`). Т.е. «не знаю ключ → значит это ТЭЛ» —
  формально новый микро-кейс-хардкод (D-064), меньше по вреду чем прежние три
  литерала T-0614 убрал, но той же природы.
- **F-1** (coverage-gap): рантайм `resolveDefinitionNames`
  (`src/http/process-projection.ts:890-918`) защищён ДВАЖДЫ — `withTenant`
  (`SET LOCAL choros.tenant_id` + `FORCE ROW LEVEL SECURITY` на
  `choros.process_definition`, миграция 074) И явным `WHERE tenant_id = $1`
  (defense-in-depth). Но НИ ОДИН тест не пинил именно tenant-scope: мутационная
  проба ревьюера (снять `WHERE tenant_id = $1 AND`) оставила зелёными И unit-тесты
  (fake-пул матчит по тексту запроса, игнорирует `WHERE`), И живой db-тест
  `ci/checks/db/process-projection.test.ts` (T-0282 RLS-тесты не сеют
  `choros.process_definition`, поэтому `resolveDefinitionNames` там всегда бьёт в
  fallback-ветку — modeler-name-резолв вообще не упражняется). Регрессия, снявшая
  `WHERE`, проскочила бы сквозь весь набор.

## 2. Решение (кратко — полное обоснование в ADR)

**F-2.** `fallbackDefinitionName` (`src/core/process-catalog-view.ts`) больше НЕ
спецкейсит `"telLinear"` — она честно эхоит ЛЮБОЙ переданный ключ обратно, без
исключений. `DEFAULT_PROC_KEY` (`src/http/process-projection.ts`) меняет своё
ЗНАЧЕНИЕ с кейс-литерала `"telLinear"` на нейтральный синтетический ключ
`"process:unknown"` (сам этот ключ НЕ является денылист-литералом — не имя
реального сущего процесса). Итог: битая/legacy-строка без `proc_key` теперь честно
показывается как «process:unknown» (эхо через `fallbackDefinitionName`), никогда не
заимствует имя реального seed-процесса telLinear.

**F-1.** Добавлен двух-тенантный db-тест в `ci/checks/db/process-projection.test.ts`:
два тенанта, ОДИН И ТОТ ЖЕ `process_key`, РАЗНЫЕ `choros.process_definition.name`
(A/B) → `listInstanceProjections(tenantA)` видит ТОЛЬКО имя A, никогда имя B. Тест
краснеет при снятии `WHERE tenant_id = $1` из `resolveDefinitionNames` (проверено
мутационно — см. отчёт ниже).

## 3. Acceptance criteria

- **AC-1** (F-2, честный дефолт): `fallbackDefinitionName("telLinear")` возвращает
  `"telLinear"` (сам ключ), НЕ `"Канонический линейный ТЭЛ"`. `verifiable_as: test`.
- **AC-2** (F-2, нейтральный процкей): проекция строки БЕЗ `proc_key` в payload
  резолвит `definitionName` в честный нейтральный machine-key (`DEFAULT_PROC_KEY`
  echo), НЕ в имя какого-либо реального seed-процесса. `verifiable_as: test`.
- **AC-3** (F-2, анти-кейс не растёт): `bash ci/checks/anti-case-lock.sh` и
  `bash ci/checks/detel-literal-baseline.sh` остаются PASS; repo-wide code-only
  count `telLinear` СТРОГО НЕ РАСТЁТ (в этой задаче — падает 3→1, записано в
  обновлённом `ci/checks/data/anti-case-baseline.json`). `verifiable_as: fitness`.
- **AC-4** (F-1, regression pin): новый db-тест
  `ci/checks/db/process-projection.test.ts` (`T-0616 [F-1]`) зелёный на реальном
  Postgres против production RLS-пути. `verifiable_as: fitness`.
- **AC-5** (F-1, мутационное доказательство): снятие `WHERE tenant_id = $1 AND` из
  `resolveDefinitionNames` (`src/http/process-projection.ts`) даёт КРАСНЫЙ новый
  тест (не только теоретически — проверено живьём на дельте, мутация откачена).
  `verifiable_as: test`.

## 4. Out of scope

- Полная деТЭЛизация `DEFAULT_PROC_KEY`-путей (F-2 не убирает сам факт fallback-а —
  запись `proc_key` в payload остаётся безусловной на write-half; фолбэк реален
  только для доисторической/битой строки — near-unreachable, но не удалён как
  ветка кода).
- `web/src/forms/FormBuilder.jsx:509`'s `placeholder="telLinear"` — UI copy-хинт
  (пример в форме), не платформенный дефолт данных; вне периметра F-1/F-2.

## 5. Риски / эскалация

Нет эскалации. Чисто READ-путь + один нейтральный fallback-key + один
регресс-пинующий db-тест; ни одного нового write-пути, ни одного нового
authority-предиката.
