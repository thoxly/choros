# T-0682 — судейский вердикт (адверс REVIEW + UX_REVIEW)

**Вердикт: approved.**

FormDesigner: collection-поле не surfaced в палитре при первом выборе набора на
загруженном биндинге. Фикс расщепляет `skipNextSchemaRebuildRef` через чистую
экспортированную `planSchemaRebuild(def, {skipDocRebuild,...})`: `fields` ВСЕГДА
репарсятся из живой схемы, скипается только document rebuild
(history/savedDocRef/selectedKeys).

## Судьба защиты T-0656 P0 (главный риск) — СОХРАНЕНА

Трассировка ВСЕХ эффектов FormDesigner:

1. **Ни один `useEffect` не имеет `fields` в deps.** Grep по файлу: потребители
   `fields` — это `validation` (useMemo, чистый расчёт `validateDocument`),
   `addFieldBlock`/`handleDrop` (useCallback, только пересоздают хендлеры),
   `selectedSchemaField` (derived), и рендер палитры (1371-1373). НИ ОДИН не
   вызывает `setHistory`/`savedDocRef`. Значит безусловный `setFields(plan.fields)`
   НЕ запускает каскад, который опосредованно перестроил бы документ.
2. **Документ перестраивается ровно в одном месте** — внутри эффекта 808, и только
   когда `plan.doc` не null, т.е. только когда `skipDocRebuild=false`. При загрузке
   биднинга `skipNextSchemaRebuildRef.current=true` → `plan.doc===null` →
   history/savedDocRef/selectedKeys не тронуты. AC-2 (unit) подтверждает `doc:null`
   на реальном вызове функции.
3. **`isDirty` зависит от `[doc, saveGen]`, НЕ от `fields`** — безусловный setFields
   не порождает ложное «есть несохранённые изменения».
4. **Побочный плюс ordering.** В dev skip-флаг читался ДО `const def = find(...)`;
   теперь — ПОСЛЕ `if (!def) return` (812-813). Если эффект транзиентно стреляет,
   когда `def` ещё не найден в `registryDefs`, флаг НЕ съедается преждевременно и
   доживает до реального rebuild-момента. Это УСИЛИВАЕТ защиту T-0656 в гонке
   «registryDefs пришли, но нужный def ещё не найден», а не ослабляет.

Итог: загруженный layout не затирается flat-rebuild-ом ни напрямую, ни через
каскад по `fields`.

## Вторая сторона бага (палитра с первого выбора) — ЗАКРЫТА

Цепочка доказательства при MOUNT-GAP (в репо нет jsdom/@testing-library, node-env
подтверждён `vitest.config.js:32`):
- AC-1 (реальный вызов `planSchemaRebuild`): при `skipDocRebuild:true` `fields`
  содержит collection-поле (`type==='collection'`).
- regression-lock: эффект перепроволочен на `planSchemaRebuild` +
  `setFields(plan.fields)`; старый ранний guard-return удалён из исходника
  (structural assert).
- Палитра рендерит из `fields` (1371-1373, не тронуто).
Три звена вместе доказывают: первый выбор набора на загруженном биднинге → палитра
получает collection. Тесты нетавтологичны — гоняют РЕАЛЬНУЮ production-функцию, не
байт-зеркало.

**UX-ветки (второй клик):** после первого прохода flag съеден; смена набора
туда-обратно даёт flat-rebuild (ожидаемо — пользователь сам сменил набор, T-0656
это pre-existing поведение, не регресс). Legacy-биндинг (fields без layout): флаг
не взводится → полный rebuild, палитра корректна. Ветки, где для палитры нужен
второй клик, НЕ остаётся — `fields` теперь репарсятся при КАЖДОЙ смене def.

## Non-blocking (нит)

- **N1 (тесты):** MOUNT-GAP — эффект сам не монтируется/не драйвится; доказательство
  держится на unit чистой функции + structural source-string assert. Приемлемо при
  отсутствии jsdom в тире (документировано в шапке файла), но полноценный mount-тест
  жизненного цикла skip-флага возможен только после появления jsdom-тира.
- **N2 (UX, поведенческий нюанс):** палитра И `validation` теперь берут поля из ЖИВОЙ
  схемы на первом проходе (раньше — из saved-binding `data.fields`). Если живая схема
  биднинга ДРЕЙФАНУЛА (поле удалено после сохранения), реопен теперь покажет
  broken-key валидацию на первом paint (раньше — только со второго клика). Это
  ЧЕСТНЕЕ и совпадает с серверным `resolveLiveRecordSchema`, но это видимое изменение
  поведения шире заявленной цели (surfacing collection). Не блокирует.
- **N3 (scope):** regression-lock тест сцеплен с точными строками исходника (ломок к
  реформату). Осознанно — единственный способ доказать перепроволочку эффекта при
  MOUNT-GAP. Приемлемо.

Строит ≠ судит (D-007): код строителя не правил; подмена на dev была транзиентной
верификацией RED, файл восстановлен из HEAD.
