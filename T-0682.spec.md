# T-0682 — FormDesigner: collection-поле не surfaced в палитре при первом выборе набора на загруженном биндинге

**P2 из live-proof T-0680, эпик E-FORMS T-0479.**

## Симптом

Открыв FormDesigner на процесс+шаг с УЖЕ сохранённым биндингом (есть `layout`), при первом
выборе registry-набора палитра НЕ показывает collection-поле (напр. таблицу), присутствующее в
живой схеме набора, — оно появляется только после ПОВТОРНОГО выбора того же набора. Новичок на
существующей форме не увидит таблицу без «второго клика».

## Корень

`skipNextSchemaRebuildRef` (`web/src/forms/FormDesigner.jsx`) выставляется `true` один раз при
загрузке существующего `layout` (F3, T-0656 P0), чтобы schema-rebuild эффект не затёр загруженную
раскладку. Но следующий проход этого эффекта при `skip=true` пропускал ЦЕЛИКОМ И
`parseRecordSchema`/`setFields` (палитра), И rebuild документа — хотя это две разные вещи:
палитра рендерится из `fields`, документ — из `history`/`savedDocRef`. Skip-флаг глушил
актуальность палитры, хотя был нужен только для защиты документа.

## Acceptance criteria

- AC-1: первый проход schema-rebuild эффекта на загруженном биндинге ВСЕГДА вызывает
  `parseRecordSchema`/`setFields` — палитра получает collection-поле (и любые другие поля живой
  схемы) с первого выбора набора, без повторного клика.
- AC-2: когда skip-флаг взведён, документ (`history`/`savedDocRef`/`selectedKeys`) НЕ
  перестраивается — загруженная раскладка не затирается (T-0656 P0 инвариант сохранён).
- AC-3: без загруженного биндинга (skip-флаг никогда не взводился) поведение не меняется —
  выбор набора строит fields+doc как раньше.
- Анти-кейс: фикс не завязан на конкретный слаг/тип поля — работает для ЛЮБОГО поля живой схемы,
  не только collection; в `src/` (в т.ч. `web/src/`) не появляется ни одного кейс-литерала
  (слаг/бизнес-название) — только в тестовых фикстурах.
