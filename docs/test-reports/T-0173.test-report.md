## Known findings (from REVIEW)

**R-1 (nit, axis 4, open):** `actorId` from X-Dev-User header not validated as UUID before use as parameterized SQL argument. No injection risk (parameterized). In dev-mode any string is accepted; Keycloak mode enforces real identity. Consistent with `notification-prefs.ts` pattern. Candidate fix: call `assertUuidShape(actorId, 'actorId')` when switching to KC mode.

**R-2 (nit, axis 2, open):** ADR T-0120 §2.2 mentions `event_kind` filter for GET /api/notifications; spec FR-6 explicitly omits it. MVP-scope narrowing accepted. Stage-2 candidate.

No blocking findings.
