## Semantic confirm note (AC-20 / anti-autofill floor)

The `isValidConfirm` function enforces a **semantic floor** on the `consequenceStatement`: it rejects length < 10, digit-only sequences, repeated-char sequences, and single "forbidden" words (ok / да / yes / no / нет / confirm / подтверждаю / confirmed). This floor is intentionally **UI/human-surface enforcement** (per T-0073 — human-confirm UX surface), not a content-security check. The forbidden-list is documented in the spec and the function is pure-core (no IO). The implementation matches the spec §1 paragraph 2 post-R-2 fix.

---

## core_pinned absolute — lossy_live_migration (AC-19 / ADR §5)

`lossy_live_migration` is classified as `core_pinned` **unconditionally** (regardless of `isCorePinned` context). This is stricter than T-0177's `isLossyNarrowing` (which only elevates destructive→core_pinned for core-pinned fields). The distinction is deliberate per ADR §4 RED-LINES (строки 154-155): a live-migration that loses running-instance state is categorically forbidden, no escape-hatch via confirm+force.
