### R-6 детали (write-path characterization)

ADR §2.4 теперь содержит явный write-path блок после vendor-update-description:
- **Роль**: provision-writer работает под привилегированной provision-ролью (migrator/provisioner-класс)
- **Граница «только `scope='system'`»**: запись `scope='tenant'`-строк в чужой тенант запрещена
- **Граница «только проекция»**: insert/update только строк с `catalog_version NOT NULL`, пришедших из vendor-master `a0…001`
- **Аудит**: каждая projection-операция → `doc_log('system_doc_projected')` + `audit_event('docs.system_projected')`
- **Недоступна harness**: provision-роль не делегируется (`delegable=false`, T-0122)
- **Контракт-строка**: FF-DOCS-PROJECTION-WRITE (static-now: grep provision-writer ⇒ только `scope='system'`-ветви; grep harness-grant-seed ⇒ нет provision-роли в `delegable=true`; assert `catalog_version IS NOT NULL` при projection-insert)

Это не нарушает NF-1: NF-1 запрещает второй authz-механизм на read/harness-поверхности, которая по-прежнему единая (grant-модель T-0018/T-0021); provision-write = инфраструктурный setup-класс (как seed-миграции), не authz-поверхность.
