**AC-13 note (R-3 deferred nit):** Rollback correctness is architecturally guaranteed by `withTenantTx` (single ROLLBACK on any exception), but no explicit test simulates an audit-write failure mid-transaction to verify DB state reverts. Deferred as a low-risk nit — candidate for next T-0121 slice (T-0121d or standalone).

**R-5 note (N+1 on force path, deferred nit):** The force path iterates `destructiveDeps` and issues one `UPDATE report_page_dep` per dep row, and one `UPDATE report_page` per affected page. This is an N+1 pattern in the UPDATE loop. At typical schema-change cardinality (≤10 affected deps) this is acceptable; a bulk UPDATE via unnest would be more efficient. Deferred as a performance nit — candidate for next T-0121 slice.

## Authz fact — PUT /api/registry-defs/:id force path

**Current gate (factual):** No PDP gate is wired. The force path contains an explicit `TODO(T-0021)` comment:

```ts
// TODO(T-0021): wire real grant PDP check: assertGranted(actor,
//   'mgmt_object:schema_destructive', 'apply', { registry_def_id: registryDefId })
// Dev-mode: force is accepted from any authenticated actor (honest degrade).
void actor;
```

Any authenticated actor (any valid `x-dev-user` in dev mode, or any Keycloak-authenticated subject) can pass `force=true` and execute the destructive path without a `mgmt_object:schema_destructive/apply` grant check. This is an honest dev-mode stub consistent with the T-0021 seam pattern, but means the authz gate specified in FR-5 / spec §3 is not enforced at runtime.

**Spec says:** FR-5 requires `grant(resource_type='mgmt_object:schema_destructive', operation='apply')`, else 403 FORBIDDEN.

**Recommendation:** Backlog candidate for T-0021 integration (real PDP wiring). Not a blocker for this task (honest degrade, not a silent bypass; `void actor` is explicit).
