## R-N2 nit — dual-control banner admin hint

Applied at commit 30d9ff3. Banner text now includes: `Второй подтверждающий обязан иметь admin-полномочия — проверяется бэкендом.`

**Backend authority check finding (R-N2):** Reviewed `src/http/grants.ts` `handleSecondConfirm` (lines 1162–1264). The function enforces:
- distinctness: `actor !== row.proposed_by && actor !== row.confirmed_by` → 409 `self_confirm` if violated
- idempotency: `confirmed2_by IS NULL` → 409 `already_confirmed` if already filled

It does **NOT** re-run `validateAdminDelegation` for the second confirmer. The admin gate runs only at first-request time (`POST /api/grants` phase=propose). The second-confirm path assumes the second actor is trusted by virtue of being authenticated and distinct. This is a deliberate T-0044 rev-2 design decision (documented in the module-level comment: "The second approver arrives in a SEPARATE confirm2 request" and R-AUTH). The banner hint "проверяется бэкендом" is therefore **technically imprecise** — the backend enforces distinctness, not admin authority, for the second actor.

**Disposition:** Flagged as handoff candidate per task brief. Not fixed in T-0137 — this is a T-0044 rev-2 design gap, not a T-0137 regression. The UI hint is retained as a user-guidance note (correct intent, slightly overstatement of backend behaviour). See PR handoff notes section.
