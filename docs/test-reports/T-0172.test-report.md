## Known findings

**R-1 (nit, axis 3, open):** `defaultTemplateRenderer` (html=false) is documented for plain-text (in-app/SMTP text:). EmailChannelDriver (T-0170) uses `text: job.body` — if/when HTML email bodies are introduced, caller must do a separate `renderNotification(..., {html:true})` call before SMTP. Gap documented in code comment. Follow-up: HTML email render path — separate task when HTML email transition occurs per E-N roadmap.

**R-2 (nit, axis 4, open):** No test for fullwidth Unicode lookalike chars (U+FF1C `＜`, U+FF1E `＞`) explicitly documenting they are not HTML-dangerous (HTML parsers do not interpret fullwidth as tags). Not a security gap — osознанно not a threat. Deferred.
