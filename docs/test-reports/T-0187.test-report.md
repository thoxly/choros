## Merge-window note (IMPORTANT for orchestrator)

When rebasing this branch onto dev, **`package.json` will conflict with any sibling branch that adds fitness entries** — because the old "append to tail of duplicate key" pattern is no longer valid. The resolution rule is:

> **Produce exactly one `"fitness"` key that is the union of all commands from both sides of the conflict.** Any merge that creates a second `"fitness"` key, or drops entries from either side, is incorrect. After resolution, `bash ci/checks/package-json-no-dup-keys.sh` must exit 0 and the entry count must equal the sum of unique additions.

The guard check (`ci/checks/package-json-no-dup-keys.sh`) is the canary — it will immediately fail npm run fitness if a duplicate key survives the merge.
