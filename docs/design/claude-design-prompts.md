## A. Общий хедер (вставляется дословно в начало КАЖДОГО промпта)

```
КОНТЕКСТ ПРОДУКТА — Choros:
Процессная платформа (BPMN) для компаний 150–300 человек, где люди, ИИ-агенты и
микросервисы — равноправные исполнители в одной оргструктуре, под одним control
plane и одним аудит-логом. Это рабочий инструмент на весь день, не лендинг.
Рынок — RU mid-market, ВЕСЬ UI-текст на русском.

ДОМЕННАЯ МОДЕЛЬ (актуальная):
- Три исполнителя = три типа шага: User Task → человек; Agent Task → ИИ-агент;
  External Task → микросервис.
- Агент = ПОЛИМОРФНЫЙ СОТРУДНИК: та же сущность employee, что и человек, с маркером
  типа. У агента дополнительно: своя LLM (endpoint/модель, BYO — клиент хостит),
  зарезервированный бюджет, порог автономии, правила эскалации.
- Права — от РОЛИ, не от человека/агента. Атом права = «грант» {роль, ресурс,
  операция, охват(scope)}; доступные инструменты и видимые поля форм — ПРОИЗВОДНЫЕ
  от грантов, не отдельные тумблеры.

ЭСТЕТИКА — инженерный / Linear-grade (НЕ МЕНЯТЬ):
- Тёмная тема по умолчанию + равноправная светлая (через [data-theme]).
- Тугая плотность: строки таблиц 32–36px, таблицы, а не «воздушные карточки».
- Резкие грани, маленькие радиусы, минимум теней.
- ЗАПРЕЩЕНО (это «AI-slop»): сиреневые градиенты, крупные скругления, мягкие
  тени-облака, emoji, шрифт Inter по умолчанию.

ТИПОГРАФИКА:
- Гротеск (не Inter) для интерфейсного текста.
- МОНОШИРИННЫЙ для всего «машинного»: ID процессов/инстансов, таймстампы, бюджеты
  (токены/деньги), статусы, числа в таблицах.

ФИРМЕННАЯ СЕМАНТИКА ТРЁХ ИСПОЛНИТЕЛЕЙ — сквозной приём через весь продукт.
Человек / ИИ-агент / Сервис ВСЕГДА узнаются одним цвето-иконочным кодом:
  • Человек → --chs-exec-human · Агент → --chs-exec-agent · Сервис → --chs-exec-service

ТЕХНИЧЕСКИЙ КОНТРАКТ ВЫВОДА (обязательно):
- React + CSS. ВСЕ цвета/отступы/типографика/радиусы/тени — только через
  CSS-переменные в одном :root, префикс --chs-* (chs = CHoroS). Никаких хардкодов.
- Фиксированные группы: --chs-color-*, --chs-space-*, --chs-font-*, --chs-radius-*,
  --chs-exec-human / --chs-exec-agent / --chs-exec-service.
- Компоненты по доменной модели: ExecutorBadge, TaskRow, AuditEvent, ProcessTimeline,
  MonoId, BudgetMeter. (Новые для прав — см. П1R; красить теми же --chs-*.)
```

> (3) агент = полиморфный сотрудник (та же строка, маркер типа).

```
[ВСТАВЬ ОБЩИЙ ХЕДЕР]

ЗАДАЧА: 4 экрана каркаса продукта на токенах дизайн-системы.

1. ОРГСТРУКТУРА — слева дерево «подразделение → должность → сотрудник». Сотрудник =
   человек ИЛИ агент (одна сущность, маркер типа --chs-exec-human/-agent). Справа —
   КАРТОЧКА ИСПОЛНИТЕЛЯ:

2. ИНБОКС ЗАДАЧ — плотная таблица: задача, процесс (MonoId), тип исполнителя (ExecutorBadge),

3. ТАЙМЛАЙН АУДИТА ИНСТАНСА (hero) — единый вертикальный поток событий человек/агент/сервис;

4. КАРКАС — левая навигация (раздел «Права и доступ» = отдельный пункт), топбар,
```

## D. Промпт 1R — Права и доступ (НОВАЯ hero-поверхность, вариант B)

> Новый проект/поверхность. В v0.1 прав-управление было тривиальным; теперь это центр
> модели (подписанный GT-1 dual-control). Наследует ту же дизайн-систему и --chs-*.

```
[ВСТАВЬ ОБЩИЙ ХЕДЕР]

ЗАДАЧА: hero-поверхность «Права и доступ» — управление ролями/грантами под аудит.
Это отдельный раздел, наследует дизайн-систему. Покажи 4 экрана:

1. РЕДАКТОР РОЛИ (структурные гранты, НЕ список тумблеров инструментов):
   • Прогрессивное раскрытие: ПРОСТОЙ режим (пресеты «чтение реестра X», «утверждать
     заявки в своём подразделении») + РАСШИРЕННЫЙ (полный грант {ресурс, операция, scope}).
   • SCOPE-ПИКЕР по закрытой решётке: узлы оргструктуры (дерево) + теги (мультивыбор) +
     числовые интервалы; для сквозной роли — НАБОР узлов (scope-set). Подчеркни, что охват
     можно только СУЖАТЬ (монотонное сужение), не расширять выше своего.
   • Блок «опиши роль словами → LLM предлагает гранты → ты подтверждаешь»: текстовое поле →
     список предложенных грантов с пометкой «предложено LLM», каждый требует явного
     подтверждения человеком (proposed_by → confirmed_by).

2. КРИТИЧНОСТЬ И DUAL-CONTROL (ядро модели):
   • Бейдж role_criticality с тремя осями: «утверждает/исполняет guarded-переход»,
     «вызывает внешние интеграции», «читает чувствительные данные». Критичная роль визуально
     помечена.
   • Экран ПОДТВЕРЖДЕНИЯ изменения прав: если назначение поднимает критичность — показать
     «ТРЕБУЕТСЯ ДВА АППРУВЕРА», эффективный дифф (что реально расширяется, не построчный),
     список аппруверов и их статусы; для некритичного — один scoped-аппрувер. Состояния:
     ожидает / частично подтверждено / подтверждено / отклонено.

3. SoD И КОНФЛИКТЫ — индикатор несовместимых ролей (кто запрашивает ≠ кто утверждает);
   при попытке назначить конфликтную пару — предупреждение со ссылкой на правило.

4. ЖУРНАЛ ВЫДАЧИ ПРАВ (grant trail) — плотная таблица append-only: кто, кому, какой грант,
   когда, предложил/подтвердил, охват. Моно-ID и таймстампы. Это часть единого аудита.

Все цвета/отступы — через существующие --chs-*. Критичность маркируй сигнальным акцентом +
статус-чипами из дизайн-системы; НЕ вводи новых цветовых групп без необходимости.
```

## G. Что изменилось против промптов v0.1 (changelog)

1. **Хедер:** добавлен блок «ДОМЕННАЯ МОДЕЛЬ» (агент = полиморфный сотрудник; права = гранты,
   инструменты/поля — производные). Эстетика и тех-контракт не тронуты.
2. **Промпт 1 (Chrome):** убрано редактирование прав (вынесено в П1R); карточка агента обогащена
   (BYO-LLM, бюджет-резервирование две крыши, порог автономии); роли показаны как назначения (read);
   в аудит добавлена пара «предложил→подтвердил».
3. **Промпт 1R (НОВЫЙ):** вся прав-поверхность — структурный грант-редактор + scope-решётка +
   role_criticality + dual-control (подписанный центр модели) + SoD + журнал выдачи прав +
   «LLM предлагает → человек подтверждает».
4. **Промпты 2/3:** без изменений (bpmn-js и form-js+sandbox подтверждены актуальной моделью).
5. **Не менялось:** эстетика Linear-grade, правило структуры (одна система + проект на поверхность),
   контракт `--chs-*`, репо-маппинг.
