# Choros — AI-консоль: агент настраивает + аналитик (ADR · E17)

> Раздел «Ассистент» с чатами, где пользователь вызывает агента, чтобы (1) НАСТРОИТЬ
> систему под клиента (внедрение разговором — USP) и (2) получить ОТЧЁТ/РЕКОМЕНДАЦИЮ из
> данных. Один surface, два режима, оба — агенты-акторы с грантами.

## 1. Решение в одной строке

**Отдельный раздел «Ассистент» = треды-чаты. ОДИН surface, агент сам роутит намерение
(настроить vs проанализировать). Под капотом — два грант-профиля: КОНФИГУРАТОР (авторит
модель E16 в DRAFT, promote человеком) и АНАЛИТИК (read-only по данным + журналу,
выдаёт отчёт/рекомендацию). Агент действует ОТ ИМЕНИ пользователя — в пересечении своих
грантов и грантов спрашивающего (изоляция + безопасность). Чат — РАВНОПРАВНАЯ дверь с
визуальным конструктором к одной DRAFT-модели, не замена. Вывод аналитика — эфемерный в
чате + «сохранить как Отчёт/Рекомендацию» (сущность). Каждое действие агента — в едином
аудит-логе.**

---

## 2. Режим КОНФИГУРАТОР (внедрение разговором)

- «настрой раздел продаж», «добавь поле ИНН в счёт», «сделай согласование с юристом при
  сумме > 5млн» → агент интерпретирует намерение и **авторит модель E16** (сущности, формы,
  процессы, привязки/триггеры, исходы, связи).
- **DRAFT-only**, promote — человеком (дословно extensibility §4: config-агент = сотрудник
  с ролью→MCP-tools, бюджетом, границей; tools `emit_form_code`/`edit_jsonschema`/
  `author_dmn`/`author_binding`/`open_draft_branch`/`request_promote`).
- Показывает **человеко-читаемый changelog** + независимый валидатор (extensibility §7/§9):
  «добавлено поле X, мягкая миграция, БЕЗ потери данных». Нетехничный клиент жмёт promote.
- **Равноправие с конструктором (несущее):** чат и визуальный конструктор/модельер авторят
  ОДНУ DRAFT-модель — один валидатор, один promote-гейт. Чат = «опиши словами» (Floor-2,
  агент), конструктор = «поправь точно» (Floor-1, человек). Расходиться нельзя — иначе
  две истины. RED-LINE: деструктив (drop/rename поля, lossy-миграция) — категорический
  human-confirm (extensibility §4 default-DENY).

---

## 3. Режим АНАЛИТИК (отчёт / рекомендация из данных)

- «собери отчёт по сделкам за квартал», «дай рекомендацию по клиенту X из истории работы»,
  «какая маркетинг-стратегия из этих данных».
- Читает **записи** (GROUP BY по `record.data`) + **журнал событий** (метрики §4: скорость,
  горлышко, человек-vs-агент) + связи (`cross_app_ref`) — **в рамках ACL спрашивающего**
  (видит только то, что видит пользователь; record-level RBAC, redaction на хопах).
- **Бизнес-данные НЕ пишет.** Если рекомендация ведёт к действию — **предлагает** «запустить
  процесс X?», подтверждает человек (граница автономии CONCEPT §3).
- **Вывод:** эфемерный ответ в чате + кнопка «сохранить как Отчёт/Рекомендацию» → создаёт
  запись (доктрина: результат = сущность; шарится, аудируется, перезапускается). Связь с
  report-pages (T-0121) как местом «сохранённых отчётов».
- Субстрат — **журнал событий S3**: «попроси отчёт» стоит ровно на метрик-машинерии, которую
  мы построили; без неё аналитика по процессам невозможна.

---

## 4. Гранты, изоляция, аудит

- Агент = актор в оргструктуре (CONCEPT §3). Действует **на пересечении своих грантов и
  грантов пользователя** → менеджер «отчёт по моим сделкам» видит только свои; админ
  «настрой процесс» получает config-authoring.
- **Per-tenant**: RLS-граница, агент не выходит за тенант.
- **Аудит**: каждый вызов инструмента/чтение/DRAFT-правка — в едином аудит-логе (тот же
  журнал, что метрики). Прозрачность «что сделал агент» (уточнение фаундера) = changelog
  (config) + audit-trail (всё).
- LLM-провайдер — конфигурация, не зависимость (CONCEPT §12): любой OpenAI-совместимый
  эндпоинт; дефолт — Claude (CONCEPT стек).

---

## 5. Surface (раздел «Ассистент»)

- **Треды-чаты** (история, как в обычном AI-чате); каждый тред = конфиг ИЛИ анализ (агент
  роутит).
- В пространстве **АВТОРИНГА** (E16 §8), не в рабочих доменах конечного пользователя —
  но доступен по правам (аналитик-режим доступен и обычным пользователям в рамках их данных).
- Контекст-aware: из карточки/раздела можно «спросить ассистента про это» (предзаполненный
  контекст записи/приложения).

## Открытые вопросы (точки решения фаундера)

- **Чат-primary vs co-equal с конструктором:** co-equal (рекоменд.) — обе двери к одной
  модели. (confidence: high)
- **Отчёт-как-сущность по умолчанию:** эфемер + save-on-click (рекоменд.) vs всегда
  сохранять. (medium)
- **Кто видит аналитик-режим:** все в рамках своих данных (рекоменд.) vs только
  роли-аналитики. (medium)
- **Может ли конфигуратор promote сам в DRAFT-tier (не prod):** нет — promote всегда
  человеком (extensibility §4 инвариант). (high)
- **Контекст-окно/стоимость:** бюджет на тред (токены/деньги, CONCEPT §3 бюджеты агента). (medium)
