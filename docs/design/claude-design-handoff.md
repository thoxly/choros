## 1. Что такое Choros (стабильное ядро)

Процессная платформа (BPMN) для компаний 150–300 человек, где **люди, ИИ-агенты и
микросервисы — равноправные исполнители** в одной оргструктуре, под одним control
plane и одним аудит-логом. Дифференциатор против ELMA/BPMSoft/Camunda: **агент =
сотрудник** (должность, роли, права → доступные инструменты, бюджеты, граница
автономии, аудит каждого действия), а **формы — кодом (позже AI-generated), а не
low-code конструктором**.

Три типа рабочего шага = три исполнителя:
- **User Task** → человек (форма, инбокс, SLA, эскалация)
- **Agent Task** → ИИ-агент (цель, MCP-инструменты, бюджет, граница автономии)
- **External Task** → микросервис (топик, retry, идемпотентность)

## 2. Дизайн-решения, зафиксированные в прошлой сессии (от архитектуры почти не зависят)

### Инструмент: Claude Design (Anthropic Labs, research preview)
- Единица работы — **проект**; каждый проект **наследует дизайн-систему
  организации** автоматически.
- Систему строит на онбординге, **читая репозиторий и дизайн-файлы** (совет:
  линковать конкретные подпапки, не весь монорепо).
- Вывод — **настоящий код**. Экспорт: `.zip`, standalone HTML, PDF/PPTX/Canva и
  **«Handoff to Claude Code»** (bundle одной командой). Это мост к реализации.
- Нюанс: фронта в репо ещё нет → читать ему нечего → порядок обратный: Claude
  Design **создаёт** систему по промпту, токены экспортируются в репо, потом
  (опционально) репо линкуется для наследования.

### Эстетика (ВЫБРАНО пользователем — не менять): «Инженерный / Linear-grade»
- Тёмная тема по умолчанию + равноправная светлая (через `[data-theme]`).
- Тугая плотность: строки таблиц 32–36px, таблицы, а не «воздушные карточки».
- Резкие грани, маленькие радиусы, минимум теней.
- Запрещено (= «AI-slop»): сиреневые градиенты, крупные скругления, мягкие
  тени-облака, emoji, Inter по умолчанию.
- Типографика: гротеск (не Inter) для текста; **моноширинный** для «машинного»
  (ID процессов/инстансов, таймстампы, бюджеты, статусы, числа в таблицах).
- **Фирменная семантика трёх исполнителей** — сквозной цвето-иконочный код
  (человек / агент / сервис) через весь продукт.
- Hero-поверхности: (1) инбокс задач, (2) таймлайн аудита инстанса процесса.

### Правило структуры (не менять без причины)
Не «всё в одном проекте» и не «три независимых системы», а:
**одна общая дизайн-система + отдельный проект на каждую поверхность**, все наследуют систему.

```
Проект 0 — «Choros · Design System»   → фундамент (токены + примитивы)
Проект 1 — «Choros · Chrome»          → оргструктура, инбокс, таймлайн аудита, каркас
Проект 2 — «Choros · BPMN Canvas»     → тема поверх bpmn-js
Проект 3 — «Choros · Forms»           → тема поверх form-js + примеры форм
```

### Линчпин: контракт токенов `--chs-*`
Единый набор CSS-переменных (`chs` = CHoroS), вставляемый дословно в начало
каждого промпта. Пока контракт один — три проекта + bpmn-js + form-js красятся
одними переменными и не разъезжаются. Фиксированные группы имён:
`--chs-color-*`, `--chs-space-*`, `--chs-font-*`, `--chs-radius-*`,
`--chs-exec-human / --chs-exec-agent / --chs-exec-service`.
Компоненты — по доменной модели: `ExecutorBadge`, `TaskRow`, `AuditEvent`,
`ProcessTimeline`, `MonoId`, `BudgetMeter`.

- [ ] **Объектная модель** — JSON Schema + JSONB, права на уровне записей.
- [ ] **Аудит-лог единый** — люди + агенты + сервисы в одном потоке. (Hero-экран.)
- [ ] ⚠️ **RBAC / ролевая модель — НАИБОЛЕЕ вероятный источник расхождения.**
