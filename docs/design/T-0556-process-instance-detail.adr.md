# ADR · T-0556 — Открытие экземпляра процесса (detail-вью + чинить «Открыть»)

**Phase:** DESIGN · **Status:** ready (design-default; фаундер away — может пересмотреть, PD не выпускался) · **Date:** 2026-06-30
**Task:** T-0556 [процессы] (родитель T-0537 E-NAV-IA)
**Origin:** приёмка процессов 2026-06-30 (параллель к T-0552 apps / inbox — «не могу открыть»).
**Foundation (факты кода):** `web/src/screens/screen-processes.jsx:610` («Открыть» → `navigate('/audit')`); `src/http/processes.ts` (`GET /api/processes` список, **`GET /api/processes/:id` уже есть**, `ProcessInstance`: status running|waiting|done|failed, node/nodes T-0456, progress, execs, recordId); `web/src/app-shell/shell.jsx` (роуты: `/processes`, `/processes/:id/edit`, `/processes/:key/branch-rules`, `/process-analytics` — **detail-роута экземпляра НЕТ**); `src/http/process-defs.ts` (publish-гейт). Связь: T-0552 (та же тема достижимости «осмотреть»), T-0554/PD-25 (публикация — отдельная ось, здесь не трогаем).

## 1. Проблема

Запущенный экземпляр процесса **виден в списке** `/processes` (имя, статус, текущий узел,
прогресс, исполнители), но **открыть его нельзя**:

- кнопка «Открыть» **захардкожена** на `navigate('/audit')` ([screen-processes.jsx:610]) —
  игнорирует `inst.id`, ведёт всех на общий экран аудита;
- **роута `/processes/:instanceId` и detail-экрана НЕТ** (есть только список, модельер
  `/:id/edit`, DMN `/:key/branch-rules`, аналитика).

Пользователь не может посмотреть: на каком шаге процесс, кто согласует, что дальше, история
переходов, какая запись его породила. Это тот же системный дефект достижимости, что в
приёмке приложений (T-0552, редактор полей) и инбокса (нет предпросмотра пул-задачи).

**Данность:** бэкенд готов — `GET /api/processes/:id` уже отдаёт полный `ProcessInstance`.
Не хватает только экрана и правильной навигации.

## 2. Что доказано (приёмка)

- 3 дефа: acceptance-demo (Опубликован, 1 инстанс), novyy-protsess (Черновик), probe-proc
  (Опубликован, 0). Статусы честные — publish-гейт реален (см. T-0554 §1).
- Инстанс acceptance-demo `07a450cb…` — источник 2 inbox-задач; «Открыть» по нему уводит на
  `/audit`, а не на карточку инстанса.
- Дополнительно вскрыто: (а) верхняя панель `/processes` показывает **«Нет активных
  процессов»**, хотя инстанс жив (рассинхрон `GET /api/processes` ↔ счётчик каталога дефов);
  (б) **publish прошёл для пустой диаграммы** (probe-proc «Опубликован» → «no diagram to
  display» в модельере).

## 3. Решение (design-default)

**Построить read-only detail-вью экземпляра процесса `/processes/:instanceId` и направить
«Открыть» на него** (вместо `/audit`).

Экран показывает (всё из `GET /api/processes/:id` + проекций):
- шапка: имя процесса, статус (running/waiting/done/failed), запущен/обновлён;
- **текущие узлы** (включая concurrent-ветки T-0456) + прогресс done/total;
- **история переходов** (аудит инстанса — из той же проекции, что `/audit`, но
  отфильтрованной по `inst.id`);
- **связанные задачи инбокса** (userTask'и этого инстанса) со ссылкой в `/inbox`;
- **запись-источник** (`recordId`, если процесс стартовал по on_create/record_action) —
  ссылка на карточку записи;
- исполнители (human/agent/service).

Действия пользователя над процессом (согласовать/выполнить шаг) остаются в инбоксе —
detail-вью именно **смотровой** (как и решено для пул-задач: «осмотреть» отдельно от
«действовать»). Это согласовано с T-0552/inbox-направлением.

### 3.1 Вторичное (в scope задачи)

- **Рассинхрон «Нет активных процессов».** Привести верхнюю панель `/processes` и счётчик
  инстансов каталога дефов к одному источнику (`GET /api/processes`), либо честно
  переименовать панель, если «активные» = «с ожидающим действием».
- **Publish пустой диаграммы.** Добавить в lint/publish-гейт проверку непустой диаграммы
  (есть ≥1 узел кроме start/end, либо хотя бы start→end), чтобы `status='published'` не
  выдавался дефу без исполнимого графа (probe-proc).

## 4. Отклонённая альтернатива

**Убрать кнопку «Открыть», инстансами управлять только через инбокс.** Отклонено: видеть
состояние/историю запущенного процесса — table-stakes управления процессами; инбокс
показывает только «мою задачу», а не процесс целиком. (Если фаундер решит иначе — это
единственная развилка тут.)

## 5. Вне scope / non-goals

Действия над инстансом из detail-вью (cancel/retry/reassign — отдельно); правка идущего
процесса; миграция версий; глубокая Flowable-история. Публикация/песочница процессов —
T-0554/PD-25 (отдельно). Конкретный layout — за impl по kit.

## 6. Приёмка

- e2e на dev: из `/processes` «Открыть» по живому инстансу → попадаю на `/processes/:id`,
  вижу статус, текущий узел, историю, связанные задачи; для acceptance-demo — 2 задачи
  ведут в инбокс.
- верхняя панель и счётчик инстансов согласованы (одно число).
- publish дефа без узлов → 422 (не «Опубликован»).
