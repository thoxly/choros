# DEMO-1 · Проход первой демо (линейный ТЭЛ) — T-0218

> 5 экранов, ~5 минут. Один straight-through ТЭЛ-инстанс на демо-тенанте
> `showcase` (T-0141). Зритель видит: агент делает работу, но не может
> превысить полномочия; ошибается безопасно; права настраиваются без ИТ.
>
> Запуск исполнимой части: `npx tsx scripts/demo-tel-walkthrough.ts --dry-run`
> (offline-нарратив) или без `--dry-run` против живого dev-стенда (применяет
> showcase + additive demo actor-seed через публичный API).
>
> Демо-сделка (фикстура, НЕ реальные данные): закупка лицензий ПО, **5 500 000 ₽**
> (≥ порога ТЭЛ §1.4 = 5 млн ₽) → оба агентских слота срабатывают.

## S1 · Подача  (персона: `e-orlov` · экран: forms / FormViewer)

Инициатор подаёт заявку на закупку: **предмет** («Закупка лицензий ПО для
отдела ИТ»), **сумма** (5 500 000 ₽), **обоснование**. Видна серверная
валидация формы (form-js рантайм, E9).

→ Доказательство: сцена-подготовка (контекст для агентских шагов).

## S2 · Триаж  (персона: `a-intake` · экран: inbox / карточка) — **слот T-0219**

**Агент-классификатор** заполняет карточку: `category = it_expense`,
`budget_article = BUD-14`, `direction = buy`, и **выводит маршрут согласования**
из суммы/категории (сумма ≥ порога → нужен финконтролёр; ≥ 5 млн → обязателен
юротдел). Рядом — **reasoning-trace**: «категория = ИТ-расход; сумма 5,5 млн ≥
порога 5 млн → юр-предпроверка обязательна; статья BUD-14».

- Слот вход (consumes): `subject, amount, justification, requester`.
- Слот выход (produces): `category, budget_article, direction, route`.
- D-139: наружу — answer + безопасные метаданные; сырой reasoning — в audit.

→ Доказательство 1 (агент делает реальную работу) + reasoning-trace.

## S3 · Юр-предпроверка  (персона: legal-precheck agent · экран: inbox / карточка) — **слот T-0234**

Так как сумма ≥ 5 млн ₽, срабатывает **условный гейт** legal-precheck. Живой
мотор `runLegalPrecheck` (T-0233, уже смержен) принимает
`dealContext { amount: 5_500_000, kind: "it_expense", direction: "buy" }` +
тело договора и возвращает `PrecheckOutcome`: **red-flags** до юротдела
(напр. односторонний перенос оплаты §4.2, иностранная юрисдикция §11.3).

**Moat-момент:** показать попытку агента самому перейти «Согласовано» → **отказ
PDP**. Роль `role-intake-agent` НЕ имеет гранта `approve` — это структурно
(write-time), не постфактум. Агент довёл инстанс до согласующего шлюза, но
перешагнуть согласующего не может. (Это существующий PDP-deny, не новый
механизм.)

- Исходы (T-0220): proceed (red-flags готовы) / defer-to-human (сомнение →
  задача инбокса с doubt_reason) / fail-closed (вне грантов/ошибка → agent.blocked).
- Dormant-by-default: без live-провода — defer/fail-closed, не «агент додумал».

→ Доказательство 2 (moat) + reasoning-trace.

## S4 · Согласование  (персона: `e-larina` · экран: processes / карточка)

Финконтролёр (человек) жмёт **«Согласовать»** на карточке. Это **card action**
(T-0125/T-0200) = операция transition + проверка гранта `approve` + audit-событие.
Решение принимает человек — агент только подготовил.

→ Доказательство: card action + человек-гейт.

## S5 · Аудит-floor  (персона: `e-owner` · экран: audit)

Демонстратор открывает аудит: видна **вся цепочка** — шаг intake-агента, шаг
legal-precheck-агента, согласование человеком — tamper-evident. Reasoning
агентов лежит в `audit_event` под T-0139-маскированием (а не в теле ответа).

→ Доказательство: аудит-floor, доверие = воспроизводимая цепочка.

---

## Приёмочный критерий демо

«Незнакомый зритель за 5 минут понял: агент делает работу, но не может
превысить полномочия (S3 moat), ошибается безопасно (defer/fail-closed), а
вся цепочка прозрачна и неподделываема (S5)».

## Что НЕ в этом проходе (намеренно)

- Циклы доработки / отказ-ветки ТЭЛ (демо строго линейна).
- Сцены B (graceful degradation на 2-й заявке у порога) и D (бытовые права) —
  отдельные таски (T-0220..T-0223); этот сценарий оставляет им место.
- Реальный live-провод LLM для legal-precheck — deploy-time за фаундером (T-0234);
  day-1 проход использует детерминированную стаб-фикстуру / dormant→defer.
