# Спека: ИИ-ассистент и BYO (D5)

> Бот реально помогает строить и настраивать; клиент подключает свой LLM и правит поведение.
>
> Решения: [../product-decisions.md](../product-decisions.md) PD-5, PD-6, PD-16 (F1–F4).
> Видение: [../../CONCEPT.md](../../CONCEPT.md) §7. Статус: спека · 2026-06-22.

## 1. Зачем
LLM настоящая (DeepSeek по env-ключу), но: «собери CRM» уходит в read-only аналитика (не
строит); BYO не доведён (фабрика игнорит tenantId, ключ один на всех, UI нет); промт
захардкожен; треды без управления. Цель: бот = со-строитель на своём LLM клиента.

## 2. Проверенное состояние
- `src/adapters/openai-llm-port.ts` — реальный OpenAI-совместимый адаптер.
  `makeLlmPortFactory` (`server.ts:118-129`) принимает tenantId, но **игнорит** → единый env
  `DEEPSEEK_API_KEY`. `agent_card.llm_*` + secret-handle API (`src/http/secret-handle.ts`)
  есть, но ассистентом НЕ потребляются.
- Промты захардкожены: `assistant-analyst.ts:157-170`, `assistant-configurator.ts:575-583`.
- Конфигуратор: draft-only + грант authoring_draft (`assistant-configurator.ts:714-727`);
  для self-reg недоступен (см. D1 tenant-zero).
- Треды = append-only audit_event; title-константа «Новый разговор»; нет delete/rename/pin
  (`assistant.ts:674-724`, `screen-assistant.jsx`).

## 3. Дизайн

### 3.1 BYO per-tenant LLM (F1)
`llmPortFactory` читает **per-tenant** `agent_card.llm_*` (endpoint/model/secret-handle) через
secret-handle, вместо глобального env. Поддержка — **любой OpenAI-совместимый** endpoint
(base_url + model + ключ). Экран «Подключить LLM» (владелец/админ). Не настроено → честный
503 «подключите LLM», бот «спит» (бьётся с tenant-zero D1: агент есть, но дремлет).

### 3.2 Конфигуратор: что сам, что через человека (F2)
Бот пишет **только в DRAFT** (формы/поля/процессы/привязки/DMN). Публикация (promote) и
деструктив (удаление/переименование с потерей данных) — **всегда human-gated**. Доступ —
через грант authoring_draft (выдаётся овнеру в tenant-zero). Это уже доктрина — закрепить.

### 3.3 Редактируемый системный промт (F3)
Промты аналитика/конфигуратора вынести из TS в **per-tenant конфиг** (agent_card), **per-agent**
(у каждого свой). Править может **только владелец/админ** через UI. Дефолт — текущие промты.

### 3.4 UX тредов (F4)
- авто-title из первого сообщения (вместо константы);
- ленивое создание (не плодить пустые) или чистка пустых;
- «удалить» = **скрыть** (tombstone-событие / display-overlay), аудит-журнал неизменяем;
  rename/pin тем же механизмом.

## 4. Инвентарь работ → задачи
- BYO-вайринг + экран подключения → T-0382.
- Вынос промта + UI → T-0383.
- UX тредов → T-0384.
- Доступность конфигуратора реальному овнеру → зависит от D1 tenant-zero (T-0373).

## 5. Открытое к уточнению на импле
- Хранение per-agent промта (колонка agent_card vs отдельная таблица).
- Механика soft-delete треда поверх append-only журнала (tombstone vs mutable-проекция).

## 6. Последовательность
1) BYO (фабрика per-tenant + UI) — без этого бот «спит» →
2) промт-редактирование →
3) UX тредов. Конфигуратор «строит» завязан на D1 (грант) и D3 (формы/привязки) и D4
   (исполнение того, что бот наавторил).
