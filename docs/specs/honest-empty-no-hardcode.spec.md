# Спека: честный интерфейс без хардкода (D2)

> Интерфейс показывает РЕАЛЬНОЕ состояние тенанта, а не вшитую демку. Убрать весь хардкод
> на продуктовом пути; ввести гейт honest-empty.
>
> Решения: [../product-decisions.md](../product-decisions.md) PD-15 (F1–F3); расширяет D-056.
> Статус: спека · 2026-06-22.

## 1. Зачем
На чистом тенанте интерфейс врёт: предлагает зашитое «Линейное согласование», кнопки активны
без данных, палитра показывает нерабочие элементы, разделы доступа — моки. «Готово» в UI ≠
состояние данных. Цель: пустой выглядит пустым; всё на экране — настоящее.

## 2. Проверенные очаги хардкода/мока
- **Лаунч-процесса**: `screen-processes.jsx:40` хардкодит telLinear/«Линейное согласование»,
  предлагает на любом (даже чистом) тенанте (B17). Кнопка «Запустить процесс»
  (`shell.jsx:261`) всегда активна (B18).
- **Палитра модельера**: протекают default bpmn-js элементы без системного смысла
  (dataStore, lanes, timer, subProcess) (B13).
- **Доступ**: `ra-criticality.jsx`, `ra-sod.jsx` — чистый мок; `screen-org.jsx:56-124` — 4
  захардкоженных сотрудника + dummy autonomy/LLM; грант-редактор на одной seed-роли.
- **Треды ассистента**: демо/пустые висят; имя-константа.
- **Навигация**: демо-бейджи; «Ассистент» как demo при готовом бэкенде.
- Бэкенд по многим путям УЖЕ честен (например `/api/process-catalog` чистому тенанту отдаёт
  пусто) — врёт в основном фронт.

## 3. Дизайн

### 3.1 Старт нового кабинета (F1)
Пусто + **кнопка «Загрузить пример»** (механизм импорта готового шаблона решения).
**Сами шаблоны-примеры пока НЕ делаем** — кнопка ведёт к «скоро» / пустому списку; реальные
шаблоны (CRM, согласование) — позже. Точки входа в рантайме — только реальные бизнес-действия
(создать объект / record_action / инбокс), generic-лаунчер убрать (см. D-?? T-0374).

### 3.2 Палитра модельера (F2)
Показывать **только реально исполняемое**: шаг-человек (userTask), шаг-агент, шаг-сервис,
старт/конец, ветвление (gateway), связи (flow). Нерабочие default bpmn-js (dataStore, lanes,
timer, subProcess, manual/businessRule/script task) — **убрать из палитры** (не серым-метить).

### 3.3 Состояние вместо демо
Каждый продуктовый экран рендерит реальное состояние тенанта: пустые состояния честные,
кнопки дизейблятся при отсутствии данных (B18), разделы доступа — на живых данных (см. D6),
треды — реальные (см. D5), демо-бейджи снять где бэкенд готов.

### 3.4 Гейт honest-empty (F3)
Автопроверка (расширение honest-gate D-056): на чистом тенанте продуктовые экраны не
показывают ни одной зашитой бизнес-сущности; нет enabled-кнопок, ведущих в никуда. Зелёный
гейт = «фронт отражает данные, не демку». Гонять на деплое (deploy-acceptance).

## 4. Инвентарь работ → задачи
- Убрать generic telLinear-лаунчер + дизейбл кнопок → T-0374.
- honest-empty (чистка хардкода фронта + палитра B13 + гейт) → T-0375.
- «Загрузить пример» (механизм, без самих шаблонов) → часть T-0375 / T-0306.
- Живой доступ вместо моков → D6 (T-0385/0386/0387).
- UX тредов → D5 (T-0384).

## 5. Последовательность
1) Убрать лаунч-хардкод + палитра + дизейбл кнопок (видимое враньё уходит) →
2) honest-empty гейт (чтобы не протекало впредь) →
3) «Загрузить пример» (механизм). Очаги в доступе/тредах закрываются в D5/D6.
