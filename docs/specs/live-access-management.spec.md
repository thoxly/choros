# Спека: живое управление доступом (D6)

> Роли/права/SoD/критичность — из интерфейса на живых данных, а не макетами. Движок прав уже
> реальный — довести интерфейс и доделать SoD.
>
> Решения: [../product-decisions.md](../product-decisions.md) PD-11, PD-17 (F1–F3).
> Статус: спека · 2026-06-22.

## 1. Зачем
~60% реально, ~40% мок. Грант-модель/dual-control/audit/org-CRUD — живые. Но грант-редактор
на одной seed-роли, вкладки «Критичность»/«SoD» — чистый мок, карточки исполнителей —
4 хардкод-сотрудника. Цель: всё на живых данных + понятно обычному человеку.

## 2. Проверенное состояние
- **Реально:** grants-dao, dual-control (`role-criticality.ts`+`dual-control.ts`+двухфазный
  `POST /api/grants`, миграция 031), audit, org-CRUD, пресеты прав (ra-data PRESETS).
- **SoD:** логика (`sod.ts`)+схема (миграция 027)+интеграция в резолвер (step 3.6) ЕСТЬ, но
  Postgres-DAO отложен (T-0053), write-эндпоинтов нет, UI мок (`ra-sod.jsx`).
- **Мок UI:** грант-редактор на хардкод `EDITOR_ROLE_ID`; `ra-criticality.jsx`; `screen-org.jsx:56-124`
  4 захардкоженных сотрудника + dummy autonomy/LLM; «Запросить изменение» — мёртвая кнопка.

## 3. Дизайн

### 3.1 Две аудитории прав (F1)
- **Владелец/админ:** полноценный редактор грантов (продвинутый), с **динамическим выбором
  роли** (убрать хардкод EDITOR_ROLE_ID), на живых данных. Пресеты-на-роль человеческим
  языком — дефолтный режим, «сырой» грант-редактор — «для продвинутых».
- **Обычный пользователь:** read-only **«мои права на человеческом языке»** («согласует счета
  до X», «только смотрит») — видит, не редактирует.

### 3.2 Критичность + SoD (F2)
- Критичное изменение прав → **всегда** второй подтверждающий (dual-control, бэкенд готов),
  **не отключаемо**. Подключить вкладку «Критичность» к живым pending-изменениям +
  two-phase confirm из UI.
- **SoD:** доделать Postgres-DAO (T-0053) + write-эндпоинты CRUD правил + админ-UI; правила
  («инициатор ≠ согласующий») задаёт админ; нарушение **блокируется при назначении**
  (резолвер step 3.6 уже умеет, нужна persistence).

### 3.3 Карточка исполнителя (F3)
Реальные данные вместо макета: роли, права; для **агента** — модель, бюджет, граница
автономии (autonomy_threshold), последние действия из аудита. Убрать 4 хардкод-сотрудника.

## 4. Инвентарь работ → задачи
- Вкладка критичности на живые эндпоинты → T-0385.
- SoD: DAO + эндпоинты + UI → T-0386.
- Живой доступ: динамич. выбор роли + read-only человеческий вид прав + реальные карточки
  исполнителей + оживить «Запросить изменение» → T-0387.

## 5. Открытое к уточнению на импле
- Маппинг гранты → человеческие формулировки (расширить пресеты до «объяснялки прав»).
- SoD DAO: запросы constraintsFor / effectiveAssignmentsOf (зеркало T-0019).

## 6. Последовательность
1) Динамич. выбор роли + человеческий вид прав (убрать главный мок-затык) →
2) вкладка критичности на живое →
3) SoD доделать (DAO+эндпоинты+UI). Карточки исполнителей — попутно с (1).
