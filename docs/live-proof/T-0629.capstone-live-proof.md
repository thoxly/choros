## ВЕРДИКТ (предварительный): ⛔ P0 — столп 1 (канвас) мёртв для 7 типов полей

### P0-1: FormDesigner не может СОХРАНИТЬ форму, если набор полей содержит money/date-time/email/url/person/multi-select/file

**Экран:** Конструктор форм (`/forms`), вкладка «Конструктор (drag-n-drop)».
**Действие:** приложение crm → набор полей «Сделка» (5 полей: title/string, amount/**money**, close_date/date, stage/select, positions/collection). Канвас авто-собрал форму.
**Что сломано:** канвас показывает «**Ошибки авторинга: Узел «Поле» нельзя привязать к полю «amount» (тип «money»)**». Кнопка «Сохранить раскладку» **disabled** пока есть ошибка авторинга (`disabled={!validation.ok ...}`, FormDesigner.jsx:1267). Виджет-пикер в инспекторе для money-поля **НЕ рендерится** (нет совместимых виджетов → `return null`, FormDesigner.jsx:476-478) → починить руками НЕЛЬЗЯ.

**Корень (код, dev tip):**
- `web/src/forms/widget-registry.js` `WIDGET_COMPAT_TABLE` содержит ключи: string, text, textarea, number, integer, boolean, select, enum, date, relation, collection, computed.
- `web/src/screens/apps-schema.js` `parseRecordSchema` при чтении record_schema обратно ЭМИТИТ типы: **money** (x-money), **datetime**, **email**, **url**, **person** (x-person), **multi-select**, **file** — которых НЕТ в WIDGET_COMPAT_TABLE.
- `nodeForField` (form-document.js:229) → `defaultWidgetForType('money')` → `WIDGET_COMPAT['money']` undefined → fallback `'text'` (form-document.js:164).
- Узел получается `{type:'field', fieldKey:'amount', widget:'text'}`.
- `validateDocument` → `isWidgetCompatible('money','text')` → `WIDGET_COMPAT['money']` undefined → **false** → authoring error → Save заблокирован.

**Масштаб:** ломает 7 из 16 типов полей. money — базовое поле CRM «Сделка» (задача прямо называет «число/деньги»). Любой набор полей с суммой/датавремя/почтой/URL/сотрудником/мультивыбором/файлом → форму НЕЛЬЗЯ собрать и сохранить через канвас.

**Фикс:** добавить в `WIDGET_COMPAT_TABLE` записи для money/datetime/email/url/person/multi-select/file (например money:['money','number'], datetime:['datetime','date'], email:['email','text'], url:['url','text'], person:['person'], 'multi-select':['multi-select'], file:['file']) + соответствующие виджеты в реестр. `defaultWidgetForType` fallback на 'text' сам по себе баг — производит виджет, гарантированно проваливающий валидатор, который гейтит сохранение.

**Замечание:** превью СПРАВА при этом рендерит money-поле корректно (₽), date — datepicker, select — dropdown, collection — таблицу (Количество/Товар). Т.е. рендерер работает; ломается именно авторинг-валидатор+save-гейт. Зелёные дети эпика (17/17) не поймали, потому что юнит-тесты гоняют компат-совместимые фикстуры, а не money-поле из реального набора → классика D-064.

## Столп 2 — AI emit_form по текстовому описанию: ⛔ P0-2 (мёртв в тенанте владельца) / НЕ ДОКАЗАН живьём

**Экран:** Ассистент (`/assistant`) в тенанте `final-demo`.
**Что сломано:** «**Ассистент пока не может отвечать — Не подключён LLM-ключ**». Композер сообщения НЕ рендерится вообще (ни в новом разговоре, ни в существующем). `GET /api/llm-connections` → `{"connections":[]}` — в тенанте `final-demo` НОЛЬ LLM-подключений.

**Расследование (БД, все тенанты):** живые LLM-подключения с секретом есть ТОЛЬКО в тенантах `dev` (a0000000-…, «T0586 DeepSeek», «T0586 DS v2») и `ooo-akson` (c7a70702-…, «DeepSeek (прод)»). В `final-demo` их нет (был — тред `ffec3650` от 2026-06-22 содержит РЕАЛЬНЫЙ ответ ассистента на «тест», значит подключение когда-то было и пропало — вероятно realm/tenant-переимпорт снёс).

**Почему НЕ доказан emit_form:**
1. В тенанте, куда попадает рядовой владелец (`final-demo`), ассистент МЁРТВ (нет LLM-ключа).
2. Подключить ключ = вставить секретный API-ключ → это запрещённое для live-proof-инженера действие (нельзя вводить секреты/креды).
3. Переключиться в тенант с живым LLM (`dev`/`ooo-akson`) = вход по паролю другим юзером → тоже запрещённое действие (аутентификация паролем).
4. Аудит (`choros.audit_event`) по всем тенантам: только `assistant.message`/`assistant.thread` (чат-реплики), НИ ОДНОГО authoring-события от ассистента (emit_form / registry_def.create / application.create через via=assistant). Т.е. позитивного следа, что emit_form-инструмент когда-либо СОБИРАЛ форму на этом стенде, НЕТ (при этом authoring-аудит вообще скудный — только application.deleted).

**Вывод по столпу 2:** capability emit_form в коде есть (`src/core/assistant-configurator.ts`: TOOL_EMIT_FORM, create_application, edit_jsonschema — пишут те же таблицы, что визуальный конструктор), но **живьём по текстовому описанию форма НЕ собрана**: путь ассистента заблокирован в тенанте владельца отсутствием LLM-ключа, а обойти блок способами, доступными live-proof-инженеру (без ввода секретов/паролей), нельзя. Это P0 для «столпа 5 (настройка через ИИ)» в приземлении рядового владельца: свежий тенант получает ассистента без LLM и без пути его включить без секрета — ассистент из коробки нем.

**Что нужно, чтобы закрыть столп 2 GREEN:** прогнать emit_form в тенанте с живым deepseek (dev/ooo-akson) под его владельцем, задав текст «собери форму заявки на отпуск с датами и причиной», и проверить, что ассистент вызвал create_application/emit_form и создал registry_def, который открывается и пишет запись. Требует владельца live-LLM-тенанта (вне доступа этой сессии) ИЛИ подключения LLM-ключа фаундером.
