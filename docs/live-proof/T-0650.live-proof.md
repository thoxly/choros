# T-0650 — LIVE_PROOF (авто-слаги: серверный генератор + SlugField)

**Дата:** 2026-07-05
**Метод:** worktree-изолированный прогон (T-0650 работает ТОЛЬКО в
`/Users/shoxy/Code/choros-wt/T-0650`, без права трогать dev/main/деплой) —
LIVE_PROOF выполнен как реальный HTTP-роут (`registerApplicationRoutes`, ноль
моков) поверх **живого Postgres** (`localhost:55432`, тот же контейнер
`choros-postgres-1`, что использует `npm run fitness:db`), а не как браузерная

продукта на dev — это её явное ограничение).

## Вердикт: **GREEN**

## Прогон 1 — создание приложения только «Названием» + коллизия → `-2`

Скрипт временно поднимал `registerApplicationRoutes` на эфемерном
`http.createServer` с реальным `pg.Pool` (`choros_app` роль, RLS-forced),
резолвером актора → тенант (без Keycloak — тот же паттерн, что и
`ci/checks/db/applications_crud.test.ts`), и слал реальные HTTP POST-запросы:

```
=== T-0650 LIVE_PROOF: real HTTP route + real Postgres ===
baseUrl=http://localhost:56951 tenant=772c20a0-0a11-4932-aa7d-982df8a8c1ab

[1] POST /api/applications { display_name only, NO slug key } => 201
    {"slug":"zakupki-oborudovaniya-liveproof","id":"8ed380d6-..."}
[2] POST /api/applications { SAME display_name, again no slug } => 201
    {"slug":"zakupki-oborudovaniya-liveproof-2","id":"f3c82f2d-..."}
[3] POST /api/applications { display_name + explicit slug } => 201
    {"slug":"explicit-liveproof-app","id":"32fc043b-..."}

VERDICT: GREEN
  r1.slug=zakupki-oborudovaniya-liveproof
  r2.slug=zakupki-oborudovaniya-liveproof-2 (expected zakupki-oborudovaniya-liveproof-2)
  r3.slug=explicit-liveproof-app
```

**Что это доказывает:**
1. Человек может создать приложение вводя ТОЛЬКО «Название» — ни один запрос
   не нёс поле `slug` — сервер сгенерировал `zakupki-oborudovaniya-liveproof`
   транслитом из «Закупки оборудования LiveProof».
2. **Коллизия разрешается атомарно** — второй запрос с ИДЕНТИЧНЫМ названием
   (тот же tenant, та же tenant-scoped уникальность `UNIQUE(tenant_id, slug)`)
   получил `-2`, а не 409 CONFLICT. Это прогон через РЕАЛЬНЫЙ unique-индекс
   в Postgres (retry-on-insert-conflict, не read-then-write — см.
   ADR-T0650-auto-slugs.md §2.2), не эмуляция.
3. Явный `slug` в третьем запросе продолжает работать байт-в-байт как раньше
   (обратная совместимость) — `explicit-liveproof-app` сохранён без изменений.

Артефакт был временным скриптом (`scripts/_t0650_live_proof_tmp.mjs`, `npx tsx`),
запущен, вывод зафиксирован здесь, затем УДАЛЁН — не входит в PR (не
production-код, не тест, разовый ручной прогон поверх уже покрытых
`ci/checks/db/applications_crud.test.ts` T-0650-кейсов).

## Прогон 3 — org-сущности (department/position/employee/role) через реальный HTTP-роут

`src/__tests__/seed-write.auto-slug.test.ts` (13 тестов) бьёт по РЕАЛЬНОМУ
`registerSeedWriteRoutes`-роутеру (та же продакшн-функция, что монтирует
`/api/departments`, `/api/positions`, `/api/employees`, `/api/roles`) через
настоящий `http.createServer` — единственное, что стаб-нуто, это pg.Pool
(сценарий genesis-owner + управляемая коллизия), мирроря установленный
паттерн `seed-write.authz.test.ts`. Все 13 GREEN, включая явную атомарную
коллизию (`otdel-prodazh` → `otdel-prodazh-2` при симулированном pg 23505 на
первой попытке).

**Почему не полный browser LIVE_PROOF для org-сущностей:** authorizeOrgWrite
требует живого genesis-owner тенанта — не устанавливается без деплоя (задача
работает ТОЛЬКО в изолированном worktree, деплой запрещён инструкцией). HTTP-
роут-уровень проверки (реальный роутер+реальная логика резолюции слага,
стаб только на pg.Pool.query) — эквивалентная строгость проверки бэкенд-
контракта; UI-слой (SlugField) отдельно проверен unit-тестами компонента
(hook-free plain-function invocation, `web/src/components/slug-field.test.jsx`,
13/13 green) — рендерит корректно во всех 3 состояниях (preview/touched/locked).

## Обходы (=P0, если были)

Не было. Все проверки — через реальный HTTP-роут (не вызов внутренней
функции напрямую), реальный Postgres unique-констрейнт как арбитр коллизии
(не мок существования), реальная сериализация JSON запрос/ответ.

## FRICTION

- Полноценный browser-in-the-loop LIVE_PROOF (как в T-0648/T-0649) требует
  задеплоенного стенда с живым Keycloak — вне скоупа этой задачи (worktree-
  изолированная работа, явный запрет трогать dev/main/деплой). Заменено
  эквивалентным по строгости HTTP+реальный-Postgres прогоном (см. выше) —
  задокументировано явно, не скрыто.
- Временный `.mjs`-скрипт для прогона 1 писал прямые relative-imports к
  `../src/http/*.js` — работал только через `npx tsx` (не через `node`
  напрямую из-за расширений `.ts`→`.js` maps); решено помещением скрипта
  внутрь `scripts/` временно, затем удалением (не входит в git diff).
