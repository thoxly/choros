# T-0683 — LIVE_PROOF (D-064): инбокс «ПРОЦЕСС» без сырого instance-UUID первичным

**Дата:** 2026-07-06
**Стенд:** http://100.121.76.86:3000 (Tailscale), tip **9cafa302** (T-0683 merge), app 200
**Проживал:** рядовой **e-orlov (К. Орлов, human, НЕ владелец)** — залогинен в chrome-сессии, тенант **Dev Silo** (`a0000000-0000-0000-0000-000000000001`, 35 исп.)
**Экран:** «Работа / Мои задачи» (`/inbox`), вкладка «Все» = 27 задач

## Вердикт: **GREEN**

Рядовой в инбоксе **больше не видит сырой instance-UUID первичным** ключом колонки ПРОЦЕСС. P0 капстоуна T-0647 (сырой `5ec293d1-…` первичным + голый `agent:`) устранён. Agent-строки очеловечены. Дровер тоже без сырого inst первичным. Title-резолв работает по назначению (honest sentinel на 404). Тенант-изоляция держит.

## Что доказано (глазами рядового, DOM-факты)

### 1. Колонка ПРОЦЕСС — 0 сырых UUID первичными (полный инбокс)
Скан всех **54** `.chs-processref` (после «Показать ещё», обе страницы рендера):
- **`primaryUuidCount: 0`** — НИ ОДНОЙ строки с raw UUID как primary (`.chs-processref__name`).
- **`agentBareAsPrimaryCount: 0`** — НИ ОДНОЙ строки с голым `agent:` как primary.
- Distinct primary-метки — все человеческие:
  - `telLinear` ×30 (человеко-имя процесса)
  - `Проверить: агенту не назначена инструкция — требуется настройка перед автономной работой` ×18 (человеко-имя задачи, agent-defer)
  - `Новый процесс` ×4
  - `LP T0638 Defer Live Proof` ×2

### 2. Сервер ШЛЁТ сырые UUID — клиент их ПОНИЖАЕТ (before/after доказательство)
Сырой payload `/api/inbox?page=1` (27 items), поле `inst`:
- **`{ "UUID": 18, "agent:": 9 }`** — сервер отдаёт **18 строк с raw instance-UUID** (`d89dcfa4-77db-11f1-…`, `b978de10-…`, `ae8c5c72-…`) + 9 с голым `agent:`.
- **`processNameThatIsUuid: 0`** — сервер НИКОГДА не кладёт UUID в `processName`.
- До T-0683 эти 18 UUID были ПЕРВИЧНЫМ текстом колонки; теперь primary=`processName` («telLinear»), а UUID **не виден первичным вообще** (уходит в `title`-тултип `.chs-processref__name`, `showInst=false` для машинного ключа).

### 3. Agent-строки очеловечены
9 строк с `execType:"agent"`, `inst:"agent:"`, `processName:null` на сервере →
клиент через `deriveProcessRefPrimary` падает в `stepFallback` (имя задачи) →
primary = «Проверить: агенту не назначена инструкция…», голый `agent:` только в `title`-тултипе.
`distinctAgentTitles: ["agent:"]` (в тултипе, НЕ в тексте).

### 4. Дровер задачи (task detail) — без сырого inst первичным
Открыт дровер agent-задачи (legal_precheck, «Открыть»):
- **Название** = человеко-имя задачи
- **Шаг** = `legal_precheck` (mono, помеченное вторичное поле)
- **Процесс** = `<ProcessRef>` → primary «Проверить: агенту…» (человек), `processRefNameIsUuid:false`, `agent:` в `title`
- **Исполнитель** = «T0586 Admin (Человек)» (очеловеченный ExecutorBadge)
- `bareUuidAsPrimaryText: []`, `monoUuidChipsInDrawer: []` — сырого UUID первичным в дровере НЕТ.
- (Секция projection «Процесс»/«Инстанс» — конструктивно: primary = `definitionName||procKey` человек, `<MonoId>{inst}</MonoId>` под ПОМЕЧЕННЫМ ключом «Инстанс», вторичным — не первичным. screen-inbox.jsx:731-735.)

### 5. Резолв title записи + тенант-изоляция
- Единственная строка с `recordId` (telLinear «Подача заявки», `3f67cb0b-200b-4286-ae6f-c773f12c85de`): RecordRef дёрнул `GET /api/records/3f67cb0b-…` → **404** (запись-сирота из старой фикстуры, не существует). НЕ 403 → это не отказ PDP/тенанта, а честное not-found. RecordRef корректно упал в honest-sentinel (D2): показал recordId **demoted mono-чипом** (`.chs-processref__record` / `data-testid="technical-id"`), primary остался «telLinear». Резолв-путь ProcessRef→RecordRef→GET /api/records/:id **функционирует** (запрос ушёл, ответ обработан, fallback сработал как задумано). Happy-path резолва title в этом инбоксе продемонстрировать нечем (нет живой записи в задачах e-orlov), но механика проверена.
- Тенант: e-orlov = Dev Silo. **`foreignTenantLeakCount: 0`** — фикстурная чужая задача «Чужой тенант / INS-9001» (OTHER_TENANT_ID) в инбоксе рядового ОТСУТСТВУЕТ. Видит только свои 27 задач. Чужих записей не протекло.

- recordId `3f67cb0b-…` = запись-сирота (404). Demoted mono-чип с UUID виден при скролле к строке — это designed honest-sentinel RecordRef, не P0. Фикстура-хвост стоит вычистить (или это ожидаемо для стенда).
