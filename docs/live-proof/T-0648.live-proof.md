## 1. Инбокс («Мои задачи», /inbox) — GREEN

Скриншот: список задач `/inbox`. Колонка «ИСПОЛНИТЕЛЬ» показывает:
- Назначенные задачи → чип **«T0586 Admin»** с глифом-точкой (человек), не UUID.
- Незанятые задачи → честный статус **«в пуле»** (не UUID, корректно — исполнителя ещё нет).

Открыт детальный «Задача»-дровер по назначенной задаче: `Исполнитель: T0586 Admin (Человек)` — имя + явная типовая подпись. GREEN.

Найдено (не блокер для этого пункта, но заметка): у части задач (`legal_precheck`) поле «Инстанс» рендерит буквально `agent:` — это раздельный факт (см. FRICTION ниже), не относится к исполнителю/имени.

## 2. Карточка инстанса процесса (история шагов) — RED

Открыт `/processes/:id` для инстанса `b978de10-...` (в процессе) и `29bb45ad-7858-...` (завершён, 2/2 шагов, богатая история).

**Проблема А (шаги не по BPMN-узлам):** «История переходов» содержит СЫРЫЕ `sequenceFlow`-id вместо человекочитаемых имён шагов:
```
sf-start-fin      sequenceFlow → ...
sf-timer-esc      sequenceFlow → ...
sf-fin-converge   sequenceFlow → ...
sf-converge-end   sequenceFlow → ...
```
Это ровно тот антипаттерн, который задача явно требовала не допустить («не sf-start-submit») — только конкретные значения другие (`sf-start-fin` и т.д. вместо `sf-start-submit`), суть та же: голый BPMN-технический id в основном тексте истории.

**Проблема Б (completedBy отсутствует полностью):** ни на одном шаге истории (userTask/boundaryEvent/exclusiveGateway/sequenceFlow) НЕ отображается, КТО завершил шаг — ни имя, ни глиф, ни UUID. Единственное поле-исполнитель на странице — агрегатный правый блок «ИСПОЛНИТЕЛИ: Человек» (без имени, один на весь инстанс). Формулировка задачи требовала: «completedBy — ИМЯ + правильный глиф; если шаг завершал АГЕНТ — глиф агента + «(агент)»» — эта информация в UI просто не рендерится вообще, ни как объект, ни как UUID.

Проверено на: `b978de10-6c9c-11f1-92f1-b6b51735389e` (в процессе, шаги: Начало/sf-start-submit... — тут корректно "Подача заявки" как имя, но параллельно sf-start-submit тоже сырой) и `29bb45ad-7858-11f1-abdf-aaa9cc4b0546` (завершён, полная история с эскалацией таймера).

## 3. Аудит (/audit, «Журнал аудита») — GREEN

Субъект действия (`record.create` → id записи) остаётся сырым UUID в основном тексте столбца действия — это отдельное поле (объект действия, не актор), в рамках анти-UUID для АКТОРА не является нарушением по формулировке задачи («сырой id только в тултипе» относится к акторам). GREEN.

## FINDINGS (для фиксации, не все относятся к T-0648 напрямую)

1. **P0/RED — /rights/trail крашится React#31** (см. §4). Прямое противоречие заявлению `rights_trail_fix` в pr-handoff. Заведена фоновая задача на дорасследование.
2. **RED — история шагов инстанса не показывает completedBy вообще** (см. §2, проблема Б) — ни имени, ни UUID, поле просто отсутствует в этой карточке.
3. **RED — сырые `sf-*` sequenceFlow id в истории шагов** (см. §2, проблема А) — тот же класс проблемы, который задача просила исключить, просто на других конкретных именах (`sf-start-fin`, `sf-timer-esc`, `sf-fin-converge`, `sf-converge-end`).
4. **Минор — «Инстанс: agent:»** в инбоксе для процесса `legal_precheck`: поле рендерит буквально строку `agent:` (похоже на шаблон `agent: ${имя}` с пустым именем) вместо человекочитаемого названия процесса/инстанса. Не проверялось глубоко (не в скоупе анти-UUID-актора — это поле процесса, не актора), но выглядит как утечка технической строки.
5. **Минор — задачи `legal_precheck` называются буквально «Проверить: no published instruction for agent»** — похоже на debug/placeholder-текст задачи, оставшийся от предыдущей сессии тестирования (не относится к T-0648).
