## P0-находка слоем глубже (→ follow-up задача, НЕ дефект T-0669)
Пикер «Набор полей» (registry_def) для уже отфильтрованного приложения САМ не фильтруется до реестра из `process_app_binding.target_registry_slug`. Для приложения с >1 registry_def (telLinear→«Согласование заявок (ТЭЛ)» имеет «Заявки»/purchases и «Согласование»/soglasovanie, target=soglasovanie): выбор легитимного-но-неправильного «Заявки» → POST /api/forms/binding → **409 WRONG_FLOOR** (те же ключи отсутствуют в live record_schema); выбор «Согласование» → 201. Тот же класс непрозрачного 409, что T-0669 закрыл на уровне процесс↔приложение — но слоем ниже (приложение↔registry_def). Воспроизведено детерминированно 2×. T-0669 своё обещание (процесс↔приложение) выполнил; registry_def-пикер вне его скоупа.

Обходов не потребовалось. Скриншоты: scratchpad w5 t0669-proof/ (20/21/30/31/40/50/60/61).
