## Вердикт: **GREEN**

Сканирование всех 42 отрендеренных строк / 84 ActorChip-бейджей: **0 сырых-UUID первичным
текстом** в идентификаторных колонках. Сырой UUID присутствует ТОЛЬКО в тултипе (demoted).
Резолвимые акторы = имена+глиф (не сломаны). Слаги ролей целы.

## Сцена (воспроизведена — в живой БД leak-UUID отсутствовали)

Таблица журнала = `choros.audit_event` (типы grant/assignment .create/.revoke). Колонки:
`actor` (КТО ВЫДАЛ), `subject` (КОМУ), `confirmed_by` (КТО ПОДТВЕРДИЛ). Резолвер
`batchResolveActors` матчит по `employee.slug` ИЛИ `employee.id`; промах → нет
`*Resolved` поля → фронт-фоллбэк отдаёт сырой id как `name` в ActorChip (условие утечки).
