## Контракт (из кода, до проверки)
- Роут: `POST /api/applications`. Обязательное поле — **`display_name`** (не `name`), непустое. `slug` — ОПЦИОНАЛЬНОЕ.
- Нет slug → `createApplication` идёт через `insertWithUniqueSlugRetry(displayName, ...)` (src/core/slug-generator.ts): base → base-2 … base-10 → base-<uuid8>, арбитр = реальный UNIQUE-констрейнт на INSERT (23505), гонки нет.
- Явный slug → одиночный INSERT; коллизия → 409; невалидный по `SLUG_RE=/^[a-z0-9][a-z0-9-]{0,63}$/` → 400.
- Fallback пустого/символ-онли имени: генератор → `item` (GENERIC_SLUG_FALLBACK). Process-key путь коэрсит `item`→`process` на своей границе (slugify-process-key.ts, F1-контракт) — юнит-тест мутационно-красный.

## Шире кейса (D-064)
| Кейс | HTTP | Результат |
|---|---|---|
| `{"display_name":"!!!"}` (символ-онли) | **201** | slug=**`item`** — честный generic-fallback для applications (НЕ пустой, НЕ крэш). id=5c7cb3e6-… |
| `{"display_name":"   "}` (whitespace-only) | **400** | `{"code":"VALIDATION","message":"display_name must be a non-empty string"}` — guard цел |

Про F1 «process»: applications-путь даёт `item` (верно). Fallback-слово `process` — это КОЭРСИЯ на границе process-key (slugify-process-key.ts), покрыта юнит-тестом мутационно-красным; live-публикация BPMN вне scope слаг-проофа (LLM-зависима). Контракт `item`(generic) / `process`(process-key) подтверждён в коде.

## B. Деплойнутый SlugField-UI (браузер, залогинен final-demo@example.com, тенант «Финал Демо»)

**B.4 — живой превью слага (без ручного машинного имени).** Экран Конструктор → Приложения → «Создать приложение». Модалка при пустом имени показывает СЛАГ-секцию в untouched-состоянии: «слаг сгенерируется автоматически из названия» + кнопка «изменить» (=компонент SlugField, default-режим). Ввод НАЗВАНИЕ=«Проверка слага лайв» (кириллица) → под полем ЖИВО обновилось:
> будет создан как **`proverka-slaga-layv`**

Транслит на лету (Проверка→proverka, слага→slaga, лайв→layv), ручной машинный ввод НЕ требовался.

**B.5 — сохранение → сущность с показанным slug.** Клик «Создать» → модалка закрылась, счётчик 1→2, новая строка в списке:
- ПРИЛОЖЕНИЕ: «Проверка слага лайв» · СЛАГ: **`proverka-slaga-layv`** · DRAFT · 2026-07-05 21:54.

Slug сущности = ровно превью до сохранения.

**B.6 — коллизия в UI (UX F-1 fix).**
- Авто-путь: повтор ТОГО ЖЕ имени «Проверка слага лайв» → сервер сам разрулил → создалось `proverka-slaga-layv-2` (счётчик 2→3). Авто-slug никогда не отдаёт 409 — пользователь бесшовно получает -2 (лучше тупика).
- Явный путь (единственный, где UI ловит 409): клик «изменить» перевёл СЛАГ в РЕДАКТИРУЕМЫЙ input (сид `yavnyy-slag-kolliziya`, hint «строчные латинские, цифры, дефис · 1–64» = touched-режим). Заменил slug на существующий `crm`, «Создать» → модалка ОСТАЛАСЬ открытой, поле СЛАГ — **редактируемый input с красной рамкой + inline-ошибка «Слаг уже занят в этом тенанте»**. НЕ тупик preview-режима; сущность-фантом не создана (счётчик остался 3). F-1 fix подтверждён.
