## Доказательная последовательность (money, набор «Сделка»)

### 1. Money привязан + кнопка активна (client-гейт T-0678 = V-WIDGET + V-CONTRACT)
Открыт Конструктор форм → ПРИЛОЖЕНИЕ=`crm` → НАБОР ПОЛЕЙ=`Сделка`. Канвас построил все поля как **Поле/Таблица**-ноды, включая **Сумма → ↳amount (money)**. Программная проверка DOM:
```
{ "hasAuthoringError": false, "hasMoneyError": false /* «нельзя привязать» ОТСУТСТВУЕТ */ }
```
Палитра явно типизирует ноду: кнопка **«Поле «amount» (money)»**. До фикса тут была бы «Ошибки авторинга: …нельзя привязать к money» и `disabled`.

### 2. POST 201 через реальную кнопку «Сохранить раскладку»
Гейт кнопки: `disabled = !validation.ok || saving || !(step)`. `validation.ok===true` (money проходит V-WIDGET+V-CONTRACT). Для сатисфакции ортогонального гейта шага (T-0665, не относится к T-0678) через реальные эндпоинты был опубликован процесс `lp-t-0678-forma-sdelki` (POST /api/process-defs → 201, /publish → 200, deploy в Flowable). Затем сатисфакция серверного гейта T-0520 (см. ниже).

Захваченное реальное тело POST кнопки (money-нода в layout):
```json
{"process_key":"lp-t-0678-forma-sdelki","form_key":"Проверка сделки","layout":{"schemaVersion":1,
 "root":{"type":"section","children":[
   {"type":"field","fieldKey":"title","widget":"text"},
   {"type":"field","fieldKey":"amount","label":"Сумма","widget":"money"},   ← MONEY
   {"type":"field","fieldKey":"close_date","widget":"date"},
   {"type":"field","fieldKey":"stage","widget":"select"}]}}}
```
**Ответ: POST /api/forms/binding → 201.** UI показал зелёное **«Сохранено.»**

### 3. Подтверждение в БД (`choros.form_binding`)
```
process_key=lp-t-0678-forma-sdelki | form_key=Проверка сделки | version=1
field_keys=["title","amount","close_date","stage"]
has_money_node ( children @> [{fieldKey:amount, widget:money}] ) = TRUE
```

### 4. Round-trip + рендер (сохранённая форма грузится и рисуется)
GET `/api/forms/binding?processKey=lp-t-0678-forma-sdelki&stepKey=Проверка сделки` → **200**, layout вернулся с money-нодой:
`{"id":"f2","type":"field","label":"Сумма","widget":"money","fieldKey":"amount"}`.
Превью (= FormDocumentRenderer, исполнительский рендер) резолвит контролы по ТИПУ:
`{ rubleSignPresent:true (MoneyInput ₽), dateInputCount:1 (DateInput), selectCount>0 }`.

## Побочная находка (НЕ T-0678, ортогональна): серверный гейт T-0520 `WRONG_FLOOR`

При первом сохранении POST вернул **409 WRONG_FLOOR** (не money-ошибка). Изоляция: **тот же 409 для формы ТОЛЬКО с text-полем** (без money вообще) → гейт **field-type-agnostic**, это T-0520 (`classifyLayoutSave`/`resolveLiveSchemaFieldKeys`), не T-0678.

Причины по цепочке (все не про money):
1. `no registry binding` — свежий процесс не привязан к приложению → создан `process_app_binding` (POST /api/process-app-bindings, 201).
2. Резолвер тянет реестр по **дефолтному slug `soglasovanie`** (`resolveDefaultStepResultSlug`, env `CHOROS_DEFAULT_STEP_RESULT_SLUG` НЕ задан на стенде), а в crm только `sdelka` → создан реестр slug=`soglasovanie` с тем же record_schema (POST /api/registry-defs, 201).
3. `R-4` — collection-subKeys `qty`/`product` (колонки таблицы «Позиции») отсутствуют в top-level KEY_SET живой record_schema: `resolveLiveSchemaFieldKeys` возвращает только `Object.keys(properties)` (top-level), **суб-ключи коллекции туда не попадают** → классификатор помечает их висящими. После удаления таблицы «Позиции» с канваса (money+date+select+text) → **POST 201**.

**Гэпы для беклога (вне T-0678):**
- **`process_app_binding.target_registry_slug` не пишется НИ ОДНИМ HTTP-эндпоинтом/UI** (только сиды/миграции). Форму для реестра с не-дефолтным slug (напр. `sdelka`) через свежий процесс сохранить нельзя — WRONG_FLOOR не резолвит реестр. E16-визард результата шага должен уметь задавать `target_registry_slug`.
- **R-4 не учитывает суб-ключи коллекций**: `resolveLiveSchemaFieldKeys` берёт только top-level `Object.keys(properties)`; форма с таблицей (collection) на любом наборе получит ложный R-4 «висящий биндинг» для суб-ключей колонок. Проверить, не ломает ли это сохранение форм с таблицами в норме.
