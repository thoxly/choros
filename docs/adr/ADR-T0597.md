# ADR-T0597 — 5 UX quick-wins (alert→toast, reveal-toggle, org-link, Anthropic-default, honest-key-status)

Статус: ready. Источник: `docs/ux-loop-report-2026-07-02.md` находки №3/№5/№6/№8/№9.

## Контекст

Пять S-размерных находок из design-steward-отчёта помечены как «quick wins —
можно исполнить сегодня без дизайн-раунда». Каждая — точечная правка одного
уже существующего экрана, использующая уже существующие kit-примитивы/паттерны
проекта (toast-провайдер, react-router `useNavigate`, `--chs-color-warning*`
токены). Ни один фикс не требует нового эндпоинта или изменения серверной
семантики.

## Решения по каждому фиксу

### 1. alert() → pushToast (находка №6)

**Решение:** заменить `alert(e.message)` в обоих catch-блоках
(`screen-inbox.jsx:672,698`) на `pushToast({ tone: 'error', message: e.message })`
через `useToastContext()` — тот же провайдер, что уже подключён и используется
в `ra-criticality.jsx`, `ra-overview-forms.jsx`, `screen-assistant.jsx`. Текст
ошибки (`ENGINE_DRIVE_ERROR_MESSAGE`-маппинг, `ALREADY_CLAIMED`-ветка,
`NOT_ELIGIBLE`-фоллбек) не трогается — эти ветки уже производят человекочитаемый
`e.message`, задача чисто про канал доставки.

**Отклонённая альтернатива:** собственный локальный error-banner в инбоксе
(как `bannerErrStyle` в llm-connections). Отклонено — toast-провайдер уже
существует именно для этого класса «неблокирующий, но заметный исход действия»
(principles §4), и инбокс — плотная построчная таблица, где встроенный баннер
на каждую строку не имеет очевидного места без переверстки. Toast работает
поверх всего экрана без изменения layout.

### 2. Reveal-toggle на поле ключа (находка №3)

**Решение:** инлайн-реализация в `ConnectionKeyBinder` (не расширение общего
kit `Field`). Локальный `showKey` state, кнопка-глазик рядом с полем меняет
`type` password↔text и иконку. Два новых имени добавлены в `KitIcon`
(components.jsx) + `ICON_REGISTRY` (icon-registry.js): `eye`/`eye-off` —
аддитивно, не меняет существующие сигнатуры или другие экраны.

**Отклонённая альтернатива:** расширить `Field` пропом `revealable` (второй
вариант, который отчёт явно допускает). Отклонено для этого T — `Field`
используется в ~15+ местах кодовой базы; менять его контракт ради одного
потребителя увеличивает площадь риска регрессии непропорционально размеру
фикса (S). Инлайн-реализация в `screen-llm-connections.jsx` достигает того же
пользовательского исхода с диффом, ограниченным одним файлом. Если reveal-toggle
понадобится где-то ещё (например будущая форма секретов) — тогда есть
основание поднять его в kit с реальным вторым потребителем как доказательством
необходимости обобщения.

**Write-only инвариант:** reveal — чисто клиентское состояние ДО отправки
(показывает то, что пользователь только что напечатал в этом сеансе формы).
После успешной привязки поле обнуляется и форма закрывается (существующее
поведение `submitKey`, не меняется) — сервер по-прежнему никогда не возвращает
сырой ключ обратно; RL-3 инвариант из шапки файла не ослаблен.

### 3. Actionable-hint «оргструктура пуста» (находка №5)

**Решение:** `AssignRoleForm` (`ra-overview-forms.jsx`) получает собственный
`useNavigate()` из `react-router-dom` и рендерит hint как JSX-фрагмент (текст +
кнопка «Открыть оргструктуру» → `navigate('/org')`) вместо голой строки, когда
`employees` пуст. Путь `/org` НЕ изобретается — подтверждён существующим
`<Route path="/org" element={<OrgScreen .../>} />` в `shell.jsx:1160` и уже
используется тем же способом (`navigate('/org')`) в `screen-overview.jsx:193`
для плитки «Оргструктура».

**Отклонённая альтернатива:** прокидывать `navigate` пропом из
`screen-rights.jsx` (который уже держит `useNavigate()` на строке 229) через
`AssignRoleForm` пропы. Отклонено — добавило бы проп в сигнатуру компонента и
всем его будущим потребителям, тогда как вызов `useNavigate()` напрямую внутри
`AssignRoleForm` — легален (компонент монтируется исключительно внутри
authenticated Router-дерева, тот же паттерн уже используют другие
глубоко-вложенные компоненты приложения) и не увеличивает пропс-поверхность.

**Kit-совместимость:** `Select`'s `hint` prop уже рендерит `{hint}` как
произвольный ReactNode без PropTypes-ограничения на string — передача JSX не
требует изменения `Select` в `components.jsx`.

### 4. Дефолт формы = Anthropic (находка №8)

**Решение:** initial `useState` формы (`provider`, `endpoint`, `model`,
`priceIn`, `priceOut`, `currency`) переключаются на значения
`PROVIDER_PRESETS.find(p => p.value === 'anthropic')` вместо ручного
deepseek-литерала. Единственный источник цифр — уже существующий массив
пресетов (не дублируем числа второй раз).

**Отклонённая альтернатива:** переписать инструкцию нейтрально («выберите
вашего провайдера») вместо смены дефолта формы — второй вариант, который отчёт
предлагает как равноценный. Отклонено, т.к. фаундер уже вставляет
Anthropic-ключ по независимому T-0574 (см. `docs/handoff/T-0572...` и
memory `choros-primitives-map-2026-07-02`), инструкция явно завязана на
console.anthropic.com/API Keys/Create Key (специфичный, не нейтральный,
пошаговый текст) — синхронизация дефолта формы с уже написанной конкретной
инструкцией дешевле и не требует переписывать прошедший UX-ревью текст.
DeepSeek остаётся первым элементом `PROVIDER_PRESETS` и полностью выбираем —
это смена ДЕФОЛТА, не удаление альтернативы.

### 5. Честный статус «ключ не привязан» (находка №9)

**Решение:** три согласованных, но независимо применимых изменения:

1. Успех-баннер (`createOk`) при создании профиля БЕЗ `secretHandle` дописывает
   вторую строку «Теперь вставьте API-ключ, чтобы он заработал.» — условие
   проверяется на момент успешного `onCreate` (был ли `secretHandle.trim()`
   пуст), не на состояние после рефетча (упрощает логику, тот же результат:
   профиль без хэндла = профиль без ключа сразу после создания).
2. `chipStyle(false)` (карточка профиля, `!secret_bound`) переключается с
   нейтральных `--chs-color-surface-raised`/`--chs-color-text-muted` на
   `--chs-color-warning`/`--chs-color-warning-soft` — токены уже определены в
   обеих темах (`design/tokens.css:193-194,263-264`), не новый токен.
3. Кнопка «Вставить API-ключ» в `ConnectionKeyBinder` получает
   `variant={secretBound ? 'ghost' : 'primary'}` — primary только пока ключ
   ещё не привязан; в режиме «Заменить API-ключ» (уже привязан) кнопка
   остаётся `ghost` — это не более критичное действие, чем другие вторичные
   операции на карточке.

**Отклонённая альтернатива:** блокировать создание профиля без ключа (сделать
`secretHandle` обязательным). Отклонено — явно противоречит контракту
профиля-как-переиспользуемой-сущности (профиль можно создать заранее и привязать
ключ позже, отчёт и текущий код оба это допускают намеренно) и потребовало бы
серверного изменения валидации, что выходит за периметр чисто клиентского T-0597.

## FF-UX гейты (информационные, не понижаются)

- **g5** (jargon denylist): новые строки не вводят T-id/дев-термины в видимый
  текст — проверено вручную при написании (тексты «Показать/скрыть ключ»,
  «Открыть оргструктуру», «Теперь вставьте API-ключ» — чистый продуктовый
  русский).
- **g6** (no-new-hardcode): все новые стили — исключительно через `--chs-*`
  токены (`--chs-color-warning`, `--chs-color-warning-soft`, существующие
  `--chs-space-*`) — ни одного нового rgba()/hex-литерала.
- **aria на toggle**: reveal-кнопка получает `aria-label` (текст, синхронный с
  состоянием) и `aria-pressed` (boolean, синхронный с `showKey`) — доступна с
  клавиатуры (`<button type="button">`, не `<div onClick>`).
