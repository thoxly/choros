# ADR T-0749 — entitlement-gates-vendor-only.sh: снятие false-positive «deactivation» (CI-гейт гигиена, substrate)

- **Статус:** реализовано (impl-фаза, coder), auto-additive frozen-thaw
  (не founder — правка мехнически додекана аддитивна, см. §3).
- **Контекст:** вскрыто ДВАЖДЫ независимо (T-0724, T-0740) при полном
  `npm run fitness`: `ci/checks/entitlement-gates-vendor-only.sh`
  (владелец T-0198) краснел на диффах, которые НИКОГДА не трогали
  entitlement/vendor-логику — потому что его `VOCAB_RE` содержит голый
  substring `activation`, а `src/http/user-mgmt.ts` (T-0702/T-0727,
  session-revoke при деактивации сотрудника) легально содержит слово
  `deactivation`, которое `activation` включает подстрокой.
- **Область:** `ci/checks/entitlement-gates-vendor-only.sh` (ЧУЖОЙ frozen-чек,
  владелец T-0198), `ci/checks/data/frozen-sanctions.jsonl` (append-only
  sanction-строка), этот файл.

## 1. Проблема — репродукция

```
$ bash ci/checks/entitlement-gates-vendor-only.sh
  FAIL: non-vendor handler reads activation/entitlement: .../src/http/user-mgmt.ts
    ...: `deactivation (best-effort, ADR-T0702 §2.2); the PDP gate ` +
FAIL [FF-T127-4]: a non-vendor http handler reads activation/entitlement
```

Файл `user-mgmt.ts` **byte-identical на базе** (`git diff cf0acba5 --
src/http/user-mgmt.ts` — пусто) — это НЕ регресс диффа T-0749/T-0724/T-0740,
а pre-existing false-positive самого гейта, обнажающийся каждый раз, когда
кто-то прогоняет ПОЛНЫЙ `npm run fitness` (а не только свой узкий срез
чеков).

Проверка по всему дереву (не только строке 451 из усечённой нумерации
самого гейта — `code_lines()` фильтрует комментарии ДО передачи в `grep -n`,
поэтому номер строки в FAIL-выводе гейта не совпадает с реальным номером
файла; реальная строка — 773):

```
$ for f in src/http/*.ts; do
    case "$(basename "$f")" in vendor-*|*.tmp.ts) continue ;; esac
    grep -vE '^[[:space:]]*(//|[*]|/[*])' "$f" | grep -niE 'activation|entitlement|verifyKey|isEntitled|not_after'
  done
src/http/user-mgmt.ts:773:  `deactivation (best-effort, ADR-T0702 §2.2); the PDP gate ` +
```

**Ровно один матч во всём нефон-vendor `src/http/*.ts`, и это — false
positive.** Никакой реальной entitlement/vendor-логики в non-vendor
хендлерах нет (что и должно быть — гейт по своей сути прав, просто ловит
неправильную подстроку).

## 2. Frozen-статус — проверено эмпирически

Второй заголовочной строкой файла: `# T-0198 · FF-T127-4 — entitlement
gates ONLY vendor endpoints (exclusion check)` → владелец `T-0198`, НЕ
`T-0749`. `ci/checks/frozen-checks-immutable.sh` (T-0146) резолвит владение
по `BASE_REF`-версии заголовка (tamper-proof), не по рабочей копии — правка
этого файла с ветки `task/T-0749` без санкции провалилась бы FF-FCI1.
Это ровно тот класс, что `coder.md` §8(б) явно запрещает трогать напрямую.

## 3. Решение — auto-additive thaw (T-0232/D-060), не founder

Прямая правка `VOCAB_RE='activation|entitlement|...'` до `\bactivation\b`
(или до исключения `deactivation`) — это **мутация существующей строки**,
запрещённая `A-1` (byte-preservation ВСЕХ непустых BASE_REF-строк).
Вместо этого реализовано **чисто аддитивно**:

1. Новая функция `strip_deactivation_noise()` (добавлена ПОСЛЕ
   `code_lines()`, не заменяет её): `sed -E 's/deactivations?//gI;
   s/reactivations?//gI'` — снимает ТОЛЬКО два буквальных compound-слова
   («deactivation», «reactivation» — единственные формы, которые вообще
   содержат substring `activation`; `deactivate`/`deactivated`/
   `deactivating` его НЕ содержат, проверено вручную посимвольно).
2. Одна новая строка в `scan_dir()` СРАЗУ ПОСЛЕ существующей
   `code="$(code_lines "$f")"` (та строка НЕ тронута):
   `code="$(echo "$code" | strip_deactivation_noise)"`.
3. Четыре новых `--self-test` блока (негатив «deactivation»/«reactivation»,
   позитив «vendor activation», микс «deactivation+isEntitled») — см. §5.

Ни одна существующая строка (включая комментарии) не удалена и не
изменена — `git diff` на файл показывает только `+`-строки. `VOCAB_RE` сам
по себе НЕ тронут: реальный `activation`/`entitlement`/`verifyKey`/
`isEntitled`/`not_after` в non-vendor хендлере продолжает ловиться (см.
позитив-проба §5). Это соответствует прецеденту T-0740 §4 (`docs/tasks/
T-0740.adr.md`) — тот же механизм, тот же владелец-класс задачи (CI-гейт
гигиена / security-follow-up), верифицирован тем же способом.

### Враг-аттестация (`ci/checks/data/frozen-sanctions.jsonl`)

- **families:** `["NO-KILLSWITCH-IN-CORE"]` — семья §7.3 каталога
  `docs/design/T-0152-security-invariants-catalog.md` УЖЕ перечисляет
  `ci/checks/entitlement-gates-vendor-only.sh` в своём Enforced-by (вместе
  с `no-killswitch-in-core.sh`, `activation-verifier-offline.sh`,
  `activation-config-pubkey-only.sh`) — новую семью заводить не пришлось
  (в отличие от T-0740, которому пришлось добавить §7.7).
- **corpus_ref:** `cf0acba54ca79ec972cb3818a422ee966deeb106` (= merge-base
  `dev`↔`HEAD`, он же стартовая точка этой ветки) — предок HEAD, корпус
  `src/__tests__/enemy/corpus/corpus.jsonl` этой задачей не трогается, блоб
  идентичен HEAD.
- **enemy_segment:** собственный расширенный `--self-test` файла (негатив/
  reactivation/позитив/микс-пробы, T-0749) — прямое машинное доказательство,
  что фикс не ослабляет детекцию реального activation/entitlement-чтения.

## 4. Почему НЕ founder-класс

Это точечный, механически проверяемый (A-1..A-4 + Враг-аттестация) фикс
false-positive; реальный security-инвариант («entitlement/activation reads
confined to vendor edges») не ослабляется — только два буквально
нерелевантных слова перестают давать ложное срабатывание. Эскалация на
фаундера за такой registry/regex-гигиенический фикс была бы over-escalation
(`founder-escalation-boundary`: к фаундеру только деньги/продукт/секреты/
необратимое).

## 5. Тесты / гейты

- `bash ci/checks/entitlement-gates-vendor-only.sh` — было FAIL (1 finding,
  `user-mgmt.ts` deactivation-строка) → **PASS** (0 findings) на текущем
  `src/http/*.ts` без единой правки продуктового кода.
- `bash ci/checks/entitlement-gates-vendor-only.sh --self-test` — PASS,
  включая 4 новых T-0749-пробы:
  - негатив «deactivation» (user-mgmt.ts-подобная строка) — НЕ флагуется;
  - негатив «reactivation» — НЕ флагуется;
  - позитив «checkVendorEntitlementActivation» (настоящий activation-read
    вне vendor-эджа) — ФЛАГУЕТСЯ (гейт не ослаблен);
  - микс «deactivation triggers isEntitled recheck» — ФЛАГУЕТСЯ (strip
    снимает только шумовую подстроку, не всю строку).
- `bash ci/checks/frozen-checks-immutable.sh` — PASS (auto-additive
  sanction верифицирована мехнически, не покраснел).
- `bash ci/checks/auto-sanction-additive.sh --self-test` — PASS (не
  тронут).
- `bash ci/checks/anti-case-lock.sh` — без новых кейс-литералов.
- Полный `npm run fitness` — доходит до конца без ложного FAIL на
  entitlement-чеке (см. handoff за точный номер чека / хвост лога).

## 6. Отклонения от спеки

Нет. Задача полностью выполнена аддитивным auto-sanction-каналом; founder-
эскалация не потребовалась (в отличие от предупреждения в постановке —
разведка показала, что фикс МОЖЕТ быть реализован как чистое добавление
без мутации `VOCAB_RE`, что и является правильным способом закрыть
false-positive, не расширяя и не сужая реальный security-инвариант).
