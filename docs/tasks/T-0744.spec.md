## 1. Problem (from ADR §1/§2.7)

Tier is a frozen snapshot taken at declaration ("does any THIRD holder exist?"),
but the claim-gate assumes "the stand-in personally holds the role". These agree
only when the stand-in IS that holder. Code let them diverge: a Tier-1 stand-in
who does **not** hold the role is added to the routing pool unconditionally
(`inbox.ts` path B + `executor-resolver.ts` path A), so when the covering pool
later empties the role looks "covered" to the router but the claim-gate rejects
the stand-in (`ttlGrantId !== null` filter) → 403 → task wedged, never falls to
the owner (`routed_to_fallback` is display-only, `void ownerSlug`).

## 2. The invariant (tech-debt, one source of truth)

> A substitution rule provides **coverage** of a role **iff** it minted a Tier-2
> grant (`ttlGrantId !== null`) **OR** the substitute personally holds the role
> (`holders.includes(substituteEmployeeId)`).

Pure predicate in `src/core/substitution.ts`:

```ts
substituteProvidesCoverage(rule, roleHolders: ReadonlySet<string>): boolean
  = rule.ttlGrantId !== null || roleHolders.has(rule.substituteEmployeeId)
```

and a pure `computeEffectivePool(holders, rules, roleSlug): string[]` that suppresses
absent holders always, and re-adds the substitute **only** when the predicate holds.
Both routing paths and the owner-empty-pool check consume these — no path re-derives
the rule. This deletes the false premise in `inbox.ts:1378` comment / T-0588 §1.3.

## 3. Three parts

**Part 1 — routing in agreement with the claim-gate.**
- `inbox.ts` `resolveExecutorFallbackBatch` (path B, live): step-3 per-role effective
  pool now `computeEffectivePool(holders, substRules, roleSlug)`. A Tier-1 non-holder
  no longer masks an emptied role → `routed_to_fallback:"role_unfilled"` surfaces.
- `executor-resolver.ts` `resolveExecutor` (path A, dormant but kept consistent): the
  substitute joins the effective pool only when `substituteProvidesCoverage`. When the
  suppression empties the pool → falls through to the existing fallback (rung 4).
  Behavioral consequence: a Tier-1 non-holder substitute (`ttl_grant_id` null, not a
  co-holder) now yields `fallback:"role_unfilled"` instead of `kind:"substitution"`.
  The pre-fix executor tests encoded that (buggy) contract → updated to Tier-2 for the
  genuine "substitute takes over" case + new Tier-1-non-holder → fallback tests.

**Part 2 — owner-claim of an orphaned role.**
- "Owner" = genesis `tenant-owner` via `isGenesisOwnerForTenant` (`src/db/org.ts:747`,
  deactivation-safe: a deactivated owner resolves false → stays `unresolvable`, per
  T-0588 AC-7). Chosen over process-owner: the ADR §2.6/§3-в2 names the genesis owner,
  who is already the F6/PD-10 last-resort executor and holds top authority in the tenant.
- New shared, fail-closed predicate `isOwnerOrphanClaimEligible(pool, tenant, actor,
  role, now)` = `isGenesisOwnerForTenant(actor)` **AND** effective pool of the role is
  empty (`computeEffectivePool(...).length === 0`). Any DB error → `false` (deny → the
  base 403 stands; never a wrong-allow, never a 500 masking a legit 403).
- Wired into BOTH claim (`POST /api/inbox/:id/claim`) and approve
  (`POST /api/inbox/:id/action`) gates, AFTER the Tier-2 substitution branch misses and
  BEFORE the 403 throw. The empty-pool gate is what keeps the owner from grabbing pool
  work with live holders (owner takes ONLY the orphaned task). Owner acts as **themselves**
  — no `on_behalf_of` recorded (unlike a Tier-2 substitute).

**Part 3 — fitness.** `ci/checks/substitution-coverage-invariant.sh` (+ `--self-test`):
asserts the predicate is exported from the pure module, that both routing paths reference
`computeEffectivePool`/`substituteProvidesCoverage` (no unconditional `effective.add`
of a substitute), and that the owner-claim empty-pool gate reuses the predicate. Plus a
pure vitest (`substitution-coverage.test.ts`) exercising the predicate in isolation.

## 4. Idempotency / regression

- Owner re-claim: the existing audit-projection claim-lock idempotency (re-claim own →
  200 no-op; other's claim → 409) is unchanged — the owner branch only decides *eligibility*.
- Regression preserved: Tier-1 substitute who IS a co-holder → coverage → pool non-empty →
  no fallback, owner-claim denied. Tier-2 substitute → coverage → substitute still claims
  (T-0588 AC-1) and owner-claim denied. Live pool holder → owner-claim denied 403.
