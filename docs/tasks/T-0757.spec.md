# T-0757 — SP-1 в forms-from-schema.test.ts: диагноз и фикс "жёсткого" 10s hang

**Приоритет:** 46 (substrate/fitness, D-056). **Гейт:** fitness-mask на dev — красный SP-1 маскирует честный сигнал ВСЕМ веткам, пока держится.

## Нулевой шаг — воспроизведение

```
cd /Users/shoxy/Code/choros-wt/T-0757
npx vitest run src/__tests__/forms-from-schema.test.ts -t "SP-1"
```

RED, стабильно воспроизводится (3/3 запусков): тест таймаутит ровно на своём
собственном хардкод-таймауте:

```
× SP-1 ... 10052ms → Test timed out in 10000ms.
```

Замечание сразу: `it(name, fn, 10000 /* allow 10s for server startup */)` —
третий аргумент `it()` — это **per-test override**, который ВСЕГДА побеждает
глобальный `testTimeout` из `vitest.config.ts` (сейчас 60000, поднят T-0646
именно чтобы не резать легитимно медленные тесты timeout-margin'ом). Поэтому
попытка "поднять testTimeout=30000" (упомянутая в задаче) объективно НЕ МОГЛА
подействовать на этот конкретный тест — она никогда не долетала до сравнения:
у SP-1 всегда действовал его собственный литерал 10000, независимо от того,
что стоит в конфиге. Это ложно выглядело как "не лечится поднятием таймаута
→ значит настоящий дедлок".

## Диагностика: где именно висит

Инструментировал (временно, `console.error` с `Date.now()`) четыре точки:
тело теста (`src/__tests__/forms-from-schema.test.ts`), обработчик роута
(`src/http/forms.ts`), `withAuth`/`authenticate` (`src/http/auth.ts`) и
`Router.dispatch` (`src/http/router.ts`). Результат первого прогона с
инструментацией — **ключевая находка**:

```
[T0757-DEBUG] SP-1 START
[T0757-DEBUG] forms.js imported          (+843ms)
                                          ... 9+s ничего ...
Test timed out in 10000ms.
```

`console.error("[...] handler entered")`, `withAuth`, `router.dispatch` —
**ни одна** из этих меток не напечаталась. Значит зависание было не в
обработке HTTP-запроса (роутинг/аутентификация/persist), а РАНЬШЕ — в
`await import("../server.js")`, то есть в загрузке/компиляции самого модуля
`server.ts`.

### Бисекция графа импортов server.ts

`server.ts` — composition root: ~90 прямых `import` (все `registerXRoutes`,
Keycloak admin-port, LLM-адаптеры, `pg.Pool` wiring и т.д.). Сгенерировал
временный тест, последовательно импортирующий каждый из этих 91 модуля с
таймингом (`await import(spec)` + `console.error` до/после) — обнаружил, что
уже к 27-й секунде (после ~38 модулей) кумулятивное время холодной
транспиляции/評valuation превысило и без того истёкший 10s-бюджет теста,
причём НИ ОДИН отдельный модуль не хангался бесконечно — просто общая
стоимость первой холодной загрузки ~90-модульного графа (esbuild transform +
module evaluation в свежем vitest worker) оказалась пропорционально большой.

### Решающий эксперимент

Временно поднял таймаут теста до 60000 (диагностика, НЕ финальный фикс) и
добавил метки — тест **прошёл**:

```
[T0757-DEBUG]      0ms  SP-1 START
[T0757-DEBUG]    843ms  forms.js imported
[T0757-DEBUG]  33514ms  server.js imported      ← вся стоимость здесь
[T0757-DEBUG]  33622ms  server created, listening
[T0757-DEBUG]  33739ms  listen callback
[T0757-DEBUG]  33776ms  socket connect
[T0757-DEBUG]  33787ms  dispatch entered
[T0757-DEBUG]  33788ms  matched route POST /api/forms/:formId/submit
[T0757-DEBUG]  33790ms  handler entered
[T0757-DEBUG]  33805ms  persist resolved
[T0757-DEBUG]  33817ms  res.end called
✓ SP-1 34686ms
```

**Вся** стоимость (33514 из 34686 ms, 96.6%) — это `await import("../server.js")`.
Всё, что происходит ПОСЛЕ импорта (создание сервера, listen, TCP-connect,
роутинг, аутентификация, валидация, memoryPersist, ответ) укладывается в
**~700ms**. Никакого незакрытого handle, никакого нерезолвленного промиса,
никакого дедлока в persist-пути — реальный HTTP round-trip мгновенный.

## Классификация: тест-артефакт, не продуктовый баг

Это не "флейк под нагрузкой" (как формулировала задача) и не "реальное
зависание" в проде — это структурная ошибка **этого конкретного теста**:

1. `forms-from-schema.test.ts` несёт собственную декларацию в шапке файла:
   *"DATABASE_URL-free: pure unit tests — no pg.Pool, no live DB, no env
   reads (FE-s27-0002 discipline: never construct pg.Pool in a pure unit
   test)."* SP-1 нарушал эту же доктрину: `createServer()` из `server.ts`
   безусловно импортирует ~90 модулей, включая `pg`, Keycloak admin-port,
   LLM-адаптеры — весь composition root, хотя SP-1 проверяет только
   memory-mode fallback ОДНОГО роута (`registerFormsRoutes` без `deps`).
2. Соседний `forms-submit.e2e.test.ts` импортирует `server.js` СТАТИЧЕСКИ
   (`import { createServer } from "../server.js"` на верхнем уровне файла) —
   та же дорогая транспиляция там оплачивается на фазе **collect** (у
   которой нет узкого per-test таймаута), а не внутри тела теста. SP-1
   единственный использовал `await import(...)` ВНУТРИ тела теста, что
   переносит холодную стоимость точно в окно, ограниченное литералом
   `10000`.
3. Прогон полного файла (`forms-submit.e2e.test.ts` вместе с
   `forms-from-schema.test.ts` и др.) подтверждает: когда стоимость
   импорта `server.js` оплачивается на фазе collect (как у e2e-файла),
   `collect` может занять десятки секунд суммарно по всем файлам — и это
   НЕ считается зависанием, потому что не режется коротким per-test
   таймаутом.

Вывод: **тест-артефакт**, конкретно — (а) тест платит за ВЕСЬ composition
root там, где нужен только один роут, нарушая собственную
DATABASE_URL-free доктрину файла, и (б) платит эту цену внутри
узко-бюджетированного тела теста вместо фазы сборки/коллекции.

## Фикс (корень, не симптом)

`src/__tests__/forms-from-schema.test.ts`, SP-1:

- Заменил `createServer(undefined, undefined, "memory")` (весь `server.ts`)
  на прямое связывание **того же самого** `Router`-класса и **той же
  самой** функции `registerFormsRoutes` — это ТОЧНО тот же код, который
  `server.ts`/`buildRouter()` использует внутри для этого роута (не "сырой
  Router API", как боялся исходный комментарий SP-1, а идентичная
  продакшн-обвязка минус 89 несвязанных регистраторов):

  ```ts
  const { registerFormsRoutes, _getRecordForTests, _resetRecordStoreForTests } =
    await import("../http/forms.js");
  const { Router } = await import("../http/router.js");
  const http = await import("node:http");

  const router = new Router();
  registerFormsRoutes(router);           // без deps → memoryPersist fallback
  const server = http.createServer(router.dispatch.bind(router));
  ```

- Больше не импортирует `server.ts` вовсе → не тянет `pg`, Keycloak
  admin-port, LLM-адаптеры и оставшиеся ~89 регистраторов. Соответствует
  собственной doctrine файла ("DATABASE_URL-free ... never construct
  pg.Pool in a pure unit test").
- Снизил per-test override с `10000` до `5000` (не поднятие, а СНИЖЕНИЕ —
  честный запас x3-6 над наблюдаемыми 200–1800ms, чтобы будущая регрессия
  к тяжёлому графу импортов ловилась БЫСТРО тестом же, а не проявлялась
  как ещё один 10s+ "hang").
- Обновил комментарий блока SP-1/SP-2, зафиксировав диагноз и обоснование
  выбора (regression-lock смысл, не просто "стало быстрее").

Продуктовый код (`src/http/forms.ts`, `src/http/auth.ts`, `src/http/router.ts`,
`src/server.ts`) **не тронут** — там не было бага, только временная
инструментация для диагностики, полностью отревертирована (`git checkout --`)
до финального коммита.

## Что атаковать судье

1. Что если `registerFormsRoutes(router)` без deps на самом деле НЕ
   идентичен тому, что делает `createServer()` для этого роута — проверить
   `src/server.ts` строки ~568-589 (`registerFormsRoutes(router, grantsPool
   ? {...} : undefined)`), убедиться что при `grantsPool == null` (что и
   есть memory-mode/тест-окружение без `DATABASE_URL`) это ТОЧНО тот же
   вызов `registerFormsRoutes(router)` без второго аргумента.
2. Не появился ли скрытый смысл именно в использовании ПОЛНОГО
   `createServer()` (например, unregistered fallback static handler или
   какой-то побочный эффект buildRouter, от которого SP-1 неявно зависел)
   — прогнать SP-1 и убедиться, что 404/other-route behaviour не
   изменилось (сравнить со старым тестом на предмет неявных зависимостей).
   Ответ по факту: SP-1 бьёт ровно в `/api/forms/purchase/submit`,
   единственный роут, который регистрирует `registerFormsRoutes` — никаких
   fallback-путей не задействовано.
3. Достаточен ли новый бюджет `5000ms` с запасом под медленный/нагруженный
   CI — наблюдаемые холодные прогоны были 678–1801ms; можно поднять до
   более щедрого значения (например 8000) если CI окажется существенно
   медленнее локальной машины, но не обязательно.
4. Убедиться, что временная диагностическая инструментация (console.error
   в forms.ts/auth.ts/router.ts) полностью отревертирована — `git diff
   dev...task/T-0757 -- src/http/forms.ts src/http/auth.ts
   src/http/router.ts src/server.ts` должен быть пустым (эти файлы вне
   диффа PR).
