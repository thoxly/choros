# ADR T-0753 — Commit a KC credential for the existing migration-088 builder persona

## Status
Accepted (substrate / LIVE_PROOF-infra).

## Context
The Конструктор-зона is gated by the choros-DB capability `authoring_draft`
(resolved through employee → role_assignment → grant, NOT a KC role). No
committed KC fixture holds it; the owner path (e-owner) is intentionally
un-committed to protect the founder's owner credential from realm-reimport
password resets. Result: the builder/authoring surface is un-livable in
acceptances.

## Decision
Add exactly one committed KC user, `e-configurator`, to
`config/keycloak/realm-choros.json`, reusing the persona that
`migrations/088` (+ `104`) already provisions on the DB side
(role-configurator → authoring_draft create/update, non-owner). The KC username
equals the employee slug and resolves via the `preferred_username` fallback in
`resolveActorSlugFromAuth`.

### Alternatives rejected
- **Mint a new `e-builder` persona** (name suggested by the task): rejected —
  would duplicate migration 088's entire role/employee/assignment/grant chain
  (new migration + UUID namespace) for zero capability difference. Reuse is
  smaller scope and closes a gap already documented in `src/db/org.ts`.
- **Commit e-owner instead**: rejected hard — realm-reimport would reset the
  founder's owner password (choros-founder-cred-lockout). e-owner stays
  out-of-band.
- **Grant authoring_draft to an existing ТЭЛ persona (e.g. e-larina)**:
  rejected — pollutes a workflow-role fixture with a builder capability and
  changes an existing user object (non-additive; reimport-risk to that
  persona). The dedicated non-owner persona already exists for exactly this.

## Consequences
- One additive user; e-owner and all existing fixtures byte-unchanged →
  reimport-safe.
- `e-configurator` = `{ isOwnerOrAdmin:false, hasAuthoringDraftGrant:true }`:
  a pure builder, separate from the founder owner, cannot escalate to owner.
- No TS/migration change; only realm JSON + docs. `dev-pw-configurator` is a
  sanctioned dev-fixture credential (FF-11 allows `dev-pw-` in realm JSON).
- Depends on migration 088/104 being applied on the target stand (they are
  committed migrations, idempotent). If a stand predates them, run migrations —
  the KC user alone is inert without the DB grant (honest fail-closed 403).
