# ADR T-0742 (T-0654-c) — «Каталог процессов» карточками + удаление ProcessCatalogSection

Спека: `docs/tasks/T-0742.spec.md`. Родитель-ADR: `docs/design/ADR-T0654-processes-split.md`,
`docs/tasks/T-0735.adr.md` (AC-B6 отложен сюда). Статус: `ready`. Только web + один e2e.

## Решение (одним абзацем)

Строим самодостаточный экран `web/src/screens/screen-process-catalog.jsx` (маршрут
`/process-catalog`, зона `constructor`), который потребляет ТОТ ЖЕ `GET /api/process-catalog`
(`{definitions, instances, bindings}`) + `GET /api/applications`, что и снятая секция, и рендерит
определения КАРТОЧКАМИ вместо таблицы. Каждая карточка сворачивает в себя: человеко-имя (ключ —
демотирован в mono-подпись), статус-бейдж, версию, счётчик инстансов (клик>0 → `/processes?definition=
<procKey>` — deep-link в грид T-0735), inline-список триггеров-связей этого `process_key` (третья
таблица «Связи» исчезает), кнопки «В модельер»/«Правила ветвления»/«Настроить триггер». Binding-
модалку (`BindProcessModal`) переносим из `screen-processes.jsx` в новый экран без изменения логики
(та же `process-catalog.js`, тот же upsert-контракт). `ProcessCatalogSection` + `BindProcessModal`
удаляются из `screen-processes.jsx`; грид получает ЕДИНСТВЕННОЕ дополнение — чтение `?definition=`
из URL (seed фильтра), чтобы deep-link части C реально фильтровал. Одна кнопка «Новый процесс» в
шапке каталога (дубль убран). Чистая логика (фильтр связей, deep-link URL, плюрализация) — в
`process-catalog.js` (pg-free, unit-тестируемо), рендер — в `.jsx`.

## Почему карточки, а не реюз грида/таблицы

Определения — это ОБЪЕКТЫ авторинга (у каждого имя, статус, версия, набор связей, набор действий),
а не строки списка оператора. Таблица прятала действия в узкую колонку и связи — в отдельную
таблицу-сироту. Карточка (`Card` kit-примитив) даёт каждому определению свою поверхность с
заголовком/телом/подвалом-действиями; связи живут внутри своей карточки, а не в общей таблице,
теряющей привязку к определению. Грид T-0735 остаётся строго для живых инстансов (зона «Работа»).

## Объектная модель (контракты — БЕЗ изменений сервера)

`CatalogDefinition` (`src/core/process-catalog-view.ts`, уже в dev):
`{ process_key, name, source:'modeler'|'engine', status, version:number|null, instance_count }`.
`ProcessAppBinding` (`src/http/process-catalog.ts`): `{ id, process_key, application_id,
application_name, application_slug, trigger_type, start_form_key, form_key, field_mapping,
target_registry_slug }`. Имя определения УЖЕ резолвится сервером (modeler `name`, либо
`engine_process_name`-overlay T-0732, либо честный fallback = ключ) — экран не резолвит имён заново.

## Новые чистые помощники (`web/src/screens/process-catalog.js`, additive)

```
bindingsForDefinition(bindings, processKey) → ProcessAppBinding[]   // связи этого определения
processGridDeepLink(processKey)            → "/processes?definition=<encoded>"  // AC-C3
definitionVersionLabel(def)                → "Версия N" | null       // null для engine (version=null)
pluralizeRu(n, [one, few, many])           → string                  // «1 инстанс/2 инстанса/5 инстансов»
instanceCountLabel(count)                  → "N инстанс(ов)"         // подпись счётчика
```

Все — pure, без DOM/сети/кейс-констант. Тесты — в `process-catalog.test.js`.

## Deep-link C→B (AC-C3)

Карточка: счётчик инстансов рендерится КНОПКОЙ (kit `Button variant=ghost`) ТОЛЬКО при
`instance_count > 0` → `navigate(processGridDeepLink(process_key))`. При `0` — статичный текст
«0 инстансов» (не мёртвая кнопка — G7). Грид `ProcessesScreen` seed-ит `definition` из
`useSearchParams().get('definition')` в инициализаторе `useState` (тот же паттерн, что инбокс
seed-ит `?instance=`, T-0735 AC-D2) — эффект первичной загрузки уже читает `definition`, поэтому
приход по deep-link сразу отфильтрован, а `<select value={definition}>` показывает выбранное
определение как активный фильтр (честный аффорданс, не скрытое состояние).

## Удаление без сиротства (AC-C8)

Функции снятой `ProcessCatalogSection` и их новый дом:
| функция секции | новый дом |
|----------------|-----------|
| список определений | карточки каталога |
| счётчик инстансов | счётчик-кнопка карточки → deep-link грид |
| «Настроить триггер» + `BindProcessModal` | кнопка карточки + модалка (перенесена дословно) |
| «В конструкторе»/«В модельер» | кнопка карточки |
| «Правила ветвления» (DMN) | кнопка карточки |
| таблица «Связи процессов с приложениями» | inline-связи внутри карточки (`bindingsForDefinition`) |
| «Новый процесс» | одна кнопка в шапке каталога |

`screen-processes.jsx` теряет: `ProcessCatalogSection`, `BindProcessModal`, импорты из
`process-catalog.js`, неиспользуемые kit-импорты (`Modal`, `Field`, `MonoId` если осиротели);
приобретает: `useSearchParams` + seed `definition`. Грид-логика T-0735 (пагинация/дебаунс/гонки)
не трогается.

## Fitness-функции (машинно-проверяемые)

- **FF-UX-1 (anti-uuid).** Карточка рендерит ИМЯ определения; ключ — только `<MonoId>`-подпись;
  ни одного bare-`{x.recordId/actor}`. Гейт: `ci/checks/ux/anti-uuid-actor-render.sh` (REQUIRED).
- **FF-UX-2 (anti-case).** Ни имени/слага процесса, ни домен-словаря в добавленных строках.
  Гейт: `ci/checks/anti-case-lock.sh` + `detel-*`.
- **FF-UX-3 (jargon).** Нет `T-\d{3,}`/`telLinear` в ВИДИМОМ тексте. Гейт: `ux-g5`.
- **FF-UX-4 (no-fake-buttons).** Счётчик — кнопка ТОЛЬКО при >0; каждый enabled-контрол
  навигирует/открывает модалку/шлёт сеть. Гейт: `ux-g7`.
- **FF-UX-5 (theme/tokens).** Только `--chs-*` токены + kit (`Card/Button/Badge/StatusChip/Modal`).
  Гейт: `ux-g2`.
- **FF-C (каталог ↔ контракт).** Тест: определения из `definitions[]` карточками; счётчик-кнопка →
  `?definition=<key>`; связи из `bindings[]` по `process_key` на карточке; кнопки модельер/DMN;
  одна «Новый процесс».
- **FF-B6 (снятие сиротства).** Тест: `screen-processes.jsx` больше НЕ содержит
  `ProcessCatalogSection`/`BindProcessModal`; грид сеет `?definition=` из URL.
