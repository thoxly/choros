# Spec T-0732 — человеко-имя движковых процессов из BPMN `<process name>`

**Родитель:** ревью T-0717 (O-1 / nit R-2), эпик E16 T-0349, столп 2. Полный
дизайн/альтернативы/трассировка — `docs/tasks/T-0732.adr.md`.

## Проблема
Движковые процессы (`source=engine` — задеплоенные прямо в Flowable из
`config/flowable/processes/*.bpmn20.xml`, БЕЗ строки `choros.process_definition`)
показываются в UI лишь по camelCase-ключу (`telLinear`): `resolveDefinitionNames`
отдаёт для них `fallbackDefinitionName` (= ключ), `deriveInstanceTitle` (web)
демотирует до generic «Процесс». Machine-leak, столп 2 (человеческий слой).

T-0717 установил: (1) `config/*` мёртв в проде (не в Docker-образе); (2) Flowable
`process_key` НЕ tenant-partitioned → резолв по голому ключу через Flowable REST
рискует межтенантной утечкой (класс T-0616 §F-1).

## Критерии приёмки
- **AC-1.** Deploy BPMN с `<process name>` → человеко-имя хранится tenant-scoped
  (своя таблица, не Flowable-tenant).
- **AC-2.** Движковый процесс в деталке записи / каталоге / инбоксе → человеко-имя
  вместо демотированного ключа.
- **AC-3.** BPMN БЕЗ `name` → фолбэк остаётся демотированный ключ (deriveInstanceTitle
  никогда не показывает голый ключ как primary — инвариант свят).
- **AC-4.** Межтенантно: тот же ключ в другом тенанте НЕ течёт чужое имя (регресс
  T-0616 §F-1) — RLS-enforced.
- **AC-5.** Анти-кейс: имён конкретных процессов нет в `src/` — только BPMN-DATA и
  `@demo-seed` фикстуры.

## Решение (кратко)
Отдельная tenant-scoped таблица-оверлей `choros.engine_process_name` (migration 131),
резолвится средним ярусом (`modeler → engine-оверлей → голый ключ`) в
`resolveDefinitionNames` (список/деталь/инбокс) и `buildCatalogDefinitions` (каталог).
Имя — DATA из `<process name>` (`parseBpmnProcessMeta`); доставка на стенд — `@demo-seed`
migration 132. НЕ строка в `process_definition` (ломает sandbox-гейт/инбокс/каталог —
см. ADR §2). Web не тронут.
