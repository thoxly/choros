# T-0660 — модельер: непрерывающий boundary-таймер + ветка эскалации мышью

Status: ready
Task: T-0660 (столпы 1/2 — движок / интерфейс-из-блоков; модельер, приоритет 52)
Base: dev, branch `task/T-0660`
Related ADR (read first): `docs/design/ADR-T0612-purchase-escalation-convergence.md`

## 1. Проблема (D-064, класс P0 «продукт этого не даёт»)

Панель таймера (`web/src/canvas/timer-deadline-panel.jsx`) и палитра
(`web/src/canvas/bpmn-palette-provider.js`) физически НЕ дают собрать мышью частый
валидный паттерн «напоминание по таймеру с эскалацией»:

1. **Нет контрола «прерывающий / непрерывающий».** Панель таймера предлагала ровно
   три поля (тип срока, срок, кому эскалация). Атрибут BPMN `cancelActivity`
   (по умолчанию `true` = прерывающий) НИКАК не задаётся из UI. Значит
   непрерывающий boundary-таймер (`cancelActivity="false"` — «напоминание, не
   отмена», семантика из ADR-T0612 §D1) можно было получить ТОЛЬКО правкой сырого
   XML. bpmn-js по умолчанию ставит `cancelActivity="true"` для граничного события,
   поэтому мышью получить непрерывающий таймер было невозможно.

2. **Нет аффорданса собрать саму ветку эскалации со схождением.** Валидный паттерн
   (ADR-T0612 §D2) требует, чтобы обе ветки — нормальное завершение шага И ветка
   эскалации — сходились в общий шлюз перед общим концом. Без схождения
   непрерывающий таймер даёт зомби-инстанс (T-0612: `end_time` навсегда `NULL`).
   Собрать это схождение мышью — многошаговая ручная сборка (граничное событие →
   userTask → шлюз, перецепить нормальный поток шага в тот же шлюз), которую
   строитель почти наверняка соберёт неверно (в отдельный конец = зомби).

Итог: единственный реальный путь — загрузка сырого BPMN XML (обход UI). По D-064
это дефект «продукт этого не даёт».

## 2. Решение

### D1 — контрол «Останавливает шаг / Работает параллельно» в панели таймера

Показывается ТОЛЬКО когда выбранное событие — граничное (`bpmn:BoundaryEvent`,
т.е. таймер закреплён на шаге). Для свободного промежуточного таймера
(`bpmn:IntermediateCatchEvent`) понятия `cancelActivity` нет — контрол скрыт.

- «Останавливает текущий шаг» → `cancelActivity="true"` (прерывающий; дефолт BPMN).
- «Работает параллельно (напоминание)» → `cancelActivity="false"` (непрерывающий).

Человеческий русский: НИКАКИХ `cancelActivity` / «non-interrupting» на экране.
Запись — через `modeling.updateProperties(element, { cancelActivity })` (интеграция
с undo/redo и перерисовкой границы события — сплошная vs пунктирная рамка), с
запасным прямым `bo.cancelActivity` для окружений без модельера (тесты).

`cancelActivity` — РОДНОЙ атрибут BPMN 2.0; Flowable читает его напрямую. Поэтому
серверные правки НЕ нужны — атрибут проходит через save/publish как валидный BPMN.

### D2 — аффорданс «Собрать ветку эскалации» (сборка схождения мышью)

Кнопка в панели таймера (для граничного таймера на шаге). Один клик собирает на
живом канвасе КОРРЕКТНЫЙ (сходящийся) паттерн через bpmn-js modeling API
(DI генерируется bpmn-js автоматически — `appendShape`/`connect`):

1. таймер → непрерывающий (`cancelActivity=false`);
2. граничное событие → новый userTask «Эскалация» (append, поток + DI);
3. шаг-хозяин → новый сходящийся `exclusiveGateway` «Продолжить» (append, поток + DI);
4. нормальный исходящий поток шага перецепляется: старый `шаг → следующий`
   удаляется, добавляется `шлюз → следующий` (шлюз встаёт МЕЖДУ шагом и его
   бывшим следующим элементом);
5. userTask «Эскалация» → тот же шлюз.

Результат-топология: `шаг → шлюз → следующий` И `таймер → Эскалация → шлюз`. Обе
ветки сходятся в шлюзе до общего продолжения. Это ровно то схождение, которое
линтер-гейт `checkTimerEscalationConvergence` (T-0641/T-0612) требует для
непрерывающего таймера — так что собранный мышью процесс проходит publish-гейт.

Предусловие (иначе кнопка отключена с подсказкой): таймер закреплён на шаге; ветка
ещё не собрана (у граничного события нет исходящих); у шага-хозяина РОВНО один
нормальный исходящий поток (чтобы перецепка была однозначной и безопасной).

## 3. Границы с T-0641 (родственная, строится параллельно)

- T-0641 владеет СЕРВЕРОМ: `src/core/timer-escalation-mapper.ts`,
  `publishProcessByKey`, xmlns-chokepoint в publish. **Не тронуты.**
- T-0660 владеет UI-модельером: `web/src/canvas/*`.
- Шов: панель пишет `choros:escalateTo` на граничное событие (как и раньше);
  ветка эскалации ведёт граничное событие → userTask «Эскалация». Серверный
  `mapTimerEscalation` (T-0641/T-0458) читает `escalateTo` и штампует
  `flowable:candidateGroups` на узел, КУДА ведёт таймер (= наш userTask
  «Эскалация»). `cancelActivity` — родной BPMN, серверу транслировать нечего.
- Round-trip доказан на фикстуре через реальные серверные чистые функции
  (`mapLanesToCandidateGroups → mapTimerEscalation → lintBpmn → normalizeBpmnForDeploy`)
  в `src/__tests__/timer-escalation-canvas-roundtrip.test.ts` — БЕЗ правок серверного кода.

## 5. Acceptance criteria

- AC1: панель граничного таймера рендерит контрол «останавливает шаг / работает
  параллельно»; переключение в «параллельно» пишет `cancelActivity=false` в модель.
- AC2: для промежуточного (свободного) таймера контрол cancelActivity НЕ показан.
- AC3: кнопка «Собрать ветку эскалации» на граничном таймере с одним исходящим у
  шага собирает `шаг→шлюз→следующий` + `таймер→Эскалация→шлюз`, таймер становится
  непрерывающим; идемпотентна (второй клик — no-op с причиной).
- AC4: собранная форма имеет DI (auto-layout) и импортируема bpmn-moddle.
- AC5: собранная форма публикуема — проходит `lintBpmn` (без
  `timer_escalation_no_convergence`) и `normalizeBpmnForDeploy`; `escalateTo`
  штампует candidateGroups на «Эскалация»; `cancelActivity="false"` доживает до deploy XML.
- AC6: старая форма (эскалация в отдельный конец, непрерывающий) — lint флагует
  (доказательство, что схождение обязательно и наш аффорданс строит именно его).
- AC7: язык человеческий (обе темы, ARIA); анти-кейс: 0 кейс-контента в src/, web/src/.

## 6. Что судье атаковать (UX-судья, G1–G7)

- Жаргон на экране (`cancelActivity`, «boundary», «non-interrupting») — не должно быть.
- Понятность: строитель понимает, что «параллельно» = шаг не останавливается,
  эскалация — напоминание.
- Обе темы, фокус/ARIA на select и кнопке, состояние disabled с внятной причиной.
- Дисклоужер: контрол cancelActivity скрыт для промежуточного таймера (нет смысла).
