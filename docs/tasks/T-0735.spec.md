# T-0735 (T-0654-b) — Экран «Процессы» = грид + доводка деталки (зона Работа)

Статус: `ready`. Родитель: T-0654 (флагман E-UX-HUMAN §5). Вход-спека: `docs/design/ux-study-2026-07-05.md` §5.
Фундамент (в dev): часть A T-0654 (сервер query-параметры + пагинация + стартер-идентичность),
T-0710 (`?instance=` scope инбокса), T-0717/T-0684 (человеко-имена процессов), T-0648
(актор-резолвер / ActorChip / RecordRef), T-0556/T-0609 (деталка экземпляра), T-0653
(view-примитив, `PROCESSES_VIEW_COLUMNS`).

Эта задача — **потребитель** контракта части A. Сервер НЕ трогаем (контракт готов).

## Часть B — грид «Процессы»

- **AC-B1** Инстансы в полноценном гриде (не скролл-щель): колонки из `PROCESSES_VIEW_COLUMNS`
  (`name/process/status/started/actor`), плотность из личного вида (comfortable/compact).
- **AC-B2** Серверные контролы, ВСЕ прокидываются в query-параметры части A:
  поиск `?q=` (debounce 250мс), селект определения `?definition=<procKey>` (лейбл — человеко-имя),
  селект статуса `?status=`, диапазон дат `?started_from`/`?started_to`, тумблер «мои» `?mine=1`.
- **AC-B3** Пагинация: читает `{total,limit,offset}`; «Показано N из total» + «Показать ещё»
  (offset += limit). Явный `limit` (25), чтобы пагинация реально включалась.
- **AC-B4** Стартер именем: `starterName`/`starterType`/`starterId` через `<ActorChip>` — не только глиф.
- **AC-B5** Честные Empty/Loading/Error; без мёртвых affordance; контраст ≥ WCAG AA обе темы (G2/G5/G7).
- **AC-B6 (ОТЛОЖЕНО в T-0654-c)** Каталог/связи «переезжают» в отдельный экран зоны «Конструктор».
  Удалять каталог с /processes ДО того, как построен его новый дом (часть C), значит осиротить
  живой функционал (список определений, настройка триггеров, редактор правил ветвления — их
  единственная точка входа сейчас в этой секции). Порядок «B раньше C» = C делает переезд.
  Грид становится ведущей секцией экрана; `ProcessCatalogSection` остаётся ниже без изменений.

## Часть D — доводка деталки экземпляра (`screen-process-instance.jsx`)

- **AC-D1** «Кем запущен: <Имя> (<тип>)» — стартер именем через `starterName`/`starterType`/`starterId`
  + `<ActorChip>` (сервер их отдаёт на детали). Рендерится только при наличии стартер-идентичности.
- **AC-D2** «Связанные задачи» → ссылка `/inbox?instance=<id>`; инбокс сеет фильтр из URL
  (реюз серверного `?instance=` scope, T-0710) + чип «Задачи этого процесса», сбрасываемый.
- **AC-D3** Заголовок «Имя процесса · Запись-источник» ссылкой — поднять `<RecordRef>` в строку заголовка
  (сейчас только в сайдбаре).

## Анти-UUID (свят, D-064)

Грид НИКОГДА не рисует сырой UUID инстанса/актора. Стартер → `<ActorChip>` (резолвит имя, id — вторично).
Запись-источник → `<RecordRef>` (резолвит title, ссылка). Инстанс-id из грида УБРАН (анти-кейс:
«рядовой находит СВОЙ процесс по имени заявки, ни разу не увидев UUID»). Гейт `anti-uuid-actor-render`.

## Анти-кейс (D-064)

Грид/деталка НЕ содержат кейс-констант (слаги/имена процессов/домен-словарь). Колонки — платформенные
(`PROCESSES_VIEW_COLUMNS`), контролы — платформенные, тексты — родовые. Гейт `anti-case-lock`.

## runtime_target

Локально / контейнер (web + существующий `src/http`). Стенд — offline на момент сдачи (план в handoff).
