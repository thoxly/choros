# T-0659 — formatJsonReadable обрезает publish-time lint-нарушения на 120 символах

## Problem

`formatJsonReadable` (`web/src/lib/format.js`) `JSON.stringify`-ит любое
объектное значение и жёстко режет результат на `MAX_JSON_LENGTH = 120`
символов + `…`. Единственный потребитель, который получает через него
**структурированные** объекты, — панель публикации процесса
(`StatusBanner` в `web/src/screens/screen-process-editor.jsx`), которая
рендерит `err.violations` (422 `BPMN_LINT_FAILED`, `POST
/api/process-defs/:key/publish`) и `pub.warnings`:

```jsx
{violations.map((v, i) => <li key={i}>{typeof v === 'string' ? v : formatJsonReadable(v)}</li>)}
```

Сервер отдаёт `LintViolation` (`src/core/bpmn-linter.ts`):

```ts
interface LintViolation {
  type: LintViolationType;   // напр. "timer_escalation_no_convergence"
  elementId: string;
  elementKind: string;       // "boundaryEvent" | "userTask" | …
  message: string;           // человеко-читаемый текст, ИНОГДА с "Fix: …" в хвосте
}
```

`JSON.stringify(violation)` кладёт в начало строки
`{"type":"timer_escalation_no_convergence","elementId":"…","elementKind":"boundaryEvent","message":"`
— это уже ~105-110 символов ДО первого символа `.message`. Реальное сообщение
`timer_escalation_no_convergence` (см.
`docs/design/ADR-T0612-purchase-escalation-convergence.md`) — 550+ символов,
и заканчивается actionable-подсказкой:

> `…Fix: either route the escalation branch into a gateway that also receives
> the guarded task's normal completion flow (so both paths converge before
> ending), or set cancelActivity="true" if the escalation is meant to CANCEL
> the guarded task rather than merely remind`

После обрезки на 120 символов пользователь видит только префикс JSON-конверта
и первые ~12 символов сообщения — сам факт нарушения и подсказка «как
починить» теряются полностью. Это системный баг рендера: он воспроизводится
для ЛЮБОГО `LintViolationType` с длинным `.message` (`timer_malformed`,
`gateway_rule_mismatch`, `agent_task_incoherent`, …), не только для
timer-convergence.

## Слой фикса

Клиентский рендер, БЕЗ изменения серверного контракта. Сервер уже отдаёт
структурированные `violations` — проблема ровно в том, что клиент
JSON.stringify-ит их через компактный (изначально предназначенный для узкой
превью-колонки в `screen-record-detail.jsx`) хелпер вместо структурированного
отображения. `formatJsonReadable` НЕ меняется (его 120-символьный контракт
остаётся верным для generic JSON field preview) — правится только сайт
рендера lint-нарушений.

## Fix

`web/src/screens/screen-process-editor.jsx`:

1. `VIOLATION_TYPE_LABELS` — словарь `LintViolationType → человекочитаемый
   русский заголовок правила` (додатив: для типа не в словаре используется
   сырой `.type`, ничего не падает).
2. `ViolationItem({ v })` — компонент одной строки списка нарушений:
   - `v` строка → рендерится как есть (обратная совместимость с
     role-warning'ами из `pub.warnings`, которые остаются `string[]`);
   - `v` объект со строковым `.message` (реальная форма `LintViolation`) →
     структурированная запись: заголовок правила + элемент (`elementKind
     «elementId»`), затем **`.message` целиком, без усечения**;
   - иначе (неизвестная форма без `.message`) → fallback на
     `formatJsonReadable(v)`, как было раньше — не регрессия для форм,
     которые линтер никогда не эмитил.
3. `StatusBanner` теперь рендерит `violations.map(v => <ViolationItem v={v}/>)`
   вместо прямого вызова `formatJsonReadable(v)`.

`web/src/canvas/editor.css`: добавлены классы `.chs-banner__violation{,-title,
-element,-message}` — заголовок жирным, сообщение `white-space: pre-wrap;
word-break: break-word` (перенос строк для длинного текста, никакого
`overflow: hidden`/`text-overflow: ellipsis`).

`web/src/lib/format.js`: только doc-комментарий у `formatJsonReadable`,
явно фиксирующий новый инвариант ("не использовать для рендера
структурированных ошибок") — поведение функции не тронуто.

## Acceptance criteria

- AC1: `LintViolation` с `.message` длиннее 120 символов (в т.ч. с "Fix:" в
  хвосте) рендерится в панели публикации ПОЛНОСТЬЮ — ни один символ не
  потерян, эллипсиса `…` нет.
- AC2: `.type` нарушения переводится в русский заголовок правила там, где
  словарь его знает; для незнакомого будущего `.type` — честный fallback на
  сырую строку типа (аддитивно, ничего не падает).
- AC3: строковые элементы `violations` (role-warning'и) продолжают
  рендериться как раньше — обратная совместимость.
- AC4: объект без `.message` (форма, которую линтер не эмитит) не роняет
  рендер — fallback на прежний `formatJsonReadable`.
- AC5: `formatJsonReadable` и его 120-символьный контракт для generic JSON
  preview (`screen-record-detail.jsx`) не меняются — не регрессия для
  несвязанного потребителя.
- AC6: русский текст на экране без жаргона (нет сырых `type`-токенов там, где
  есть перевод; нет "JSON", "stringify" и т.п. в видимом тексте).

## Не в скоупе

- Серверный контракт (`LintViolation`, `/publish` 422-конверт) не менялся —
  фикс целиком клиентский, по прямой инструкции задачи.
- Поведение `formatJsonReadable` для НЕ-lint потребителей (record-detail
  generic field preview) намеренно не тронуто — 120 символов там уместны
  (компактная превью-ячейка, не actionable-ошибка).
- Перевод остальных `LintViolationType` в словаре — покрыты все 11
  существующих типов на момент фикса (`src/core/bpmn-linter.ts`); новый тип
  автоматически деградирует до сырой строки, не блокирует рендер.
