# T-0758 — agent-instruction-runtime-dormant.sh: comment-aware refinement (D-056)

Substrate/fitness fix. Origin: `npm run fitness` red on a **clean dev** checkout
(dev@b50308be), masking the honest CI signal on every branch built on top of it —
flagged pre-existing by T-0756 (`docs/tasks/T-0756.pr-handoff.json` `fitness_caveat`).

## 0. What the gate protects, by its own spirit (FF-COMP-6, T-0123, ADR §4)

`ci/checks/agent-instruction-runtime-dormant.sh` enforces **AC-11**: day-1, NO
runtime response-formation path (`src/core/engine`, `src/worker`,
`bridge-runner.ts`, `bridge-smoke-runner.ts`, `src/adapters`) may read
`agent_instruction`. In `src/http`, a read is allowed **only** in the authoring
DAO, the pure-core type/changelog module, the audit/promote registration
(`artifacts.ts` `CONFIG_TABLES`), and tests — **never** in a response-forming
handler. This is a real, still-needed invariant: agent competency/instruction
content must stay confined to the authoring surface and never leak into the
runtime path that forms an answer.

**The gate is right in spirit.** The red is a false positive in its *mechanism*,
not a defect in what it guards.

## 1. Diagnosis — reproduced on a clean checkout

```
$ bash ci/checks/agent-instruction-runtime-dormant.sh
[FF-COMP-6] agent-instruction-runtime-dormant: no runtime read of agent_instruction
PASS FF-COMP-6: no engine/worker/bridge runtime path reads agent_instruction
FAIL FF-COMP-6: response-forming http handler reads agent_instruction: src/http/agents.ts
FAIL: agent-instruction-runtime-dormant found 1 violation(s)
```

Section 1 (`RUNTIME_PATHS`) is clean. Section 2 (`src/http` allowlist loop) fails
on exactly one file, `src/http/agents.ts`, which is **not** in the `ALLOWED_RE`
allowlist (only `artifacts.ts`, the DAO, the core type module, and tests are).

The detector is `grep -rlE "agent_instruction|agent-instruction" "${SRC}/http"`
— a **file-level, comment-unaware** substring scan. `src/http/agents.ts` carries
exactly two hits, both pure documentation **comments** (byte-identical to
`origin/dev`; `git diff origin/dev..HEAD -- src/http/agents.ts` is empty — this
predates T-0758 and every intervening task):

```
41: // T-0645: the SINGLE shared agent-management authority predicate. saveDraft
42: // (PUT /api/agents/:id/instruction) and the agent-instruction promote path
43: // (artifacts.ts) gate on THIS one resolver — no per-file fork.
...
177: // Authz — THE SAME class/predicate as the secret-handle lifecycle
178: // (POST /api/agents/:id/secret-handle) AND the agent-instruction promote path
179: // (artifacts.ts, T-0645): genesis-owner OR a confirmed, in-window, delegable
```

Neither line reads the `agent_instruction` table or the promote path; both are
prose *naming* the promote path implemented in `artifacts.ts` (which IS on the
allowlist) for cross-reference. `agents.ts` itself performs zero
`agent_instruction`/`agent-instruction` **code**-level access anywhere — verified
by re-scanning the whole file with comment lines stripped: zero hits.

**Conclusion:** path (b) from the task brief applies — "если строки в agents.ts
— просто комментарии-документация, научи чек отличать код от комментария." The
lines are pure documentation; the gate's *pattern* is the bug (comment-unaware),
not the guarded invariant.

## 2. Fix — comment-aware detector, additive/narrowing only

Added `file_has_code_level_agent_instruction_hit()`: re-scans a candidate file
with `#`/`//`/`/* */`-continuation comment lines stripped (`grep -vE
'^[[:space:]]*(#|//|/\*|\*)'`), then re-applies the *same, unchanged* pattern.
Only a hit surviving that strip is treated as a genuine code-level read; a
file whose only hits are comment lines is now `SKIP`ped instead of `FAIL`ed.
Wired into the `src/http` allowlist loop, immediately before the pre-existing
`FAIL`/`BAD_HTTP` increment (which is untouched and remains the live path for
any real violation). Two new `--self-test` probes
(`T-0758-COMMENT-ONLY`, `T-0758-REAL-HIT`) pin both directions permanently.

**The diff against BASE_REF (`b50308be`, this branch's merge-base) is 100% pure
insertion** — zero existing lines removed or modified, confirmed both by manual
`diff` and by `ci/checks/auto-sanction-additive.sh --verify` (A-1..A-4 PASS).
`RUNTIME_PATHS` (section 1) is untouched — it was not red and is out of scope.
