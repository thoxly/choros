# T-0758 — agent-instruction-runtime-dormant.sh: comment-aware refinement (D-056)

Substrate/fitness fix. Origin: `npm run fitness` red on a **clean dev** checkout
(dev@b50308be), masking the honest CI signal on every branch built on top of it —
flagged pre-existing by T-0756 (`docs/tasks/T-0756.pr-handoff.json` `fitness_caveat`).

## 0. What the gate protects, by its own spirit (FF-COMP-6, T-0123, ADR §4)

`ci/checks/agent-instruction-runtime-dormant.sh` enforces **AC-11**: day-1, NO
runtime response-formation path (`src/core/engine`, `src/worker`,
`bridge-runner.ts`, `bridge-smoke-runner.ts`, `src/adapters`) may read
`agent_instruction`. In `src/http`, a read is allowed **only** in the authoring
DAO, the pure-core type/changelog module, the audit/promote registration
(`artifacts.ts` `CONFIG_TABLES`), and tests — **never** in a response-forming
handler. This is a real, still-needed invariant: agent competency/instruction
content must stay confined to the authoring surface and never leak into the
runtime path that forms an answer.

**The gate is right in spirit.** The red is a false positive in its *mechanism*,
not a defect in what it guards.

## 2. Fix — comment-SUBSTRING-aware detector, additive/narrowing only

### 2.1 R1 — the first revision was itself broken (judge finding, blocking)

The first revision stripped whole **physical lines** that merely *start* with a
comment opener (`grep -vE '^[[:space:]]*(#|//|/\*|\*)'`). The judge
live-reproduced a **new false negative** it created: a line carrying real code
AFTER a leading same-line block comment —
`/* internal note */ const __evilProbe = "select * from choros." + "agent_instruction";`
— appended to a clean, non-allowlisted `src/http/app-secret.ts` made the gate
print `SKIP ... comment-only` and exit **0**. Lint-pragma-then-code
(`/* eslint-disable */ const x = ...`) and minified-banner one-liners are
common real TypeScript shapes, so this was a genuine weakening, not a corner
case. Reproduced on this branch before reworking; fixed as below.

### 2.2 The reworked mechanism — strip comment SUBSTRINGS, not lines

`strip_comment_substrings()` is a string-aware per-character scanner (POSIX
awk) that removes only the comment *text* and re-applies the same, unchanged
pattern to the remainder (`file_has_code_level_agent_instruction_hit()`):

- **`/* ... */` block-comment spans** are removed — inline (code before/after
  the span on the same line **survives**) and multi-line (state carries across
  lines until the closing marker);
- **`//` line-comment tails** are removed — but `//` **inside a string
  literal** (e.g. a URL `"http://.../agent-instruction/..."`) is content, not
  a comment: the string survives the strip;
- **string literals** (double-quoted, single-quoted, backtick template
  literals incl. multi-line state) are preserved verbatim with
  backslash-escape handling; comment markers inside them are inert;
- **`#`** is honored as a comment only when it opens the physical line
  (shell-style); a **mid-line `#` is conservatively kept as code** — TS has no
  `#` comments, and stripping `#` tails would hide a real hit in a private
  class field (`this.#agent_instruction`). This deliberately deviates from the
  judge's literal "trailing `#`" suggestion in the MORE conservative
  direction (the judge's text itself offers the state-machine alternative);
  the deviation is pinned by probe `T-0758-R1-PRIVATE-FIELD`.

Design rule: every stripping decision errs toward **keeping** text (worst
case a false positive — the gate reds and a human looks) rather than dropping
it (a false negative — a real violation sails through).

A file whose only hits are comment text is `SKIP`ped instead of `FAIL`ed. The
helper is wired into the `src/http` allowlist loop immediately before the
pre-existing `FAIL`/`BAD_HTTP` increment (untouched, still the live FAIL path
for any real violation). Ten `--self-test` probes pin both directions
permanently: `T-0758-COMMENT-ONLY` (skip), `T-0758-REAL-HIT`,
`T-0758-R1-LEADING-BLOCK` (the judge's exact evasion), `T-0758-R1-MINIFIED`,
`T-0758-R1-TRAILING`, `T-0758-R1-MID-BLOCK`, `T-0758-R1-MULTILINE-ONLY`
(skip), `T-0758-R1-MULTILINE-THEN-CODE`, `T-0758-R1-SLASHES-IN-STRING`,
`T-0758-R1-PRIVATE-FIELD`.

**The diff against BASE_REF (`b50308be`, this branch's merge-base) is 100% pure
insertion** — zero existing lines removed or modified, confirmed both by manual
`diff` and by `ci/checks/auto-sanction-additive.sh --verify` (A-1..A-4 PASS;
the R1 rework replaces only this task's own previously-inserted lines, never a
BASE_REF line). `RUNTIME_PATHS` (section 1) is untouched — it was not red and
is out of scope.

## 6. Out of scope / honest limits (rewritten after R1)

- `RUNTIME_PATHS` (section 1 of the gate) — not red, untouched. Its detector
  remains the original file-level grep (any hit, comment or code, fails) —
  deliberately NOT narrowed: the engine/worker/bridge surface has no
  legitimate documentation reason to name agent_instruction, so the stricter
  posture stays.
- **R1 history (honesty note):** the first revision of this task claimed
  "every non-comment (code) hit is still detected exactly as before" — that
  claim was FALSE. Line-level stripping dropped code following a leading
  same-line comment opener, and the judge live-reproduced the false negative
  (see §2.1). The claim is re-made only for the reworked substring-stripper,
  and this time it is backed by the R1 shapes themselves as permanent
  self-test probes plus live mutations of those exact shapes (§4). Lesson: a
  "narrowing-only" claim about a detector must be adversarially probed against
  the evasion shapes the narrowing itself introduces, not only against the
  shapes that motivated it.
- **Trailing `//` comments** are now stripped (string-aware), so a comment-only
  trailing mention no longer reds a file — but code before/after any comment
  still detects (probe `T-0758-R1-TRAILING`).
- **Mid-line `#`** is kept as code (TS private fields; no `#` comments in TS)
  — a conservative deviation from the judge's literal "trailing #" wording,
  in the direction of fewer false negatives (probe `T-0758-R1-PRIVATE-FIELD`).
- Known theoretical residue (accepted, false-POSITIVE direction only): a
  comment marker inside a regex literal (e.g. `/foo\/*/`) may cause the
  scanner to strip more or less than a full TS parser would — but every such
  misparse keeps hits visible or reds the gate; none hides a hit. A false
  negative would require a real `agent_instruction` read to live inside text
  the scanner classifies as comment, which the string-literal preservation
  and the probe set are designed to prevent.
- No change to `ALLOWED_RE`, `RUNTIME_PATHS`, or any other frozen invariant.
