# T-0758 — agent-instruction-runtime-dormant.sh false positive on a clean dev checkout (D-056)

Substrate/fitness fix. Origin: `npm run fitness` red on a **clean dev** checkout
(dev@b50308be), masking the honest CI signal on every branch built on top of it —
flagged pre-existing by T-0756 (`docs/tasks/T-0756.pr-handoff.json` `fitness_caveat`).

## 0. What the gate protects, and why it was red

`ci/checks/agent-instruction-runtime-dormant.sh` (FF-COMP-6, T-0123) enforces
**AC-11**: day-1, NO runtime response-formation path may read `agent_instruction`,
and in `src/http` a read is allowed **only** in an explicit allowlist
(`artifacts.ts`, the authoring DAO, the core type module, tests). The detector is
a **comment-blind** grep: any occurrence of `agent_instruction`/`agent-instruction`
in a non-allowlisted `src/http` file fails the gate.

The gate was RED on clean dev because `src/http/agents.ts` (not allowlisted)
carried **two pure documentation comments** that named the promote path in prose:

```
42: // (PUT /api/agents/:id/instruction) and the agent-instruction promote path
178: // (POST /api/agents/:id/secret-handle) AND the agent-instruction promote path
```

Both are byte-identical to `origin/dev` (`git diff origin/dev..HEAD --
src/http/agents.ts` is empty). `agents.ts` performs **zero** code-level
`agent_instruction` access. So the comment-blind detector produced a **false
positive** — the invariant it guards is not actually violated.

## 1. The chosen fix — the SIMPLE path (zero false-negative surface)

**Reword the two documentation comments so they no longer contain the literal
token, and keep the gate comment-blind (byte-identical to BASE).**

- `src/http/agents.ts` lines 42 and 178: "the agent-instruction promote path" →
  "the instruction-promote path in artifacts.ts". Meaning is preserved (it still
  points to the promote path implemented in `artifacts.ts`); the hyphenated
  `agent-instruction` token is removed, so the comment-blind grep no longer
  matches. This is the **only** functional change on the branch.
- `ci/checks/agent-instruction-runtime-dormant.sh`, `frozen-sanctions.jsonl`,
  and the T-0152 catalog are **byte-identical to BASE** (b50308be) — no frozen
  check is modified, no sanction is needed, no catalog family is added.

### 1.1 Why NOT the comment-aware detector (the abandoned lexer path)

The first three revisions of this task tried to make the detector *comment-aware*
(strip comment text before matching). Each revision opened a new false-negative
evasion that the reviewer reproduced live — a hand-rolled-lexer whack-a-mole:

- **R1** — a line-level stripper dropped whole lines starting with a comment
  opener, hiding code after a leading same-line `/* */` block comment.
- **R2** — the R1 revision's full-line `#` rule dropped a TypeScript line-leading
  private-field declaration (`  #rows = q("...agent_instruction...")`), hiding a
  real read.
- **R3** — the scanner treated a regex literal's raw `/*` (e.g. the common
  trailing-slash strip `path.replace(/\/*$/, '')`) as a block-comment opener,
  swallowing to EOF.

The reviewer proposed a general "unterminated `/*` = not a comment" rule for R3.
**I tested it empirically and it does NOT close the class:** a regex `/*` followed
by *any* later real `/* ... */` block comment (a trailing file note is ubiquitous)
still swallows every line between them — a reachable false negative in real code
(demonstrated in scratch: the required R3 probe passes, but the regex+later-`*/`
residual returns `hits=0`). Closing that would require true regex-vs-division
lexing, which the coordinator explicitly forbade ("не углубляйся в лексер дальше
unterminated-правила"). This hit the coordinator's pre-set boundary ("if the
unterminated fix does not close a swallow path — STOP; switch to the simple
path"), so I pivoted here.

**A comment-aware detector is the wrong tool for a security gate:** every gap in
the comment lexer is a place a *real* `agent_instruction` read can hide. The
comment-blind gate has the opposite, correct posture — it can never have a false
negative (it flags everything, including comments); its only cost is false
positives on legit comments, which we eliminate at the source by not writing the
literal token in prose.

## 2. Non-weakening — proven, and structurally guaranteed

The comment-blind gate (BASE) reds on **every** occurrence of the literal in a
non-allowlisted `src/http` file, in **any** position, because there is no lexer to
evade. Demonstrated by six live mutations appended to a clean
`src/http/app-secret.ts`, each → RED (exit 1), each reverted via `git checkout`
(no `git stash`):

| mutation shape | result |
|---|---|
| plain code hit `const __m = "agent_instruction"` | RED |
| R1 leading same-line block comment + code hit | RED |
| R2 line-leading `#rows` private-field declaration | RED |
| R3 regex `/\/*$/` + code hit | RED |
| R3 regex `/*` + a later `/* trailing note */` + hit between | RED |
| a comment-only mention of the literal | RED |

The last row is the deliberate trade: the comment-blind gate flags comment
mentions too. That is *why* the fix removes the token from the two legit comments,
and it is the property that makes false negatives impossible.
