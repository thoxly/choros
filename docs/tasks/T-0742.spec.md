# Spec T-0742 (T-0654-c) — «Каталог процессов» карточками (зона «Конструктор»)

Родитель: `docs/design/ADR-T0654-processes-split.md` · `docs/tasks/T-0654.spec.md` §Часть C.
Предшественники в dev: грид T-0735 (T-0654-b), сервер part-A T-0654, человеко-имена
T-0684/T-0717/T-0732. Только web (`web/src/**`) + правка одного e2e-теста. Сервер НЕ трогаем.

## Зачем

`/processes` после T-0735 — это грид оператора (зона «Работа») + внизу «пришитая»
`ProcessCatalogSection` (определения + связи-таблица + кнопки модельер/DMN). T-0735 сознательно
ОТЛОЖИЛ удаление секции (AC-B6) до постройки её нового дома, чтобы не осиротить binding-конфиг,
DMN-вход и правила ветвления. Эта задача строит дом — отдельный экран зоны «Конструктор» —
переносит туда все функции секции и удаляет секцию с `/processes`.

## Критерии приёмки (из T-0654 §Часть C)

- **AC-C1** Новый экран в зоне `constructor` (nav-config, capability `authoring_draft`,
  маршрут `/process-catalog`), рядом с Модельером.
- **AC-C2** Определения — КАРТОЧКАМИ: человеко-имя (не UUID/ключ), статус, версия(и),
  счётчик инстансов.
- **AC-C3** Клик по счётчику инстансов (когда >0) → экран «Процессы» с `?definition=<procKey>`
  (deep-link в грид части B); грид сеет фильтр определения из URL.
- **AC-C4** Триггеры-связи ПРЯМО на карточке (третья таблица «Связи» исчезает — сворачивается
  в карточку по `process_key`).
- **AC-C5** Кнопки «В модельер» / «Правила ветвления (DMN)» на карточке (+ «Настроить триггер»).
- **AC-C6** Дубль «+ Новый процесс» убран — одна точка создания (одна кнопка «Новый процесс»
  в шапке каталога).
- **AC-C7** UX-гейты G2/G5/G7; без фейковых кнопок; анти-UUID; обе темы читаемы.
- **AC-C8 (перенос без сиротства)** `ProcessCatalogSection` удалена из `screen-processes.jsx`;
  binding-модалка (единственный вход в trigger-config), DMN-вход, правила ветвления и создание
  процесса живут в новом каталоге. `/processes` = только грид оператора.

## Анти-кейс (D-064)

«Внедренец открывает Каталог процессов, видит свои определения человеко-именами карточками (ни
одного UUID/машинного ключа как основного контента), кликает счётчик «3 инстанса» у нужного
определения → попадает на грид «Процессы», уже отфильтрованный по этому определению, видит эти 3
живых процесса; из карточки же открывает модельер и правила ветвления». Ни разу не увидев UUID
как контент; без единой кейс-константы (имя/слаг процесса) в платформенном коде.

## Не-цели

- Не переписываем грид (T-0735) — только добавляем чтение `?definition=` из URL для deep-link.
- Не меняем сервер (`GET /api/process-catalog`, bindings) — контракт готов.
- Личные виды каталога, версии-история, DnD карточек — вне объёма (follow-up).
