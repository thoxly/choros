## 2. Что построено (generic примитив + кейс в seed)

### Generic (src/, case-free — enforced `ci/checks/customer-crm-anti-case.sh`)
- **`src/core/completion-effect.ts`** — примитив: реестр `(procKey, activity) → handler` + `runCompletionEffect(client, ctx, registry)`. Ноль case-литералов; ключи — непрозрачные строки; никакого pg/http/env.

### Case-quarantine (src/, дозволенные namespace: runtime/customer-onboarding, composition — дом кейса с T-0244)
- **`src/runtime/customer-onboarding/issue-key-effect.ts`** — `applyIssueKeyStep`: **(CE-3) `SELECT … FOR UPDATE` на записи + transition-гард ДО `issueEntitlement`** (конкурентный double-approve: проигравший блокируется на row-lock, перечитывает committed `status='active'`, active→active запрещён ⇒ порт НЕ вызывается — exactly-once на уровне БД-лока); затем `runIssueKey`, и на успехе **пишет обратно** `circuit_id` + `activation_key_issued_at` + `status='active'` в `record.data` (системный актор, JSONB-merge, audit `record.update`). **Закрывает Step 5c T-0244.**
- **`src/composition/customer-onboarding-effects.ts`** — связывает `customer-onboarding` × `task-issue-key`/имя-шага → эффект (инъекция deps). **(CE-2 fail-VISIBLE, доктрина T-0571 AC-7):** `ok:false` (pdp_denied/port_error вкл. dormant/bad_transition) ⇒ throw `HttpError(422, STEP_EFFECT_FAILED)` ⇒ approve-tx ROLLBACK (task.approved снят, запись не тронута, шаг ОТКРЫТ для честного ретрая) ⇒ роут отвечает видимой типизированной 422 — никогда не тихое «done»+200 без ключа.
- **`src/composition/completion-effects-root.ts` (CE-1, ПРОВОД)** — `buildCompletionEffectRegistry(pool, env?)`: продакшн-сборка реестра. PDP-деки: `makeDbGrantSource` + tenant-scoped record-fetch + `loadTenantOrgAncestry`→`makeResourceAncestryOracle` (байт-идентично `resolveReadVisibility` в server.ts — single-resolver). Entitlement — через `makeEntitlementWiring(env)` (env-гейт на ПОРТЕ, не на проводе). **`src/server.ts` вызывает его безусловно** при наличии pool и передаёт `completionEffectRegistry` в `registerInboxRoutes` — шов no-op для чужих (process, step), env-гейт на проводе не нужен.

### Seam (generic inbox)
- **`src/http/inbox.ts`** — в approve-tx, после `applyStepResult`, вызывает `runCompletionEffect` (строго gated: нет реестра/нет эффекта для (procKey, activity) ⇒ no-op, байт-идентично pre-T-0249; эффект бросил ⇒ tx ROLLBACK). Case-free — матч по `task.taskDefKey`/`task.step`.

### Seed (кейс живёт в данных)
- **`migrations/134_vendor_crm_onboarding_binding.sql`** — (a) `process_app_binding` on_create (customer-onboarding ← vendor-crm; **`trigger_registry_id` обязателен** — customer-subscription is_system=true, NULL-fallback не сработал бы; `submit_task_key='task-fill-card'`); (b) `list_view` «Клиенты» (CRM-список над гридом).

Закрыто slug→UUID-резолв-адаптером в composition root (fail-closed: неразрешимый слаг ⇒ 422, не тихий скип).

## 4. Находки «нехватка примитива» (для судьи и беклога)

1. **Нет generic «BPMN-шаг → серверный код-эффект»-примитива.** `applyStepResult` умеет только фиксированный эффект (запись approval-записи); agent-step — только LLM. Синхронный код-эффект (выпуск ключа) на конкретном шаге не собирался из примитивов ⇒ построен `completion-effect.ts` (generic). **Кейс-биндинг выражен как composition-регистрация (код в quarantine), НЕ как data-конфиг** — потому что binding-таблица `(process, step) → effect` = отдельный будущий примитив (иначе потребовалась бы ALTER known-tenant-таблицы + dual-control relief; вынесено как follow-up).
2. **Step 5c write-back был мёртв 2 задачи** (T-0244 отложил, T-0246 не трогал). Закрыт здесь.
3. **on_create для is_system-реестра требует явного `trigger_registry_id`** — NULL-fallback (binding-trigger-dao) стреляет только на первый is_system=false реестр; customer-subscription is_system=true. Задокументировано в migration 134.

4. **Slug↔UUID несовместимость runIssueKey × actor_event-субстрата** (вскрыта ПРОВОДОМ CE-1, см. §3) — класс «примитив жил только на in-memory дублёрах»; закрыт адаптером, кандидат на generic-выпрямление (actor-event API должен принимать слаги или субстрат — маппить).
