### R-5 (NEW, blocking) — tier db-tests are structurally non-functional

`ci/checks/db/tier_promote_atomic.test.ts` and `ci/checks/db/tier_read_scope.test.ts`
set the tenant GUC with `SET LOCAL choros.tenant_id = '...'` **outside any active
transaction** (seed helpers at lines 30/45/60; verification blocks at 105/140/167/
203/243). Over the `pg` driver in autocommit mode, `SET LOCAL` is a per-transaction
setting and is discarded immediately, so `current_setting('choros.tenant_id')`
reads back `""`. An RLS policy / audit trigger then casts the empty GUC to `uuid`
and the seed INSERT fails with `invalid input syntax for type uuid: ""` **before any
assertion runs**. I reproduced this directly against the app role:

```
APP INSERT (no BEGIN): invalid input syntax for type uuid: ""
```

Even the blocks that *do* have `BEGIN` (lines 129, 156, 192, 225, 310) place the
`SET LOCAL` on the line **before** `BEGIN`, so it is still a no-op inside the new
transaction. The passing sibling db-tests (`cross_tenant.test.ts:714+`,
`genesis-owner-seed.test.ts:130+`) wrap work in `BEGIN` and place `SET LOCAL`
**after** `BEGIN`.

Consequence: the live probes for **AC-2 (trigger), AC-3 (config-only), AC-4/AC-5
(atomic promote + audit), AC-6 (read-scope), and the R-2 409 path** never actually
touch the DB — they all die in seeding. Iter-1's "covered — DB not available here"
masked this. The pure-function and DDL layers are correct; the **live verification
layer claimed by these ACs is unproven**.

Fix: in both files, for every `withClient` block that does tenant-scoped work, issue
`BEGIN` first and place `SET LOCAL choros.tenant_id` immediately after it (then
`COMMIT` at the end), matching the `cross_tenant.test.ts` pattern. Re-run
`DATABASE_URL=... npm run fitness:db` (with 046_tier applied) and confirm the tier
tests are green before re-review.
