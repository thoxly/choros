## 1. Хэш-функция: детерминизм между машинами/чекаутами

### 1a. Locale-независимость `.sort()`

Имена файлов миграций следуют паттерну `^\d{3,}_[A-Za-z0-9_]+\.sql$` — исключительно ASCII-символы. JavaScript `.sort()` для строк из ASCII-диапазона (`[0-9A-Za-z_]`) даёт одинаковый порядок независимо от локали процесса (locale-sensitive сортировка касается Unicode-символов; в ASCII-диапазоне лексикографический порядок не зависит от locale). Проверено: все 47 миграций в репо имеют только ASCII-имена. **Детерминизм гарантирован.**

### 1b. Hash8 коллизии

8 hex-символов = 32 бита. Вероятность коллизии двух разных migration-наборов (birthday problem): для 10 веток ≈ 1.2×10⁻⁸. Эффект коллизии: две ветки с РАЗНЫМИ наборами миграций разделят шаблон (неверная схема → сбои тестов). Риск **пренебрежимо мал** для масштаба команды. Нит (документировать в ADR как known limitation). Blocking отказано — масштаб не оправдывает более широкий хэш в MVP.

**Вывод:** хэш-функция детерминирована, коллизия — теоретическая угроза пренебрежимого уровня.

## 3. Orphan-cleanup: сценарий "чужой current"

Это **ключевой сценарий T-0192** (задача решала именно его). Анализ строго по коду:

```typescript
// db-cleanup-orphans.ts:100-114
const TEMPLATE_RE = /^choros_test_template_[0-9a-f]{8}$/;
for (const { datname } of rows) {
  if (TEMPLATE_RE.test(datname)) {
    if (datname !== CURRENT_TEMPLATE) {
      staleTemplates.push(datname);   // ← сюда попадёт чужой current!
    }
  } else {
    orphans.push(datname);
  }
}
// staleTemplates дропаются ТОЛЬКО при --stale-templates
```

**Сценарий:** Ветка A (hash=`aaaa1234`, активна, tests running) и ветка B (hash=`4e98434b`). B запускает `--stale-templates`. B видит `choros_test_template_aaaa1234` как stale (не равен `CURRENT_TEMPLATE` B). B **дропает его**.

**Это возвращает гонку?** — Частично, да: если A в этот момент клонирует шаблон (setup уже прошёл) — клонирование уже завершено, run-DB существует, teardown сработает нормально. Если A ещё не запустила `setup-template` и шаблон снесли — следующий `fitness:db` упадёт с "template not found".

**Важно:** `--stale-templates` — **явный opt-in флаг**, не включён в автоматические CI-прогоны (`npm run fitness:db` без флага). Обычный cleanup-orphans (без `--stale-templates`) не трогает ни один шаблон по TEMPLATE_RE — **гонка не возникает при стандартном workflow**.

**Вывод:** проблема "дропнуть чужой current" реальна, но только при ручном вызове `--stale-templates`. Для автоматических прогонов регрессия исключена. Нит: ADR не документирует это ограничение явно — стоит добавить предупреждение.

## 6. 6 осей рубрики

### Ось 1: Корректность (соответствие ADR/спеке)

- **FR-hash:** SHA-256 вычисляется по sorted filenames+contents. Три файла используют одну и ту же `computeMigrationsHash` функцию (глобального состояния нет, all deterministic). PASS.
- **FR-template-name:** `TEMPLATE_NAME = choros_test_template_${MIGRATIONS_HASH}`. Паттерн верный. PASS.
- **FR-advisory-lock:** per-hash lock ID вместо фиксированного `147_001`. Формула `(parseInt(MIGRATIONS_HASH, 16) & 0x7fff_ffff) | 0x1000_0000` даёт значение в диапазоне [0x1000_0000, 0x7fff_ffff] — уместно для PostgreSQL advisory lock (int8, наш диапазон << 2^63). PASS.
- **FR-orphan-regex:** `TEMPLATE_RE = /^choros_test_template_[0-9a-f]{8}$/` — точно описывает новый формат и исключает legacy `choros_test_template` (без хэша) из regex, что корректно отправляет его в `orphans` (не как template). PASS.
- **ADR-поправка:** `docs/design/T-0147-db-test-isolation.adr.md` — поправка T-0192 добавлена с таблицей совместимости FF-T147-1..9. PASS.
