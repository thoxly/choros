## 1. Containment-семантика: RESOURCE_ORACLE equality-only и широкие скоупы

### 1a. Что означает equality-only для иерархических скоупов

RESOURCE_ORACLE: `isDescendantOrSelf(h, a, b) = (a === b)`.

Если у актора есть грант с scope `{kind:'node', hierarchy:'resource', nodeId:'parent-uuid', nodeLevel:'registry'}` (широкий узел), а запрос — на страницу app_id='child-uuid', то `isNarrowerOrEqual(targetAppScope, grantScope, RESOURCE_ORACLE)` вызовет `atomIsNarrowerOrEqual`, который проверит `oracle.isDescendantOrSelf('resource', 'child-uuid', 'parent-uuid')` = `child-uuid === parent-uuid` = `false`. Широкий грант НЕ покроет app-узел.

**Это осознанный day-1 ограничительный выбор**, явно задокументированный в комментарии RESOURCE_ORACLE (`src/http/report-page-render.ts:96-112`):

> Day-1: resource hierarchy is flat (application → registry → record).
> No DB-backed tree traversal yet (T-0053).

Полная иерархическая traversal отложена на T-0053. Equality-only означает: только гранты с `nodeId == appId` покрывают страницу. Это fail-safe: никакого over-grant по иерархии.

### 1b. Проверка реальных скоупов в живой БД

Все `application/read` гранты в dev-тенанте (id `a0000000-0000-0000-0000-000000000001`) — отсутствуют. genesis-owner (e-owner, slug) проходит через short-circuit в `loadAdminContext → isGenesisOwner → {ok:true}` до этапа scope-containment.

Гранты с `scope = {}` существуют исключительно в тест-тенантах `ct-tenant-11111111` и `ct-tenant-22222222`, созданных `cross_tenant.test.ts`. Эти тенанты не имеют пользовательских сессий через render-path.

```sql
SELECT DISTINCT tenant_id FROM choros.grant
WHERE resource_type = 'application' AND operation = 'read';
-- результат: только 11111111-... и 22222222-...
-- dev-тенант (a0000000-...) отсутствует
```

### 1c. Обработка scope `{}`

Объект `{}` проходит guard `typeof rawScope !== "object"` (т.к. является объектом). Затем `isNarrowerOrEqual` получает `parent.kind = undefined`, что не является `"set"`, поэтому `atomIsNarrowerOrEqual` попадает в ветку "Cross-kind non-set → false".

```
isNarrowerOrEqual({kind:'node',nodeId:'app-id',...}, {}) → false
```

Верифицировано live: `node --input-type=module`, `dist/core/grant-lattice.js`:
```
isBottom({}): false
isNarrowerOrEqual(targetAppScope, {}): false
```

`{}` гранты теперь не покрывают ни один app. Это корректно — `{}` не является валидным `ScopeElement` и не должен давать доступ.

**Нет ложного 403 для genesis-owner**: genesis-owner (e-owner) проходит через `isGenesisOwner` short-circuit до scope-containment. Нет ложного 403 для любого существующего dev-тенанта.

### 1d. Вывод по п.1

Equality-only oracle — правильный day-1 выбор (fail-safe, T-0053 отложен). Ложного 403 для реально-используемых акторов нет. Гранты с `scope={}` в ct-тест-тенантах корректно становятся не-покрывающими (они и не должны были работать — невалидный scope).

## 2. Порядок: page до checkReadGrant — 404/403 oracle

### Анализ

Обе функции (`renderFloor1`, `dataFloor2`) теперь загружают страницу ВНУТРИ `withTenantTx` ПЕРЕД вызовом `checkReadGrant`. Это необходимо для получения `page.app_id`. Следствие: актор без гранта на ЧУЖОЕ приложение, запрашивающий несуществующую страницу, получит 404 (страница не найдена), а запрашивающий существующую — 403 (нет гранта). Это подтверждает существование страницы.

### Оценка

ADR T-0121 и T-0013 не содержат явного запрета или требования к порядку 404 vs 403. Прецедент в кодовой базе:
- `dataFloor2` до T-0181 уже загружал страницу до PDP-gate (код T-0181 iter-1).
- T-0181 R-1 fix установил порядок gate-before-tx для Floor-1. T-0193 разворачивает это для получения app_id.

Exposure ограничен: актор, не знающий `page_id`, не может эксплуатировать это. UUIDs v4 непредсказуемы (entropy 122 бит). Кросс-тенантная RLS блокирует любой запрос к чужому тенанту (T-0013 гарантия). Паттерн "page-first → gate" допустим как известная архитектурная компромисс.

ADR не запрещает этот порядок, существующий прецедент это допускает. **Не blocking.**

Severity: **nit** — стоит задокументировать в ADR §6 явный выбор "page-id оракул допускается при UUID v4 entropy" для будущих ревьюеров.
