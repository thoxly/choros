## 2. Axis 1 — Correctness (соответствие ADR/спеке)

### 2.1 XSS-барьер — адверсариальный разбор

**escapeHtml: 5 символов и порядок**

```ts
// src/core/notification-templates.ts:62-68
return s
  .replace(/&/g, "&amp;")
  .replace(/</g, "&lt;")
  .replace(/>/g, "&gt;")
  .replace(/"/g, "&quot;")
  .replace(/'/g, "&#39;");
```

Все 5 символов присутствуют: `& < > " '`. Порядок корректен: `&` первым — double-escape исключён.
Прогон: `escapeHtml('&amp;')` → `'&amp;amp;'` (правильно). `escapeHtml('<>&"\'')` → `'&lt;&gt;&amp;&quot;&#39;'` (правильно).

**Обходы (adversarial):**

- `javascript:` в payload при `html=true` — шаблоны день-1 не содержат `<a href>` контекста. URL-протокол в тексте не опасен без href. **Безопасно.**
- Unicode fullwidth `＜script＞` (U+FF1C/FF1E) — не экранируется, что правильно: fullwidth-символы не интерпретируются парсером HTML как теги. **Нет ложного негатива.**
- Double-quote/single-quote injection: `" onmouseover="alert(1)` → `&quot; onmouseover=&quot;alert(1)` при `html=true`. Тег-атрибут-инъекция заблокирована. **OK.**
- `html=false` path — намеренно raw: `defaultTemplateRenderer` использует `html=false`, что соответствует ADR §2.9 "plain-text-часть — без экранирования". Email-драйвер (T-0170) использует `text: job.body` (plain-text SMTP), не HTML-тело. **Нет утечки в HTML-контекст на day-1.**

**Потенциальный gap (nit, не blocking):** `defaultTemplateRenderer` явно документирует "Email drivers that need HTML bodies should call `renderNotification(..., { html: true })` directly". Однако EmailChannelDriver (T-0170) не вызывает render самостоятельно — он получает уже готовый `job.body` из outbox-строки. Это создаёт архитектурный gap на будущее: переход на HTML email потребует либо нового рендера перед SMTP, либо изменения в fanout. **Известная day-1 ограниченность, зафиксированная комментарием.**

### 2.2 Интеграция с fanout T-0169 (dead-wiring)

`defaultTemplateRenderer` экспортирован, но ни в одном production-файле не потребляется (grep: `grep -rn "defaultTemplateRenderer\|notification-templates" src/ --include="*.ts"` — только сам модуль и тесты). `publishNotificationEvent` определён в `notification-router.ts` и вызывается только в тестах.

Это **known-acceptable dead-wiring**, аналогичный T-0171 (PostgresPrefStore не подключён к publishNotificationEvent в T-0171, принято как "known-acceptable"). Спека T-0172 раздел 5 явно выносит "outbox-wiring" за рамки задачи. FR-8 ("реализация порта для инъекции") требует создать реализацию — не провода. Полный production wiring ложится на E-N.6/E-N.7. **Замечания нет.**

### 2.4 Template body для `task.assigned` — упрощённый вариант

Спека §4 (таблица) содержит `body = "…назначена вам{{#assignedBy}} пользователем {{assignedBy}}{{/assignedBy}}."` — optional-секция. Реализация применяет упрощение: `"Задача «{{taskName}}» назначена вам."`. Спека §4 (примечание) явно разрешает: "если conditional section не реализуется day-1 … это допустимо — main invariant: простая {{var}}-подстановка + HTML-escape". **Соответствует.**

### 2.5 Fail-closed: missing var → ""

### 2.6 Fallback для unknown event_kind

`renderNotification`: `tmpl === undefined` → `{ title: eventKind, body: '' }`. ADR §2.9, FR-6, AC-7. **Соответствует.**

### 2.7 DataClass — импорт, не редекларация
