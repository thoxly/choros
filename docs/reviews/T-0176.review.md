## 6. `lossy_narrowing` in union — по ADR? (axis 1)

**Question (point 5 from review prompt):** `lossy_narrowing` is in `DepViolationType` union but `checkReportPageDepFields` never emits it. Is this per ADR?

**Answer: yes, this is correct per ADR.**

- ADR §3 declares the FULL closed vocab: `type: 'missing_in_schema' | 'lossy_narrowing'`. Both values are required to be in the type definition.
- Spec §4 out-of-scope explicitly states: _"lossy_narrowing триггер (dep_kind='aggregate' + type-narrowing) — T-0177 (schema-change API)"_
- The union is declared in T-0176 (type contract needed for §9 T-0121b export surface) but the trigger implementation is deferred to T-0177.
- This is a forward-declaration pattern: T-0177 will extend or call this module and emit `lossy_narrowing` violations. Having the type defined here means T-0177's `DepViolation[]` return values have the correct type without spec amendment.
- No deviation from ADR. No finding.

## 10. Findings summary

### R-1 (nit) — `DepViolation.message` additive vs ADR §3 minimal type

**Axis 1 / Location:** `src/core/report-page-compat.ts:57` (`message: string` in `DepViolation`)
**Issue:** ADR §3 defines `DepViolation` with three fields (`type`, `registryDefId`, `fieldKey`). The implementation adds `message: string`. This field is not listed in spec FR-3. However, `BindingViolation` (the mirror source per NF-1) has `message: string`, so the addition is correct by NF-1 logic and is additive (non-breaking).
**Suggestion:** No action required. If the ADR/spec are updated for T-0177, `message` should be explicitly added to the ADR §3 `DepViolation` interface to close the documentation gap. Nit only.

### R-2 (nit) — Minor test coverage gap in `classifyReportPageFloor` filter sub-paths

**Axis 5 / Location:** `src/__tests__/report-page-compat.test.ts` (missing case at `src/core/report-page-compat.ts:199–207`)
**Issue:** The `filter` sub-object with missing `field_key` or missing `value` is not explicitly tested. Implementation handles both correctly (returns Floor-2 with descriptive reason), but test coverage is incomplete for these internal branches.
**Suggestion:** Add two tests to `AC-14`:
  - `classifyReportPageFloor([{...agg:'count', filter:{op:'=', value:42}}])` → Floor-2 (filter.field_key missing)
  - `classifyReportPageFloor([{...agg:'count', filter:{field_key:'f', op:'='}}])` → Floor-2 (filter.value missing)
Nit only — does not block T-0177 dependency.
