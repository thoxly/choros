## 6-Axis Rubric

### Axis 1 — Correctness

No blocking issues found.

- **invoke_proposal** (line 455–465): `ON CONFLICT DO NOTHING` safe — PK includes `(tenant_id, id)` with fresh `uuid()` each call, so conflict only on exact same PK, which cannot happen in practice. Columns match migration 043. `caller_id`/`target_id` are declared logical (no FK in schema), confirmed by spec.
- **notification** (line 471–487): FK `(tenant_id, recipient_id) → employee(tenant_id, id)` correctly resolved via `seedState.empId{A,B}`. `KNOWN_TENANT_TABLES` ordering guarantees `employee` is seeded before `notification`. Row is minimally valid (all NOT NULL cols covered).
- **email_channel_config** (line 493–503): PK is `(tenant_id)` — exactly one row per tenant. `ON CONFLICT DO NOTHING` is the correct idempotency primitive here. The probe still works on re-runs: the row exists (either from this run or a prior one), and AC-1/AC-2 verify 0-visibility from the opposing tenant. No silent failure risk: if `DO NOTHING` fires it means the row already exists, which satisfies the probe invariant.
- **notification_preference** (line 505–516): PK = `(tenant_id, event_kind, recipient_scope)`. Uses `uuid()` slice for `recipient_scope`, making the PK unique per call. `ON CONFLICT DO NOTHING` is harmless but practically never fires. No FK deps to resolve. Correct.
- **report_page** (line 518–535): FK `(tenant_id, app_id) → application`. Uses pre-seeded `seedState.appId{A,B}` (populated in the explicit Phase 1 of `beforeAll`). Returns new `pageId` stored in `seedState.reportPageId{A,B}` for downstream dep. Correct.
- **report_page_dep** (line 537–550): Two FKs — `(tenant_id, page_id) → report_page` and `(tenant_id, registry_def_id) → registry_def`. Both targets are pre-seeded (`reportPageId` and `regId`). `KNOWN_TENANT_TABLES` ordering (`registry_def, …, report_page, report_page_dep`) guarantees both. Correct.
- **seedState** additions (line 626–628): `reportPageIdA/B` initialized to `''`; populated before `report_page_dep` case is reached. No race condition possible (sequential loop over `KNOWN_TENANT_TABLES`).
