## 2. Guard correctness (axis 2)

`ci/checks/package-json-no-dup-keys.sh` reviewed in full.

### Scope

The guard uses a character-level JSON parser (`findDups`) that tracks depth via a
stack of `Set` objects. It detects duplicate keys at **any depth** — top-level
and nested (e.g. `scripts`-level). Verified by manual test:
- `{"name":"a","name":"b"}` → detected at depth 0
- `{"scripts":{"build":"tsc","build":"tsc2"}}` → detected at depth 1
- `{"version":"1","version":"2"}` → detected (non-fitness key)

This satisfies "ловит дубль ЛЮБОГО ключа" per spec FR-2.

### Self-test honesty

`--self-test` mode:
1. Creates a temp `package.json` with `"fitness"` appearing twice.
2. Runs the checker against it.
3. Expects non-zero exit (duplicate detected); fails if exit is 0.

Reviewer inverted the test manually: planted a `"name"` dup in a temp copy and
confirmed the checker exits 1 with `FAIL: duplicate keys: name` on stderr.
The self-test can fall the right way and the wrong way — it is honest.

`bash ci/checks/package-json-no-dup-keys.sh` exits 0, output: `PASS`.
