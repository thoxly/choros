## 3. Анализ R-1 фикса (immediate-dead)

### 3.1 `runOutboxOnce` — механизм перегрузки

Реализован корректно: `perRowMaxAttempts` → возвращает `1` для `IMMEDIATE_DEAD` notification rows → `markRetry(..., maxAttempts=1)` → `attempts 0+1=1 >= 1 → dead`. Первая попытка убивает строку. Правильно.

### 3.2 BLOCKING — R-NEW: `startOutboxDispatcherLoop` не передаёт `perRowMaxAttempts` в `runOpts`

`startOutboxDispatcherLoop` строки 177-182 строит `runOpts` вручную и НЕ включает `perRowMaxAttempts`:

```typescript
// outboxDispatcher.ts:177-182
const runOpts: RunOutboxOptions = {
  batchLimit: opts.batchLimit,
  maxAttempts: opts.maxAttempts,
  backoff: opts.backoff,
  ...(opts.onDispatched !== undefined ? { onDispatched: opts.onDispatched } : {}),
  // perRowMaxAttempts НЕ ЗДЕСЬ — УТЕЧКА
};
```

`lifecycle-bridge.ts` передаёт `perRowMaxAttempts` в `startOutboxDispatcherLoop` (строка 339), TypeScript принимает его без ошибок (поле из `RunOutboxOptions`, которое `OutboxDispatcherLoopOptions extends`), но оно никогда не попадает в `runOpts`, с которым вызывается `runOutboxOnce`.

**Итог:** в production dispatch-loop строки с `IMMEDIATE_DEAD_ERROR_PREFIX` продолжают получать `maxAttempts=5` (не 1). R-1 с точки зрения runtime PATH исправлен только для `runOutboxOnce`-вызовов напрямую, но NOT для вызовов через `startOutboxDispatcherLoop`.

**Тесты проверяют только `runOutboxOnce` напрямую** (строки 947-956 и 1011-1024 в notification-email.test.ts) — они не тестируют production path через `startOutboxDispatcherLoop`. Тесты PASS по причине обхода петли.

**Это новый blocking finding R-NEW (переписывает бывший нит R-3).**

### 3.3 Вариант исправления

В `startOutboxDispatcherLoop` добавить `perRowMaxAttempts` в `runOpts`:

```typescript
const runOpts: RunOutboxOptions = {
  batchLimit: opts.batchLimit,
  maxAttempts: opts.maxAttempts,
  backoff: opts.backoff,
  ...(opts.onDispatched !== undefined ? { onDispatched: opts.onDispatched } : {}),
  ...(opts.perRowMaxAttempts !== undefined ? { perRowMaxAttempts: opts.perRowMaxAttempts } : {}),
};
```

Это не меняет поведение для вызывающих без `perRowMaxAttempts` (опциональное, default=undefined → без изменений).
