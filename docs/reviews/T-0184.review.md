## 2. Ось 1: корректность fix (src/db/audit-grant-trail.ts)

### 2.1 Предикат

```typescript
const params: unknown[] = [GRANT_TRAIL_TYPES, tenantId];
let paramIdx = 2;

const conditions: string[] = [
  `type = ANY($1::text[])`,
  `tenant_id = $2`,
];
```

- `tenant_id = $2` — явный WHERE-предикат, привязанный к `tenantId` через positional параметр. ✅
- `tenantId` уже был в сигнатуре `queryGrantTrail(pool, tenantId, opts)` — никакого нового параметра. ✅ (NF-1)
- `paramIdx` инициализируется в 2, точно отражая что params[0]=GRANT_TRAIL_TYPES ($1)
  и params[1]=tenantId ($2) уже заняты. ✅

### 2.2 Трассировка paramIdx по всем опциональным ветвям

| Ветвь | Действие | Правильность |
|---|---|---|
| `actor` filter | `paramIdx++` → 3; `actor = $3`; `params.push(actor)` | ✅ |
| `subject` filter | `paramIdx++` → (next); `subject = $N`; `params.push(subject)` | ✅ |
| `roleId` filter | `paramIdx++` → (next); `(subject = $N OR payload->>'roleId' = $N)` — **одно** значение используется дважды в одной строке условия; `params.push(roleId)` — один push | ✅ |
| `beforeSeq` filter | `paramIdx++` → (next); `seq < $N`; `params.push(beforeSeq)` | ✅ |
| LIMIT | `paramIdx++` → last; `params.push(limit + 1)` | ✅ |

Ни одна из независимых `if`-ветвей не пропускает increment. Нет off-by-one.
SQL-параметры согласованы с `params` массивом во всех комбинациях.

### 2.3 GUC сохранён

`withTenant()` по-прежнему выполняет `SET LOCAL choros.tenant_id = '${tenantId}'`
(src/db/audit-grant-trail.ts:94). GUC остаётся основным guard для NOBYPASSRLS-пути,
WHERE — defence-in-depth для BYPASSRLS (choros_migrator). Оба механизма активны. ✅ (FR-2 / NF-1)

  TENANT_B rows с ACTOR_B в БД есть, но в TENANT_A контексте их нет. Это реальное
  доказательство isolation, а не smoke. ✅ (NF-3)

Прогон выполнен дважды ревьюером: оба раза зелёный. ✅

### 4.2 Нит: grep матчит комментарии, не SQL-код

Regex `WHERE[[:space:][:alnum:]_.$]*tenant_id` в реальном файле матчит строки 11 и 126
(комментарии `"WHERE tenant_id = $N added..."` и `"WHERE tenant_id guard"`), а не
SQL `conditions`-массив, где `tenant_id = $2` находится без предшествующего `WHERE`
на той же строке. Если кто-то уберёт `tenant_id = $2` из conditions-массива, но
оставит комментарии — grep пройдёт. Реальным защитным слоем остаётся DB-gated тест AC-2.
Статический check — belt-and-suspenders; полностью отсутствовать он не должен, но его
grep мог бы матчить условие в массиве (`conditions.push.*tenant_id`). **(nit, ось 5)**
